## 公开参考核对后的调整

2026-09-06 用户授权搜集参考；出处与边界见 [P01-S01–S11](evidence.md#公开资料对照2026-09-06用户授权专项搜集)。上一版依据本地代码和经验；本节补充公开证据后的调整，未获实施授权。

- **生命周期参考 Epic Gameplay Cues**：保留瞬时和持续实例区分，增加恢复已存续状态的路径与明确的多来源实例政策。WhileActive 不当作逐帧创建事件。
- **数据绑定与预览参考 Unity VFX**：预览控制真正的运行时实例，默认读资产值，临时覆盖只影响实例；提供事件测试和单步。前台独立 view 是本项目要求，不是搬 Unity 编辑器。
- **生产路线加入 Effekseer**：A 为高质量纹理／序列帧与 Godot 原生粒子／shader；B 为 Effekseer 制作后导出序列帧，运行时仍用 A；C 为 Effekseer 实时插件接入共享接口。三者可组合。优先 A+B 完成首批斩击／爆发，持续护盾使用原生动态材质或在 C 通过项目兼容性验证后采用。C 当前未验证，不能视为已选依赖或要求改渲染器。
- **框架为不同场景实现提供统一调用边界**，不用一个巨型 RangedVisualKind 分支承载全部效果，也不预先制作通用节点编辑器。只有采用专用运行时时才增加对应适配器，避免无需求抽象。
- **样板评审参考 Riot**：先完成基础效果并在预览中验收，再扩展变体；高级质感与有效范围、朝向、层级都要看，不能用清晰度替代用户的美术目标。

## 共享数据与播放路径

1. **VfxDefinition / VfxCatalog**：只读 `.tres` 与已登记效果目录，包含稳定 id、中文名、PackedScene、支持的阶段／参数、时间与挂接策略、绘制层及质量预算。场景封装纹理、序列帧、粒子、shader 和编排。定义默认参数只存一份，不引入任意字符串参数字典。美术来源及许可随素材保留。
2. **PresentationBinding**：在既有能力／状态／攻击表现规格中引用特效 id，配置哪一阶段、作用对象与挂接点使用哪个效果。一个技能可组合多个效果，一个效果可跨技能复用；现有角色动画 Cue 保留独立含义。模拟只消费需要的稳定标识／不可变数据，不依赖 PackedScene 或 GPU 对象。
3. **VfxPlayer / VfxInstance**：每个战斗或预览舞台拥有一个播放器；场景 root 暴露统一的开始、上下文更新、可选受击、带原因结束与强制清理接口。返回实例句柄，持续特效按玩法实例键唯一管理。具体样子由场景负责，播放器不按技能名称写分支。
4. **BattlePresentationAdapter**：消费提交成功的事实与状态快照，解析同一份 binding，形成类型化播放请求。包含作用域、事件序号／施放与操作关联、源目标／状态实例、位置方向、实际区域和结束原因。缺失事实按样板最小补齐，不从日志文字、动画帧或血条变化猜测。
5. **VfxPreviewScreen**：独立 authored 前台场景，加载同一目录、绑定解析器和播放器，仅提供展示舞台与合成输入。效果单独预览检查素材；技能组合预览读取该技能的正式 binding，不能再抄一份编排。

正式：战斗事实 → 表现适配 → 共享绑定解析 → 共享播放器 → 效果场景。
预览：舞台与操作输入 → 共享绑定解析 → 共享播放器 → 同一个效果场景。

## 必须落实的契约

- **瞬时／持续／移动**：瞬时效果自行完成；持续效果开始后更新同一实例，由实际状态结束关闭；飞行效果跟随权威子弹轨迹。VFX 销毁不能销毁逻辑子弹，粒子碰撞不能扣血。
- **施放／命中**：当前某些技能即时提交，没有真正前摇阶段。不能仅增加视觉前摇就宣称伤害延后，也不能每条伤害都重复播放一个范围大招。按施放、操作、目标分别去重；区域主体一次，目标命中按事实逐个播放。
- **护盾语义**：先核查现有护盾是累计数值还是可区分来源的实例。前者可做一层聚合视觉，后者按实例管理；不能伪造独立护盾。受击消耗、耗尽、到期、驱散、死亡与作用域退出必须可区分，正常结束不一律播放破碎。来源缺口需要玩法事实补充，不能由播放器猜测。
- **位置与图层**：由正式单位提供显式身体／武器／脚底挂接点，由舞台提供投影与地面／角色前后层；移除统一身体偏移。地面范围的逻辑形状／半径来自实际技能快照，美术溢出与有效范围分开，不拉伸圆形贴图冒充所有区域。
- **材质与时钟**：静态资源共享；可变 shader 参数、粒子及播放状态归实例。统一暂停／倍速需要覆盖 AnimationPlayer、AnimatedSprite2D、粒子、shader 时间和自定义更新。第一版不承诺任意拖动时间轴，GPU 粒子无法靠 AnimationPlayer.seek 完整回退，重播采用清理重建。
- **失败与清理**：重复开始／结束幂等，换战斗清理全部句柄和订阅；终止发射后允许有界尾迹，强制清理立即结束。支持重建持续状态快照，重新绑定视图不能漏掉存续护盾。
- **预算与校验**：目录 id 唯一、引用有效、场景 root 接口和阶段能力匹配、绑定参数合法。不可无限重复生成持续效果；拥挤时削减碎屑／次要粒子，保留关键状态和范围表达，绝不改变伤害。对象池按实际需要增加，不作为第一步前置工程。

## 预览室范围建议

- 列表／筛选、已引用技能、角色与地面参照、背景切换；播放／暂停／重播／循环／倍速。
- 按能力展示受击、正常结束和破碎等按钮；预览操作不是玩法判定，也不访问存档。
- 默认正式参数；位置、距离等环境条件可以改变，调试覆盖明确标识并可恢复，不修改共享资源。第一版不提供保存编辑，不维护第二套特效编辑器。
- 素材单体与技能组合使用同一个入口。共享路径证明接入一致，不等于正式混战的触发时序与可读性验收已经通过。

## 建设顺序建议

1. 建最小共享定义、播放器与预览入口；已有简单远程效果作为兼容资源迁入，不变更子弹玩法。
2. 做高质量交叉撕裂样板并接一次真实技能命中，验证素材、挂接和组合播放；不把现有线条效果作为美术达标。
3. 做范围爆发／持续区域样板，验证区域数据、地面分层、施放与目标级事件。
4. 做护盾样板，补齐其实际生命周期缺口，验证生成、持续、受击、结束与清理。
5. 按前三类经验推广其余技能。检查共享资源不被修改、重复事件、暂停倍速、结束原因、范围位置与零残留；真实输入及混战观感单独验收。

不建议先造大而全的通用时间轴编辑器，也不建议先做一个直读文件路径的独立素材浏览器；需要先建立正式与预览共享的最小播放契约。

## 制作方法修正：先拆动作，再选载体与素材（2026-09-07）

以下是基于 P01-S12–S20 的项目建议，不是新增玩法或本轮实施。保留用户认可的治疗粒子和能量弹，不再用每次反馈触发一轮无参考的整体重绘。

### 素材粒度的判断
判断单位是“需要独立控制的运动、寿命、颜色、空间归属”，不简单追求图片越小越好：
- 完整效果概念图可用于定风格，但不默认直接成为游戏中一张可扭动的 sprite。
- 一颗光点/火星、一片飞溅、一段能量条、一块烟雾：适合独立粒子，生成图集变体可以复用。
- 刀光横截面、拖尾条纹、方向性 mask：适合映射到弧形网格/ribbon/trail；几何控制路径与宽度，shader 控制流动、显隐与着色。
- Noise、Flow map、Gradient、SDF 等控制数据要求准确的数值与采样语义，优先程序/专业工具制作；不能把看起来像噪声的彩图直接当可用控制贴图。
- 烟火卷曲、破碎等需要每帧改变轮廓/拓扑的局部，可用手绘或离线模拟烘焙 flipbook。完整瞬时效果也可能适合烘焙，不建立“一张图一定错”的规则；固定视角/色彩与不可独立交互是代价。
- 已有高清生图可以保留为风格参考或分层素材。之后提示词应先规定用途、UV方向、留边、透明度、是否可平铺、颜色与亮度层是否需分开，而非泛泛要求“高级魔法”。

### 组件分工
| 组件 | 负责什么 | 不应该代替什么 |
|---|---|---|
| 贴图/图集 | 形状、材质、细节变体 | 整个技能的全部动作关系 |
| 粒子发射器 | 数量、出生区域、方向、速度、寿命、受约束随机性 | 主要打击轨迹和时点的随意猜测 |
| 网格/轨迹 | 空间轮廓、扫过路径、宽度、朝向、尾迹 | 只用裸几何取代已要求的美术质量 |
| Shader/材质 | 显隐、流动、色带、软边、扭曲、混合 | 任意把径向冲击改成角向旋涡 |
| 动画/时间编排 | 主次层错峰、快慢与峰值、角色/命中关联 | 改变真实伤害时机 |
| Flipbook | 局部复杂形变随时间演化 | 可变轨迹、动态碰撞和任意方向的完整替代 |

### 交叉撕裂的拆解示例（建议，非已实施）
- 主动作：两次斜向扫切，分别定义起点/弧线/终点与速度，不先固定一张完整 X。
- 主刀光：弧形条带/轨迹承载单条方向纹理，亮锋与较暗拖尾分层；笔画随动作形成，不是整张斜线绕中心摇摆。
- 命中层：短促的局部亮点/冲击形，定位到真正命中点；不是每一层都最亮。
- 次级层：少量火星或碎屑按挥砍/接触方向飞出，各自拖尾与寿命；是否适合血肉、金属或魔法随主题决定。
- 收尾层：刀痕/余辉继续完成原方向运动并降低亮度，避免凭空停住后换成另一种消散运动。
- 技能只有结果事件而没有施放前事件时，不能在伤害发生后补一段“预备”并假装时间正确；先确认动作/表现触发契约，视觉不得推迟规则结算。

### 工作顺序与验收改变
1. 为一个样板选少量方向明确的成熟参考；标明参考的是动作、节奏还是材质，不临摹成品资产。
2. 先列主/次层与时间关系，明确角色/地面/世界挂接和实际玩法时点。
3. 做运动骨架，先验证挥、爆、围绕、漂浮的动作是否成立；此阶段不是最终低成本几何美术交付。
4. 依照分层清单生图/画图/制作网格/序列帧，再在引擎组合。
5. 正常速度看完整动作，慢放核对各层，逐帧用于诊断，静态截屏只能验证局部画面。最后再看实际角色尺寸与背景，不把黑底大图当作正式观感通过。
6. 先收敛一个基准样板再推广。专业工具可用，质量不由是否使用某插件决定；不用“创新”“复杂”替代是否贴合动作。
