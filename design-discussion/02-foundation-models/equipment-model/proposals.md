# M05 装备模型：方案讨论

## M05-Q01：同名装备的重复使用与限制作用范围

状态：已收束，用户结论见 [M05-D01](decisions.md)。以下保留原提案及取舍，完整 E01–E06 及证据缺口见 [已有证据](evidence.md)。

### 本题边界

装备属于具体英雄、每人三槽、战前免费装卸转移已有玩法基线。现行实例路径容许同名装备占不同槽；这不是空白规则。本轮比较是否需要新增统一同名限制，以及特例应该约束穿戴还是某项收益，不重选槽数量或重新讨论所有装备能有什么效果。

### M05-Q01-P01：保留普通同名装备可重复穿戴，必要限制由明确内容承担

Agent 建议保留 E01 的现行方向：已有两件同名装备时，可以在槽位允许的情况下交给同一个英雄，也可以分配给不同英雄。不新增所有装备共有的“同英雄同名最多一件”。

每件装备保留自己的归属和投入；它产生的状态、属性或触发仍按具体规则结算，不保证所有数值／机制翻倍。这与 M04-D01 一致，不是允许无上限递归或复制永久装备。

若某件装备有真实限制需要，可用明确的英雄唯一、具名效果唯一、共享触发上限、互斥组或特殊挑战范围表达，避免暗中无效；E02–E06 是参考空间，不全部纳入初期。普通同名重复本身不作为必须封禁的理由，也不默认给所有被动加唯一标签。

### 玩家收益与代价

同一核心可用两个槽强化自己的主方向，但会让出生存、抗性或其他联动槽。第二件即使不能完善另一名英雄，也可能继续服务当前体系，与 G03 的逐步定向及替换相容。

代价是强件重复可能挤压组合多样性，某些触发／转换还可能非线性放大；需要在具体内容、机会成本和供给中处理，而不是假定“有三个槽所以必然平衡”。同名属性／状态合并的可解释性归 I18，第二件出现概率及后续用途归 R06／R08，不据此默认增加合成、分解或出售系统。

### 证据与恢复

已有研究对同名穿戴的完整规则较稀疏；直接案例为 Astronarch 多 copy 修复与 Backpack Dungeon 特殊挑战禁重。E02–E05 为明确标注的项目对照，不声称六种都有完整原作证据。

2026-09-08 用户确认可以重复穿戴，其他限制依靠词条控制；例子为两件装备的爆伤可叠加，而“暴击多打一下”的特效词条唯一。记录 M05-D01，明确采用重复穿戴与词条级叠加／唯一的组合，不将所有特殊词条一律设为唯一，也不采用其他限制清单。Q01 收束；后续核对装备成长／个体定义等真实未定接口，供给归对应议题，不把“词条”理解成已采用随机生成或洗练。

关联 [I20](../../05-integration/cross-topic-issues.md)：实例／同名／效果唯一／额度范围与重复奖励的区分；I12 战前调整、I15 固定英雄外部联动、I16 羁绊贡献、I18 状态规则、I19 控制反制继续有效。当前只讨论和记录，不改权威、实现或研究原库。

## M05-Q02：同一种装备获取时的固定定义与随机个体差异

状态：已收束，用户结论见 [M05-D02](decisions.md)。以下保留原提案，完整 E07–E11、原作边界及项目对照见 [已有证据](evidence.md)。D01 只确定穿戴和词条结算，本题随后由用户明确固定配置与可升级品质。

### Q02-P01：初期保留固定成品，随机集中于出现的装备与组合机会

Agent 建议初期沿用 E07 的固定定义基线，不额外引入逐件随机数值／词条：同一明确内容版本拿到手即可确认用途，让关键装备成为可识别的定向信号。构筑变化来自拿到哪些装备、交给谁、与英雄／羁绊／遗物怎样组合；不默认第二件会随机成更好或更差的版本。

理由是 G03 已有随机开局、逐步定向、开放供给及关键装备成型的体验；再加装备内部随机，会让“拿到关键装备”与“拿到可用版本”分成两次命中。固定成品也减少多英雄装备比较的负担。代价是重复物品的个体惊喜较少，需要具体装备有足够不同的用途；不能以固定定义代替内容多样性或供给可达性。

若希望初期就有个体差异，E10 固定核心＋随机附加比完全随机核心更能保留定向信号；这只是条件性取舍，不替用户采用。E08 的纯数值浮动是否值得，取决于它是否产生有意义的选择，而非单纯让玩家反复换成数字更大的一件。

品质 E11 可与固定或随机并存，装备是否能成长另作子问题；此建议不等于禁止未来品质／升级，也不预定这些系统必须存在。E08–E10 的部分条目为项目对照，已有库没有逐件生成概率表，不能把推论包装成多个原作验证。

### 恢复与关联

2026-09-08 用户明确“都是固定的，但是可以升级品质”，记录 M05-D02：同种同品质的词条／数值固定，不采用逐件随机；品质可升级，升级后仍用明确配置。Q02 收束，E08–E10 保留未采用对照。下一项核对品质升级的具体收益或投入方式，先明确单一子问题；品质数量、配方、费用和成功规则尚未决定，不把可升级推定为三合一或随机强化。

关联 I21：按 D02 转为固定品质配置、成长投入与供给可达性的衔接；I20 继续负责同一词条身份和唯一范围。当前只讨论和记录，未修改权威或实现。

## M05-Q03：品质升级的投入来源与机会成本

状态：材料与风险方向阶段收束，用户结论及候选见 [M05-D03](decisions.md)。完整 E12–E19 见 [已有证据](evidence.md)。以下保留原提案，不等于逐条采用；各品质数值、材料数量／价格或提供窗口未定。

### Q03-P01：通用升级资源作为主途径，已有核心不必等待同名副本

Agent 建议以 E15 的通用升级材料／工具为主途径：获得目标装备后，玩家可以主动把有限升级投入给它；初期升级结果确定，不另加失败、掉级或毁装。这能支撑 G03 在关键装备出现后逐渐定向，同时避免同名再次出现成为继续培养的硬门槛。

代价是增加一类需理解和分配的资源，玩家可能囤积等待更好的装备。若更重视资源简洁，E14 共用金币也能实现“投入指定装备”的目标，但升级将与其他花钱行为争预算；最终资源与供给在 R08／R09 衔接，不此时定价格或工坊系统。

E12 同名合成可保留为兼容的另一条途径，E18 特殊事件可作补充，不要求本次全部采用。若采用同名消耗，应由玩家主动选择，因为 D01 已允许重复装备服务当前阵容；不能凑齐自动合并，抹去多件穿戴的决定。E13 同类材料、E16 配方追逐、E17 共用成长机会同样保留对照，不能只因可兼容就全部安排进初期。

### 用户回应与恢复

用户要求材料尽量通用，可以考虑和金币分开，也可以需要只有高级 Boss 稳定产出的特定升级材料，以形成风险收益取舍，但不能不升级就玩不了。记录 M05-D03：通用性与非强制升级边界已定，独立材料及 Boss 稳定产出保留可考虑方向，不把它扩成所有升级的必经门槛或每件装备专属配方。

本次没有逐条采用 P01；确定成功、同名合成及其他补充渠道仍非用户决定。Q03 按材料与风险方向阶段收束，供给、费用、窗口及 Boss 安排归 R08／R09／R12／R13；下一项先核对品质增强内容的真实公共分歧，避免把不同装备特效再做成全局单选。I21 记录上述依赖，I20 保留词条唯一及不同品质共存规则；未修改权威或实现。
