# 玩家单位数值校准（2026-09-26）

本轮完成31名发布可选英雄的首次数值校准，其中17名进入当前征程池；7名保留库未改动、未重新开放。参数是可试玩的一版，不是最终平衡或自然胜率。执行／恢复归[活动任务](../../../../work-items/active/player-unit-balance.md)。

## 行为与职责

- 普攻统一对敌输出。济世医师、盈光祭司只通过明确技能治疗，保留各自治疗事件联动。
- 正式怒拳的怒劲不自然消失；施放消耗、死亡／战斗结束清空，原有满怒／半血／濒死和排队规则保持。
- 收紧通用坦度、续航与施法频率；补足追刃客近战存活和霜羽猎手基础输出。保留需要队友、状态、护盾、召唤等投入才能兑现的能力。

## 验证与限制

`PlayerUnitBalanceCalibration`采用同一固定种子、同一四人裸装队框架，每次替换一名候选，在第4／6层精英场景采样；31名均覆盖，共62个配置。固定搭档不适配所有专门机制，不能据此直接给英雄排名，也不是按自然获取时点安排的征程。保留三个阶段的记录：

- `before.json`：旧玩家数值、上轮敌人曲线。
- `iteration1.json`：只调整玩家与治疗／怒劲后的对照（霜羽攻击当时12）；暴露中区过度增压。
- `after.json`：最终玩家参数与回调后的遭遇曲线；包含双方变化，不能把全部胜负差异归因为玩家调参。

第6层此裸装框架由旧版30/31胜，变为只改玩家时0/31胜，再到联合校准后的16/31胜；这是固定框架的压力分布，不是通关率。济世医师作为候选时，旧样本26.1秒治疗1018，现30.6秒治疗560；怒拳现可出3拳。角色战斗时长与敌方配置不同，不把总量当作纯系数变化。

`stages-final.json`合并以下未失效记录：旧`difficulty/player-balance-iteration1.json`的第1／5层（后续未涉及其英雄／敌人参数）、`player-balance-iteration3.json`的第10／15层和`player-balance-pressure.json`的第9／14层。原始迭代文件保留在difficulty目录。

## 敌我隔离和资源复用

`before-authoring.json`／`after-authoring.json`记录独立单位字段和依赖指纹；`python tools/audit_player_balance.py after`确认95份敌方玩法资源均未被玩家调参改变。当前生产英雄与敌人没有共用可调数值的定义／技能依赖，20份静态视觉或组件资源共用。现有ContentValidator继续拒绝重复定义引用和错误敌我分类，无需复制贴图或再建旁路属性层。

同素材的玩家／PvE敌人分别读取各自定义。实验室将一个英雄放到敌方测试队时仍使用其英雄定义，不能据此改写共用资源。运行状态仍归每个战斗实例。

## 通过的检查与待试玩

- 低并发.NET构建0警告／错误。
- `PlayerUnitBalanceContractSmoke`：带受伤队友仍普攻敌人；正治疗属性不能切回普疗；技能治疗、事件归属、运行数据隔离。
- `GritActionQueueContractSmoke`：长间隔受伤且反复治满仍能出拳，受控保留、消费、队列、濒死次数、复活、回滚和确定性。
- `DuelGritHookContractSmoke`、`FirstContentSystemsContractSmoke`、`EnemyDifficultyContractSmoke`：三英雄规则、控制概率、共享机制及正式阶段／结算。机兵测试改用生命比例伤害，保持两次非致命触发输入。
- `BattleFloatingCueContractSmoke`：当前正式界面生成治疗数字；实际鼠标选择仍可读取状态；浮字上限和清理通过。旧测试内容包、节点与状态文本入口已迁到当前正式界面，断言目的保留。无新截图／观感验收。
- 全局生命与Boss失败规则未改；相关结算由难度契约入口覆盖。未操作玩家存档、未自动跑整条征程。
- 待玩家验收：治疗等待时间是否可读、怒拳在实际站位下是否及时出手、转入中区的补强机会、棘毒末区弱点、召唤与深羁绊收益是否合适。
