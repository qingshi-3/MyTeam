# 成长征程交付与运行证据

玩家入口：启动正式主场景，在菜单选择“成长征程 · 工坊与升阶”。开局六选二后进入首战部署；军团面板的“成长工坊”提供生产分配、材料升阶、固定三选一、研究制作和法术预设。该入口使用 `growth-journey` 存档命名空间。

## 已接通的范围

- 26名代表单位与分段真实供给，包含三个节点生产来源、霜羽／构装战斗组合和九名后段发现候选；不是49位的全量运营重构。
- 生产按受益者原始攻击／生命的4%线性累加，或改为研究；生产者与受益者必须在冻结参与名单内。已有增量留在本局单位实例中，不随生产者下阵消失。
- 非终局节点材料+1，一名英雄最多花4材料升阶一次，同时冻结三个不同未拥有的高阶伙伴供领取；不足三项或保存失败时整次不支付。
- 研究4兑换一份法术，开战前预设，真实开战验证与保存成功才消费；启动失败／重载不重复支付。法术只存在于该次战斗能力中。
- MX01每战首次成功冻结的16最大生命当场生效并跨战保存；MX03机制升阶实际保留跨目标寒意计数。临时增益不整体回存。
- 普通／精英败战按全局生命决定继续，Boss败战终局；v8状态与明确的v7迁移、重复请求、冻结、保存失败回滚都有定向检查。

## 最终配置与结果

成长征程已经改用独立地区／遭遇资源。首区保持原值；二区相对Alpha的普通／精英生命与伤害为1.25／1.15，Boss为1.5／1.25；三区普通／精英为1.25／1.25，Boss为1.10／1.40。原有层内曲线继续相乘，敌人场景与美术复用。调优重点是中段组合门槛和末段输出压力，避免主要靠叠生命延长战斗。

最终资源上的31条连续征程共261战，238胜、23败、无超时；20局完成三个Boss，11局在Boss失败终止。原三个种子中霜羽、定向培养、研究和无生产者升阶路线各3/3通关；缺投入路线均在第二Boss止步。未参与选参的两个种子中，培养与霜羽仍可通关，研究和低投入各有一局失败，不能将结果推广为所有散搭必败或所有成熟组合必胜。

## 历史证据及解释边界

- [最初九局](growth-journeys-baseline.json)：84场战斗全胜，说明原压力不足；保留原结果。
- [十二局反例](growth-counterexample-journeys.md)：10局通关，两局止于第二Boss。
- [初轮压力分析](growth-pressure-comparison.md)：拆解实际羁绊、队伍职责、供给时序和法术目标。所谓散搭自然形成了四霜等有效组合，不能当成无羁绊；最初研究脚本选错法术受益者，不能据此断言法术无效。
- [选参时的42局](growth-profile-journeys.md)使用修正后的七路线及两档测试专用敌人profile。它们是真实连续供给与战斗，参数克隆不代表最终发布的难度；同checkpoint的法术分支是单场因果对照，不能另算完整征程。
- 单位遥测包括伤害、治疗、控制施加次数与有效量、承伤、护盾吸收、普攻和逐技能释放次数；尚不能完整归因控制持续时间。
- 旧authored／holdout文件中Godot坐标曾被序列化为`{}`，不能直接从这些JSON还原站位。记录代码已修正，新精英结果保存明确X／Y；未猜测回填旧数据，也未为记录格式重复跑整批战斗。

连续诊断使用真实 `RunApplication`、逐节点序列化重载及 `BattleSimulation`，不注入金币、材料、单位或成长，不伪造胜利。供应缺失、普通失败与Boss止步都原样记录。有限种子及固定选牌脚本用于发现问题，不是总体胜率、最优策略证明或玩家体验验收。
