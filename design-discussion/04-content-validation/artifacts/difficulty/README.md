# 敌人难度首轮校准 · 2026-09-26

用户“推进”后的可执行首轮。规则归 `gameplay-design/tower-autobattler-core.md`，执行入口归 `work-items/active/enemy-difficulty-and-build-gates.md`；本目录是实测证据，不是另一套玩法权威。

## 方法与边界

`tests/EnemyDifficultyCalibration.tscn` 发布正式内容包，调用正式 Run 战斗准备与 `BattleSimulation.RunToEnd()`，不修改模拟结果、不干预生命、不注入胜负。使用 1776、2026、9173 三个固定种子；每个锚点分别比较普通／精英或 Boss，不代表该种子在同一层同时提供两种路线。固定 BattleNumber = FloorIndex、相同站位规则，无手动战术指令。每次读取完整结算、时长、原队伍余量、剩余敌人和摘要。

| 阶段 | 人数 | 物品投入 | 获取边界 |
| --- | --- | --- | --- |
| 开局 | 2 | 0 | T1/T2 基础职责组合；没有按初始人口 7 当作开局已有 7 人。 |
| 第4–5层 | 3 | 1件18金币装备 | 仅用 T1/T2，不要求T3核心或深羁绊。 |
| 第6–10层 | 4 | 2件18金币装备＋1件24金币遗物 | 60金币等价物品预算；T3英雄可从第4层起抽到，尚未假设必得；不带T4。 |
| 第11–15层 | 5 | 4件18金币装备＋1件24金币遗物 | 96金币等价预算；阵容可包含T4功能位。 |
| 额外人数压力样本 | 7 | 3件18金币装备＋1件24金币遗物 | 总标价113（英雄均5）低于5人组121；额外招募也消耗路线机会。第11层的7人刻意超出部分种子的可达人数，用作偏向人数队的压力检查；第14–15层才是正常可达上限检查。 |

真实供给核对：开局六选二；固定路线轮转下，首领前剩余三层只有1或2次招募机会，所以首 Boss 按3人而非4–7人校准；第二个 Boss 前累计最多5或6人；末区才可能到7人。招募、营火和精英互相竞争，战斗、事件和商店也竞争；上表不是“每层白送一次招募和装备”。同组装备单价均18、遗物单价24，英雄单价均5，实际队伍和持有者逐项写入 JSON。

这些是同投入的**战斗能力**比较，没有证明整局必然取得指定物品，尤其不能把四霜羽作为所有局的强制配方。当前铁甲卫与霜羽猎手本来各贡献1名成员，4人羁绊需要再给其他两名英雄配徽章。`winter` 固定对照保留一枚配在铁甲卫上的冗余徽章；`winter-efficient` 把它换成等价攻击装备，独立列作补测，不能冒称有对应旧基线。供给概率／自适应选牌策略／全程败战丢奖励后的实际成型率仍由后续试玩继续校准，本轮没有新增保底或强制配方供给。

## 已落地

- 9种地区／节点配置，共17个完整敌阵模板。首区前哨三人，之后盾后弩阵／双翼突袭；中区尸群掩护／贯光与冲阵；末区鳞甲护射／重卫贯光／换位火网／冲阵回刃；三个Boss保留原技能与阶段，配固定职责护卫。
- 地区与局部层数分别配置生命、攻击，取乘积。首区逐渐加压；中区散搭的存活余量明显下降并开始出现败战；末区用较高生命配适度攻击延长压力，避免仅提高瞬时伤害把正常构筑一起秒掉。所有倍率只作用于初始敌人生命和攻击；固定值技能、召唤物不自动同比增长。
- 霜羽成员攻速由2人+0.15／4人+0.30改为+0.25／+0.65。冰冻25%／35%／50%与0.8秒、重复成员不叠计、徽章不送技能保持。通用装备和遗物未削弱。
- 预览、实际战斗、结算认证共享模板和站位。显示敌阵名及原有敌人／地形信息；全局生命、营火、败战推进、Boss一败结束继续沿原规则运行。

具体数值只在 `content/project/encounters/*.tres` 和 `content/traits/definitions/trait_ne10_winter.tres` 维护。

## 关键实测

每行每种阵容3个固定种子，**不是玩家胜率**；更完整的数据见 [前后对照](comparison.md) 和 [最终记录](final.json)。

| 检查点 | 调整前 | 当前 |
| --- | --- | --- |
| 两种散搭，第9层普通 | 均3/3，生命余量约90% | 分别2/3、3/3，平均余量9%／20% |
| 两种散搭，第二Boss | 均3/3 | 均0/3 |
| 棘毒／召唤／霜羽，第二Boss | 均3/3、压力很小 | 均3/3，余量76%／64%／84% |
| 五人散搭，第11层普通 | 均3/3 | 均0/3 |
| 成型棘毒／召唤／霜羽，第11层普通 | 均3/3 | 均3/3，余量约84%／64%／85%，保留优势战 |
| 两种五人散搭，最终Boss | 2/3、3/3 | 均0/3 |
| 七人人数队，最终Boss | 没有对应旧样本 | 1/3，平均余量10%；第11→14层普通余量54%→31%，第14层精英2/3 |
| 棘毒／召唤／完整霜羽，最终Boss | 均3/3 | 均3/3 |
| 霜羽缺深羁绊，最终Boss | 3/3 | 0/3 |
| 棘毒失去持续支援，最终Boss | 无旧样本 | 0/3；同投入完整棘毒3/3 |

不是所有换掉指定核心都应失败：`summon-missing` 换掉砂骨核心后，仍保留群兽、护盾／亡语与治疗，属于有效替代配合，最终Boss仍3/3；不会为了凑“缺件必败”结果强行砍掉这种组合。原五人普攻小配合 `attack-pair` 能应付部分普通战，但当前第二／最终Boss均0/3，说明小配合不能自动等于足够完整的后期构筑。

当前保留的压力点：第14层普通固定站位下棘毒／霜羽为2/3，精英更严；这时需要读敌阵和地形、换站位／功能位或选择恢复。最终Boss完整构筑约568／664／916 ticks，霜羽较慢，玩家需重点体验是否拖沓。七人队仍可能战胜最终Boss，目标是其常规上限和可靠性受限，不用隐藏规则保证它必败。原队伍余量由最终生命／生命上限汇总，返场、临时单位不用于冒充征程生命变化。

## 数据来源与复现

- `before.json`：255场，改动前生产内容与随机填池。
- `iteration1.json`：首次加压，暴露后段伤害过高、正常构筑一起失败，已回调。

- `after.json`：315场完整中间矩阵，第二Boss小幅回调、加入人数与缺件补测后保存；后段仍偏松，因此不是当前最终值。
- `late-sustain.json`：提高末区持续压力后的165场，只重测第11／14／15层。
- `mid-pressure.json`：最终中区普通增长后的42场，只重测第9层。
- `final.json`：在 `after.json` 上按阵容／层数／类型／种子替换上述已重测行，合计315场；未改区域复用其已验证记录。`comparison.md` 由同名样本生成，不把新增补测冒充前后对照。

PowerShell：先 `dotnet build my-team.csproj -maxcpucount:2 -v:minimal`，再设置 `$env:CALIBRATION_LABEL='review'`，运行 Godot `--headless --path . res://tests/EnemyDifficultyCalibration.tscn`。可选 `$env:CALIBRATION_FLOORS='8,13,14'` 只复测指定**零基**层号；删除该环境变量恢复完整锚点。输出写本目录，不触碰玩家存档。不要把某次标签的结果覆盖成另一组配置的结果。
