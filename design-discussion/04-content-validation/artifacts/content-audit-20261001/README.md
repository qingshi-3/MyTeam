# 成长征程内容审查

后续更新：本文与 `inventory.json` 保存**清理前审查快照**，其中旧供给数量和资源路径用于定位当时问题。用户随后授权清理并要求整体重设计；实际改动、空白名单和未完成项见 [redesign.md](redesign.md)，验证见 [verification.md](verification.md)。下文“本轮只审查”仅指最初审查轮次。

2026-10-01。审查对象为当前工作区中主菜单实际进入的成长征程。结论是：组队、培养、战前投入和精英选敌的骨架符合规划，但旧物品、矩阵羁绊与26名代表英雄的供给没有完整衔接；部分奖励没有效果，部分构筑目标不可达，升阶和事件也尚未提供规划要求的选择深度。当前不宜仅靠调整敌人数值解决这些问题。

这是审查事实与 Agent 建议，不是新增玩法决定或修复完成记录。本轮只增加讨论记录和静态盘点，没有修改游戏规则、代码、运行资源或玩家存档。

## 范围与判断依据

- 主入口：[project.godot](../../../../project.godot) 指向 `GrowthGameRoot.tscn`。成长战役使用26名英雄的供给池，并直接复用含6件装备、15件遗物的 `pool_all_items`。14条矩阵羁绊共39档，另加载两条旧装备羁绊。
- 正式规则：[构筑框架](../../../../gameplay-design/combat-build-framework.md)的共同构筑语言、核心与功能位、装备联动及成长基线；[核心规则](../../../../gameplay-design/tower-autobattler-core.md)的纯自动战斗、选敌、法术和独立奖励组。
- 规划边界：[M03](../../../02-foundation-models/trait-model/decisions.md)、[M05](../../../02-foundation-models/equipment-model/decisions.md)、[M06](../../../02-foundation-models/relic-model/decisions.md)、[R08](../../../03-run-mechanisms/supply-and-economy/shops-and-rewards/decisions.md)及[内容决定](../../decisions.md)。已确认但未整合的方向按规划缺口处理，不冒充现行代码违约。
- 范围限定：[成长活动任务](../../../../work-items/archive/growth-and-composition-design.md)明确本批只制作26名代表，重点验证霜羽与构装工坊；不能把未制作全部49名本身列为错误。需要审查的是这个代表包进入主流程之后，玩家实际看到的目标、候选和效果是否自洽。
- [静态盘点](inventory.json)记录逐英雄标签、14条羁绊可达性、21件物品、26项升阶及来源 SHA-256。全体26名可取得英雄均为 `IsHero = true`；升阶发现池也没有池外英雄。可达性上界包含所有合法招募与发现，不代表一次正常征程保证取得这些英雄。

## 优先处理的问题

### A01 四件遗物在当前征程没有合法受益者

**P1，代码与供给静态证实。** 行军战鼓、远征口粮、引魂灯、最后军旗都使用 `RelicPlayerArmyTargetSpec`。实际筛选条件是我方、初始单位、非临时、非英雄；当前常驻阵容全部是英雄，战中召唤物又被明确排除。因此它们既不强化玩家英雄，也不强化工蜂、灵体或构装机芯生成的临时单位。

这四件仍进入普通商店和战利品，占初始15件遗物池的4件，约26.7%。最后军旗还标价34金币。玩家可以花掉金币或一次奖励选择，却没有战斗收益；这不是“暂时缺少配套”，因为当前整局合法供给都无法补出所需常驻士兵。

证据：[目标筛选](../../../../src/Relics/RelicScopes.cs)、[物品池](../../../../content/project/pools/pool_all_items.tres)、[英雄池](../../../../content/growth/project/growth_hero_pool.tres)。对应定义位于 `content/relics/definitions/item_{war_drum,field_rations,soul_lantern,last_banner}.tres`。

**建议：** 优先让成长征程停止提供这些无效候选，再按各自职责决定改为英雄、召唤或其他明确对象。不要简单把四件全部扩大为全队属性，避免将无效物品问题变成通用属性堆叠。

### A02 冰系装备与当前冰系英雄没有使用同一套身份和状态

**P1，代码与资源静态证实。** 这里存在两个独立断点。

1. 霜羽徽章贡献的是旧 `trait_ne10_winter`（霜羽同盟），当前冻原盾卫等英雄贡献的是 `mx_frost`（霜羽）。给已有3名当前霜羽的队伍配一枚徽章，仍然只有3点当前霜羽，另起1点旧同盟；不会达到预期的4霜羽。收集多枚徽章仍可以组成旧同盟并获得攻速，所以它不是完全无效，而是无法承担当前体系的补位装备职责。
2. 霜痕战刃施加 `status_frost`，转成 `status_freeze`；当前英雄读取的寒意是矩阵独立计数，`Frozen` 条件又只接受 `matrix_freeze`。例如裂冰斗士被动要求攻击被冻结目标后获得盾，武器单独造成的旧冻结不能满足这个条件。它仍可满足部分广义“受控”判断，不能夸大为全部控制联动失效。

证据：[徽章贡献](../../../../content/equipment/definitions/equipment_ne10_winter_badge.tres)、[英雄贡献](../../../../content/validation_matrix/definitions/hero_mx01.tres)、[战刃](../../../../content/equipment/definitions/equipment_rimebrand.tres)、[冻结判定](../../../../src/Battle/BattleMatrixAbilities.cs)、[裂冰斗士被动](../../../../content/validation_matrix/abilities/hero_mx02_p.tres)。

**建议：** 先统一玩家可以理解的羁绊身份及寒意、冻结接口，核对贡献去重、触发归属、持续时间和冻结限制，再调装备强度。若有意保留两种冰系，须给予足够不同的职责和说明，不能让相近名称承担互不兼容的承诺。

**P1，可达性静态证实；属于当前代表包与展示的衔接问题。** 26名英雄及全部发现候选合计只能覆盖39档中的24档。当前装备只提供旧羁绊，两种物品都不能补矩阵人数；临时召唤物不计数，普通招募也不允许重复英雄。即使假定取得所有相关英雄，以下上界仍然成立。

**建议：** 先明确代表包本局支持哪些完整路线，对不可达目标作明确区分；需要保留为可玩目标的档位，再补实际取得路径或适配当前档位。不能直接假定“把其余23名塞进池里”就解决问题，那会改变供给稀释和成型成本。

### A04 十九名英雄的升阶只附加相同的开场小盾

**P1，资源及基础／升阶能力集对比证实；属于设计完成度不足。** 26名可升阶英雄中，15名只新增“开战20盾、持续2.5秒”，4名GX只新增“开战32盾、持续3秒”。这19项保留全部基础能力，只追加这一个护盾能力，没有改变原有输出、状态利用或运营机制。

同一机制覆盖近战、远程、施法和运营单位，不能充分回答“为什么现在升这名英雄”。对暂时不会受击的后排，小盾还可能在承伤前消失；这一点是时序风险，本轮未测实际浪费比例。升阶同时获得高阶三选一仍有价值，但容易使玩家主要为发现新英雄而付款，削弱规划中“旧核心机制成长”的另一半。

证据：[26项升阶盘点](inventory.json)、雪幕术士与 GX01 的旧占位资源（本次后续清理已删除，原数值保留在盘点中）、[一次升阶与发现规则](../../../../src/Growth/GrowthRunService.cs)。

寒羽游侠的换目标保计数、碎盾锤的消盾后返盾、机弩手的破盾攻速窗口则已有原机制的延伸，适合作为审查其他升阶的参照。这里不要求每个升阶都新增复杂系统，而应改变该单位原有机制的使用条件、覆盖、兑现或风险。

## 选择深度和收益结构

### A05 装备和遗物尚未形成足够丰富的体系配套

**P2，内容盘点证实，合理性为设计评估。** 六件装备中，四件只有基础属性，一件是攻速加旧羁绊，一件是命中触发的冰系战刃。当前没有可取得的毒层利用、护盾转换或召唤死亡联动装备。并非基础属性装备应被删除：攻速、回蓝可以通过英雄技能间接形成重要配合；缺口在于它们几乎包办了全部装备选择，玩家很少能靠装备改变一个英雄在体系中的职责。

遗物也以通用属性、开场盾和少量控制／召唤补强为主。玩家早在内容决定D26提出“特殊机制不足”，D28的图标和音效接入明确没有修订效果，因此不能把物品美术完成当作这个反馈已解决。

| 装备 | 当前用途 | 审查判断 |
| --- | --- | --- |
| 先锋徽甲 | 持有者护甲加12 | 合理的生存基础件，价值取决于承伤位置 |
| 精工瞄具 | 持有者攻击加10 | 合理的过渡输出件，需与成长后的比例收益比较 |
| 蓄能护符 | 每秒额外3法力 | 有助主动循环，是目前较明确的通用机制配套 |
| 疾攻手套 | 攻速加0.25 | 能支持普攻和命中触发，应保留这种间接联动 |
| 霜羽徽章 | 攻速加0.10及旧同盟身份 | 当前体系补位不成立，见A02 |
| 霜痕战刃 | 命中叠攻速、寒霜、冻结及旧装备羁绊 | 机制丰富，但共享状态衔接不足，见A02 |

| 遗物 | 当前实际作用 | 审查判断 |

**建议：** 以当前真正支持的路线补完整的供给、转换和兑现配套，而非平均给所有名称各加一件。先修无效目标和状态兼容，再比较体系专用件与通用属性件的机会成本。当前证据不支持直接削弱生命、吸血或统一提高羁绊倍率。

### A06 同一供给池没有充分区分奖励价值和兑现阶段

**P2，限定条件下的数值比较证实。** 壁垒军旗15盾和整军壁垒40盾走同一个开场授盾处理。在同次免费遗物选择、尚未持有两件的前提下，40盾在效果上严格更优；17与24的商店价差无法给免费领奖增加取舍。这不等于15盾永远无用：两件可以先后取得并叠加。

鎏金军契标价16，每次胜利返3；若剩余至多5次胜利，单靠自身收益最多返15，无法回本。商店仍使用同一全年段物品池，没有剩余结算次数筛选。免费拿到它与花钱买它是不同判断，不能混为一谈。

证据：[成长战役](../../../../content/growth/growth_campaign.tres)、[通用选择生成](../../../../src/Project/RunOfferDefaults.cs)、[遗物授盾](../../../../src/Relics/RelicScopes.cs)、[物品价格](../../../../content/definitions/items/item_gilded_contract.tres)。

**建议：** 奖励与商店分别评估价值，给同类遗物不同触发条件或收益用途，并处理依赖剩余推进次数的经济内容。保留“普通遗物唯一、装备可重复”的现行规则；本轮没有采用稀有度、弃奖补偿或刷新新制度。

### A07 事件只有金币概率选择

**P2，内容和运行配方静态证实。** 当前成长战役没有覆盖默认事件，所有事件都是同一对选项：65%获得18金币、失败无收益；或确定获得6金币。前者期望11.7金币，后者提供确定性，因此仍存在风险偏好及购置门槛的差异，不能称为绝对没有选择。但它不读取阵容、装备、遗物、材料、研究或成长状态，反复出现时很难形成构筑取舍。

这是事件内容的深度不足，不是应恢复扣血的证据。D54明确要求失败无收益并去掉扣血，当前实现遵守了这个决定。营火的恢复25全局生命与8金币已形成生命预算取舍，满血时恢复禁用也合理。

证据：[默认事件和营火](../../../../src/Project/RunOfferDefaults.cs)、[当前数值](../../../../src/Project/RunRulesDefinition.cs)、[D54](../../decisions.md)。

**建议：** 让事件围绕现有成长、物品和队伍需求提供不同机会成本，并在选择前说明取得和放弃什么。具体交换、培养或特殊奖励方案仍需设计，不借审查擅自开放出售、返还或移除权限。

### A08 节点三选一只有两套固定类别组合

**P2，生成算法静态证实。** 六类轮转依次为普通战、招募、事件、精英、商店、营火；每次取三个，步长固定为2。因此非Boss层只会出现以下两组的排列：

- 普通战、事件、商店。
- 招募、精英、营火。

种子和层数会改变排列与奇偶组，不能形成更多类别组合。具体战斗阵容、奖励和英雄候选仍有随机性，所以不是每局内容完全相同。实际代价是玩家不会在同层比较“招募还是买装备”等组合，类别机会的节奏相当固定。

证据：[节点表](../../../../content/project/tower_node_table.tres)、[默认步长](../../../../src/Project/TowerNodeTableDefinition.cs)、[路线生成](../../../../src/Run/TowerGenerator.cs)。

**建议：** 将它作为R10外层循环尚未收口的已知限制，先定义不同阶段应出现哪些竞争，再决定组合规则。当前正式规则仍保留15节点／三区，不能把这个发现直接当成采用新地图或全面随机节点的授权。

## 符合规划的部分

- 职业与体系双轴、开战定档、成员受益和部分跨成员协作已有实际机制；毒、寒意、护盾、召唤、魂能、施法资源的过程并非只换名称。当前首要问题是供给覆盖和跨系统接口，不能据此否定全部羁绊设计。
- 基础收益与装备／遗物奖励组分离，组内选择、独立跳过、普通遗物唯一、商店已售商品不自动补货，符合已局部整合的规划。
- 精英候选展示具体敌阵，并以金币、研究、材料作差异收益；例如首区三种精英分别给研究4、材料2、金币6的额外胜利收益，已有明确的战前风险与资源选择。
- 生产者将同一次机会用于攻击培养、生命培养或研究，战前法术消耗有限库存，已经为纯自动战斗提供了战前投入。是否划算仍取决于取得时点、自动行为和具体对手，不能只按配置存在判定体验通过。

## 后续处理顺序与验证边界

1. 先处理A01至A03：无效物品、冰系接口和不可达目标。它们会污染玩家反馈，先调数值可能把错误内容暂时掩盖。
2. 再按英雄原有职责完成A04的升阶差异，并为当前完整路线补A05所缺的装备／遗物作用。每项说明适合谁、改变什么、何时取得、占用什么机会以及替代品。
3. 随后处理A06至A08的阶段供给、事件和节点竞争。保留已确认结构，未整合的刷新、回收、装备品质和外层循环另按现有专题推进。
4. 内容衔接修正后，再做少量同阶段、同投入的真实征程对照。观察成型时间、无效候选次数、升阶对象变化和战前调整能否兑现，再决定强弱数值。无需先扩成全流程大回归。

本轮完成资源全量盘点、核心判定路径追踪、基础与升阶能力集合比较，以及可达性／数值的静态核算。没有新跑战斗、编译或隔离真实输入；此前矩阵与成长路线的模拟仅作为范围背景，不作为当前平衡已验证的依据。19项小盾的实际吸收率、通用吸血生命组合是否过强、法术性价比及玩家选择体验仍未验证。最终观感、手感、节奏和平衡也没有记为用户认可。
