# R03 替换与培养回收：方案讨论

## R03-Q01：可回收的培养价值以什么形式返回

日期：2026-09-08。状态：后续 [R03-D01](decisions.md)已采用 RC01，折损留待实际体验决定。以下保留原推荐与取舍，证据与 RC01–RC05 见 [已有证据](evidence.md)。承接 R02 的共享＋类别资源混合支付、英雄专属机制成长；不重开装备转移、不默认下场即退款。

### Q01-P01：优先按实际投入种类回收

Agent 推荐 RC01：回收时按真实支付的通用／类别材料分别返回相应库存。是否全额、扣减方式及触发窗口另定，本建议不意味着可以免费随时重置，也不决定出售或保留英雄。

理由：它保持 R02-D02／D03 的材料含义。法师路线取得的材料经过培养与回收后仍用于匹配英雄，通用资源则保留自由分配；同体系更换核心和跨体系转型会自然拥有不同的剩余资源适配情况，而不增加一套强制锁阵容规则。代价是跨体系退出后可能有暂时不用的类别库存，这个成本须在后续整体转型体验中评估。

如果用户希望跨体系转型也有很高自由度，RC02 更符合该目标，但应明确接受类别资源可经培养回收转为通用预算的经济意义。RC03 更强调方向承诺；RC04 是直接指定接受者的迁移形式，可与材料适用规则组合；RC05 将培养与金币支出连接，当前缺少可直接支持材料再购的经济决定，暂不作为优先推荐。

### 本轮边界与下一步

不以材料分配等效推定不同英雄同品阶等价，也不把旧英雄的专属加强移植给新英雄。返回已撤销的投入与保留成长不能重复享有，是普通价值归属问题；后续按实际选择核对，不先新增通用反循环系统或实现任务。

先处理用户对返回形式的回应，再讨论撤回培养是否保留英雄、触发窗口与损失边界，最后定比例。R02 的类别资格与免费／折扣节点可在真实需要时回看；R07／R08／R09 衔接招募收入、资源渠道与经济，R04 区分后备轮换与退出，I24 跟踪跨题关系。现阶段只讨论和记录。

### 用户回应：采用 RC01，折损依据实际体验再定

用户选用 RC01，并允许考虑适当折损，具体按玩起来是否足够爽再定，已记录 R03-D01。返回形式收束；折损是否采用、扣减多少不在本轮补定，也不因提到体验就启动原型或试玩。下一步处理触发窗口与英雄去留等真实未定项，不重复表决返回形式或立即追问损失比例。

## R03-Q02：撤回培养的操作、英雄去留与可用窗口

日期：2026-09-08。状态：后续 [R03-D02](decisions.md)已采用 RT01＋RT06＋RT07；以下保留原推荐，其常规战前开放范围未被采用。比较与来源见 [RT01–RT07](evidence.md)。D01 的实际材料返还与体验后决定折损保持。

### Q02-P01：优先保留英雄的整份培养回收，常规战前可用

Agent 推荐 RT01＋RT05：合法战前准备中，玩家可主动撤回某英雄的整份可回收培养，按 D01 返回对应材料并移除该部分加强，英雄保留在名册，可继续承担基础技能、功能与羁绊职责。不是换下场自动退，也不强迫用户放弃已招到的英雄才能调配投资。

这与允许低费单位在核心和羁绊位之间转换、前期探索后按装备／遗物定型的方向吻合。常规回收不以额外节点或专用道具为前提；回收代价是否包含折损、多少折损仍按用户后续体验判断，不在此预设免费无损。

RT02 局部撤销确有细调价值，但会涉及多个成长结构的依赖与回退说明，初期不建议仅为精细分配强做全节点撤销。RT03／RT04 增强退出承诺但会牺牲保留英雄的灵活性；RT06／RT07 增加机会规划同时使回收依赖服务或物品。全部保留比较，以上优先级尚未获采用。

### 待回应与依赖

先处理用户对操作与窗口的回应，不能用 G03 自由部署直接替用户批准成长重置。之后按被采用的成长结构核对重新培养时专属选择／随机候选如何处理，以及免费／折扣成长的回收归属；不预先建立通用反刷新系统。折损比例不再作立即表决项。I24 联动 R02／R04／R07／R08／R10／R12；只讨论记录，未实现或试玩。

### 用户回应：整体回退，服务／物品提供门槛，避免游玩负担

用户选择 RT01＋RT06＋RT07，默认全部回退，保留英雄；RT02 只有交互极其便捷流畅、阶梯精准且易理解时才可考虑。用户明确否定无条件无门槛回退，认为它会成为游玩负担，记录 R03-D02。因此原方案不能继续以“更灵活”为理由默认每场随时开放，服务和物品门槛需要真实存在；具体频率／价格未定，不能替用户叠加固定限制。

后续按 D02 继续，不再等待 RT01＋RT05 的表决，也不默认精细回退初期制作。服务与物品是两类已接受入口，是否联用、何时可用及物品供给另按实际设计明确；折损仍归 D01 后续体验。下一步核对重新培养时选择和候选的关系，不先做交互原型或技术方案。

## R03-Q03：整体回退后，再培养是否重选或重新抽取加强

日期：2026-09-08。状态：后续 [R03-D03](decisions.md)已采用 RE01＋RE04。以下保留推荐与取舍；研究与 RE01–RE05 见 [已有证据](evidence.md)，原作依据与项目推演分开，D01／D02 的返还、整体回退及实际门槛保持。

### Q03-P01：明确分支允许重选，随机节点可重新抽取

Agent 推荐按成长类型处理：固定路线仍取得对应加强；有明确专精／路径的结构采用 RE01，回退后可重新选择；实际采用随机候选的英雄可用 RE04，重新升阶时按当前合法池生成候选。不要求每个英雄随机、不开放精细回退，不默认保留原结果作保险。

理由：用户已要求回退有真实门槛，因此合法回退可以承载同一英雄改换玩法的价值。为得到更适合新装备／遗物的加强而消耗一次服务或物品机会，是可理解的用途；不能只按无成本无限刷的假设再锁死选择。本建议也不保证重抽更好，旧加强可能不再出现。

若用户希望随机机会在首次培养时即固定，RE03 仍能纠错旧选择、又不增加随机机会；RE02 则只提供资源回收。RE05 更保护原有构筑，但提高反复寻找理想结果的能力，暂不作为通用推荐。保留不同形式的价值，不因推荐 RE04 隐藏其他机制。

### 下一步与依赖

先处理重养选择的回应，勿再次要求批准无门槛回退、精细回退或折损比例。后续服务／物品供给要知道重置是否包含重抽价值，归 R08／R09／R10；专精改变后候选资格与 R02 衔接。免费、赠送及折扣成长的返还归属还须在实际内容出现时明确，不以本题自动给出退款。I24 同步；未实现或试玩。

### 用户回应：同意 RE01＋RE04

用户同意 Q03-P01，已记录 R03-D03：明确分支回退后可重选，随机成长重新按合法池生成候选，固定路线保持。不默认保留旧结果作保险，也不新增全员随机或精细回退。Q03 收束，后续核对内容／供给／体验层的剩余事项，无基础冲突时转 R04，不重选回退门槛或折损比例。
