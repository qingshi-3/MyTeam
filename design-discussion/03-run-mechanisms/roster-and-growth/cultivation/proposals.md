# R02 英雄培养：方案讨论

## R02-Q07：培养维度的职责与重叠（2026-10-06，待讨论）

**当前衔接：** 用户已确认保留系统支撑能力，少量内容边做边测、按反馈取舍，统一见 [M05-D04](../../../02-foundation-models/equipment-model/decisions.md#m05-d04保留系统能力小批内容随测试反馈迭代)。因此不再把“是否先删除装备通用能力”作为前置选择；具体装备规模、成长配合、增益曲线和最终主次仍靠内容验证，以下分析不自动转为全部采用。

### 当前复核：装备的独立职责与成长放大速度（2026-10-06）

用户把装备分为数值与机制，提出高属性成长可能使数值装冗余、机制未必需要装备承接，并用 O(1)／O(n)／O(n²) 类比《将熄之焰》不同配方的提升。这里是用户对设计矛盾与体验的判断，不是删除本项目装备、否定所有非线性效果或采用新的公式。主 Agent 与 Astra（high）独立分析，保留 D09／D10；本轮未修改正式规则或实现。

沿用复杂度类比时，先把 n 定义为某项培养后的属性、把讨论对象定义为装备带来的增量，并固定其他相关条件。若无装输出近似随 n 线性增长，固定加值 c 的额外收益为常量；固定倍率 k 的额外收益为 (k−1)n，绝对回报随培养增长而增加，相对倍率不因此上升；同一成长规模同时提高每次伤害和触发次数，两者相乘才可能近似平方增长。两个固定百分比乘区仍是固定倍数，不能据此叫 O(n²)。实际范围、系数、目标数量、战斗时间与触发资格均影响回报；反馈循环需另按时间／迭代次数分析。

据此，高面板不使全部数值装备无价值，只会使固定加值的相对收益下降。机制也可能是扩大攻击次数、承接人数或复制效果的数值放大器，不能通过把效果叫作机制就宣称它不与培养争夺战力主导。酒馆未设常规装备槽的开发者动机未取得直接证据，不能推定因为属性高所以必然无需装备。

不同放大速度可以服务不同阶段，固定加值可能帮助前期存活，较高阶增长也可能是付出成本后形成组合的回报。若在正常可达的培养范围、相近取得／槽位成本下，某类配方大多数情境都压过另一类，才暴露选择退化的问题；仅用高低品质提高常数，不能自动修复不同曲线的交叉。主核若持续积累又获得多维放大，会更容易吸走装备和培养两边的资源，因此不能预先断言“可转移装备一定有利于养副核”。

装备可单独成立的候选理由是有限槽位中的可移交配置：把保护、输出覆盖或其他能力交给谁，是否值得从老核移给新人，能否在保留英雄身份时调整应对。相同效果放进固定技能、一次升阶或全局遗物，会改变选择对象、可逆性和机会成本；若这些载体已经提供同样且更清楚的配置价值，则没有必要额外造装备层。

Agent 暂倾向先检验少量可移交配置是否有独立价值，再决定是否展开装备品质／升级内容，而非默认恢复整套基础装与配方目录。这不是已选方案，也未撤销 M05-D01–D03。也可取消独立装备线，把效果归入现有载体，但要承认随之失去的局部配置、投入转移及物品奖励空间。若保留，先以低／典型／高培养量及前中后期实际战斗对照装备的相对收益和用途，检查是否扩大同一成长量的多个维度、与其他效果互相触发，以及对全队分配的影响。不设置新的通用培养硬顶，也不把所有高阶放大一律禁止。

### 当前复核：先明确主要构筑来源（2026-10-06）

用户以酒馆战棋几乎全靠属性、《将熄之焰》约七成靠装备、云顶偏升星与羁绊说明体验差异。这些百分比按用户对主要成长来源的感受记录，不作为实测贡献或已采用的项目比例。主 Agent 与 Astra（high）复核后撤回上一轮六四数值建议：没有成套内容和共同测量口径，它只是偏向培养的折中，尚不能支撑定位；下方保留历史理由与可复用的四组对照。

属性是结果，增长来源和决策重点需分别判断。酒馆通过单位触发、生产与放大组织成长，不能简化为只拼面板；《将熄之焰》的装备、遗物等与英雄能力共同构筑，并非英雄本身无关；云顶星级／人数羁绊是重要组织手段，装备仍会决定承接者与阵容结构。来源与限制见本题证据，不依据这些案例推导通用百分比。

结合老核心延续、持续成长及晚来成员价值，Agent 更倾向让单位能力与成长配合承担主要构筑，让装备提供有分量的补强、适配和部分机制变化。羁绊保持阵容组织与组合回报，不自动改为全部生产属性；装备可以在个别流派成为关键，也不因此必需每个普通核心都等一件指定装备才能发挥。可观察预期：正常取得的单位与成长组件已经能建立一条有作用的队伍路线，拿到契合装备后明显增强或调整应对；如果普遍都是先拿某件装备才知道队伍怎么组，实际定位就更接近装备主导。上述主次仍是待讨论建议，用户本轮举例未选择它，也没有改成八二等新数字。

### 历史六四提案：装备与永久属性培养的比重（2026-10-06）

用户将核心升阶作为共同前提，要求比较另两者，范围见 D10。主 Agent 与 Astra（high）建议：在中后期、正常培养的核心上，属性养成总体略重于装备，先以约六四的设计倾向讨论；不是实测贡献、伤害分账、资源兑换率、上限或每名英雄必须符合的定额。基础英雄、升阶、羁绊与遗物等保持可比，分别看追加培养和装备更替的收益，不能把英雄天生基础数值都算成培养贡献。

永久培养承担有分量的本体积累，装备同时提供属性、放大和机制适配。偏重培养服务于老伙伴的长期价值；若普遍拉到七三甚至更悬殊，需警惕后期装备奖励与新人补强失去分量。五五可支持更强的换装与适配体验，并非原则错误；六四是当前体验目标下的起点，不是已有数据支持的精确最优值。

比重用实际结果校准：同职责、相近取得条件下，充分培养的核心配普通合适装备，应通常比浅培养核心仅靠高品质堆数值更可靠；充分培养者从普通装备换成匹配其技能的装备，应获得清楚且值得争取的提升。机制装备针对某场遭遇成为决定因素是允许的，不能为了守六四削掉其特色。新人因技能更适合某个敌人而优于老核，也不等于培养失败。

装备可转移不等于转移无机会成本：移交后老核失去同件装备，必须比较全队结果。应避免同一套装备普遍搬给浅培养的同职责新人就完全取代老核，而非禁止合理换人。装备若产生永久成长，要区分其直接穿戴效果与历次培养产出，不能把同一收益重复算给两侧；不因属性源自装备就新设独立培养顶。

验证建议为同阶段、同升阶、同单位／队伍和敌人的四种对照：浅培养／充分培养 × 普通合适装备／较好且匹配的装备；比较生存、伤害、控制与全队胜负，再核对各组真实可取得的成本和时间。装备与成长存在乘算和机制互动，两边的移除损失不可直接相加为百分比；当前只定想要的相对关系，不声称完成测量。开局、功能位和装备强依赖的具体流派可以不同，不压成全局固定比例。

### 当前草案：持续成长如何形成选择（2026-10-06）

用户否定直接给属性定统一硬顶，并要求展开第二种方向，决定归 D09。以下由主 Agent 提案、Astra（high）独立复核，不是已采用的具体规则；没有运行、正式文档或资源修改。上轮来源已复读，本轮重点为项目适配，未证明平衡。

**培养结果与成长时机。** 初期优先比较攻击、法强、生命等直观且可分配的永久属性，不把所有英雄都做成全属性自增长。攻速、射程、减伤、冷却等优先保留给具体能力与装备；参数自身的合法范围不等于永久培养额度封顶。临时效果仍是临时效果，只有明确写明的成长跨战保留。单位、装备、遗物可提供不同成长方式，但不加一条统一经验等级或每人必点的训练菜单。

成长默认跟随真实进程结算，复用现有有效行动／冻结参与者的语义，不能按打开整备、换入名册、领奖或读档增加次数。需要区分实际参战触发与非战斗服务触发：战后产出不能临时换上后备领取；若服务前临时换上生产者即可免费领收益，就不能以该单位牺牲战斗席位作为平衡证据。第一批优先测试真实参战单位的产出；是否覆盖非战斗行动、相应资格和成本仍需单独确定，不能无说明恢复所有旧生产模式。

**三种成长关系并存。** 定向培养给玩家集中投入的自由；多目标成长让各合格成员得到独立份额，缺席者份额不自动全折给大哥；联动内容改善产出量、覆盖范围或把一种增长转为另一职责需要的属性。不是每套阵容必须有三种角色，也不要求所有英雄自带成长。示意：单目标每次 +8 攻击，与两名不同受益者各 +5 攻击，让集中收益和整队收益有区别；数字未经平衡，取得难度、战斗能力与实际受益人数必须一同计价。

常规产出优先固定增量或按未培养基准计算固定增量，避免因目标已成长就自动放大下一次同效果。例如基础 100、每次 +8，五次后 140；新配合令之后每次 +12 则继续加 12，既不抹掉历史也不因为接近某阈值减产。固定增量只是起点：增加合格触发机会、提高一次回报、扩大受益对象都可以产生构筑深度。纯倍率、自增长产出和复制会形成更强的组合，须逐套预算，不能凭“固定单次增量”宣称不存在经济复利。

**把副核的价值落实到收益。** 后期新人的关键用途应开箱可用，例如处理后排或群体目标；装备可转移、已有多目标成长能覆盖新人，定向收益仍可由玩家决定继续给老核。新人不自动复制老核积累，也不要求一切投入齐全才有战斗作用。示例路径：前期定向培养持续单体主核；中期取得覆盖多个队友的成长来源；后期引入能清杂的成员，同时参与后续成长，老核继续处理精英。二者面板不必追平；若最后几个机会才取得纯成长发动机，可能来不及回本，不能保证每次招募都值得买。

**成长路线必须有真实投入期。** 单占一格不足以证明代价：早期敌人过松会使成长者必选，过紧又可能让路线不可行。成长者应有基本战斗作用，但与同取得成本的即时战力单位相比，投入期和回本点必须在实际遭遇中存在。提供低效率可替代来源与多个独立成长方向，避免早期未抽中特定一人就无法通关；不采用统一免费成长保底或具体供给配额。限制无成本重复和无终点互相触发，优先把效果写成有清晰来源、合格对象与消耗的关系；不先套所有成长每战 N 次的机械总锁。战斗杀敌等路线需要区分真实遭遇目标与反复召唤／复活刷出的对象，不能让拖延同一战斗成为通用最优解；具体战斗成长规则留到成品设计。

**与升阶、装备和 PvE 衔接。** 一次升阶提供机制节点，装备提供打法与有限槽位选择；它们可有完成态，永久属性不因此归零或停止成长。并非每种阵容都要依赖永久成长者：即时技能配合、临时战斗强化等路线应有通关空间，但也承担自己的取得与投入。关卡按公开的敌人职责和阶段预算制造不同难题，允许成功成长带来真实碾压回报，不根据玩家面板自动追涨；不能靠专门惩罚强主核的强制免伤或随机封印强迫多核。

**最小比较证据。** 在相同供给成本、进程机会、装备条件与固定 PvE 遭遇下，比较早拿成长者／晚拿／没拿，以及集中主核／提前分投／主核加功能新人；同时检查自然取得和多种可达路线，不能只做满配终局实验室。记录每次永久增长及来源、战力兑现、阵亡与伤害／控制组成、换入新人的即时贡献和回本窗口。观察成长位何时值得保留或换下；若在所有阶段都优于战斗位，或没早拿成长组件就普遍无解，需重做供给与产出。第一批建议只做一条定向成长、一条多人共享成长及一条不依赖永久成长引擎的对照阵容，先验证三者的不同节奏；不是新增羁绊数量或已采用具体名单。

### 历史复核：持续属性成长与培养硬顶

用户指出属性培养参考酒馆战棋、王者万象棋，认为与刚确认的上限相悖；其他维度基本可接受。主 Agent 补查暴雪历史补丁和万象棋项目组访谈，Astra（high）独立复核。两者并非完全同构：酒馆存在反复触发的属性增长；万象棋访谈描述高等级上限、机制节点与节点后属性收益递减。参考事实见 [证据](evidence.md#持续属性成长与培养上限2026-10-06)，不将原作的等级或递减直接并入本项目。

冲突成立，但限于持续成长的主要回报：硬顶较早触及时，成长组合从持续强化引擎变为加速培养完成的工具；硬顶很难触及时，又不能承担引导后续投入转向副核的作用。更换“经验／训练”名称或按效果来源豁免，都不能同时保留两种目标。

| 可讨论方向 | 保留的体验 | 必须接受的取舍 |
|---|---|---|
| 保留普通永久属性统一硬顶 | 主核有明确完成态，成长单位帮助核心成熟、再培养其他成员 | 持续叠属性不再是始终有效的主要回报；满额后的产出对象和成长单位作用必须设计，不能假定自动无损溢出。 |
| 保留成长组合持续产出属性 | 老伙伴可继续强化，获得提高产出效率的成员仍有期待 | 重新讨论 D08 的统一数值完成态；副核靠职责互补、覆盖面及投入回报争取资源，不能再保证主核封顶后必然转投。 |

Agent 当前更倾向第二种，前提是用户确实要把单位之间持续产生和放大属性的配合作为主要乐趣。一次升阶、装备槽位及成品仍可有明确完成边界，但这属于调整上限范围，不能声称保留了原来的所有永久属性硬顶。有限征程、有效触发机会、产出速度和成长组件占位成本可以用于约束，单凭“回合有限”不能证明平衡；自反馈、复制和乘算仍须验证。PvE 下还需验证强成长能否保留关卡决策空间，不以敌人自动匹配玩家属性抹平培养收益。

本轮只重开取舍，未确定递减、阶段锁、具体上限、成长公式或撤销 D08；也不自动恢复等级与同名合并。下方上一轮建议保留为讨论过程，其中“所有来源共用硬顶”正在复核。

### 上一轮三种培养职责建议

用户在确认 D08 后继续询问培养应覆盖装备、升阶、升级还是属性。本轮主 Agent 核对 D07／D08、M01-D02、D65 与现行装备转移边界，由 Astra（high）独立审视职责重叠；没有新增用户决定或实现。属性属于结果，升级／升阶属于进程表达或取得方式，装备属于可重分配的配置载体，不把四者直接视为四条必须叠加的养成线。

Agent 建议以三种主要投入组织：

| 维度 | 玩家获得的价值 | 边界与待定项 |
|---|---|---|
| 本体永久数值培养 | 让长期伙伴保留逐次投入，提供主核养成与副核培养取舍 | 遵循 D08 明确上限；先覆盖少量直观属性，攻击／法强／生命等具体范围待选，不把所有战斗参数都做成通用训练项。各属性独立封顶或共用培养额度仍未定。 |
| 一次升阶 | 强化原有打法，形成少数清楚的成熟节点，并衔接已有高阶发现结构 | 不强制每人新增技能／被动；有分量的关键参数加强也可成立。当前收益留白仍按 D65，未设计清楚不填充。升阶完成与数值满额分开表达，不增加等级或新前置锁。 |
| 装备搭配 | 调整打法、补短板、放大能力，并通过重分配让新人及时有用 | 保留战前可转移方向，具体成品重做；槽位与成品强度提供边界。装备自身可移除的属性不占常规培养额度，装备触发的同类永久培养仍计入 D08，不能按来源名称豁免。 |

等级可以重新比较，但本轮不建议直接恢复独立经验／等级／升级收益。若等级仅负责整理数值进度，可作为第一项的替代表达；若所有不同培养触发最终只产相同经验，需要评估是否削弱单位成长配合。只有它能清楚改善分配、反馈或晚入队培养时才值得采用；用户提问“升级”不构成撤回 D07。技能单独升级、专精／天赋等也不能仅为增加栏目另开普遍投入线；有实质作用的选择可以在已有升阶设计空间内讨论，不自动全员加树。

遗物与羁绊继续承担队伍构筑；它们能影响单个英雄，但不因此给每人再加独立等级。各来源的同类永久培养共用上限口径，临时光环与跨战保留要区分。成长型单位依然可提供培养机会，具体产出／对象／有效结算点需设计；主核满额后不能默认反复浪费产出，也不能自动无损转移。

需要警惕：如果装备承担几乎全部成长，拆装备就可整体替换老英雄，本体积累失去分量；如果所有本体投入都只是同样比例加属性，升阶与升级的区别可能仅剩名称；如果副核需要三轴全满才有用途，则后期招募期待无法兑现。三种投入不应互相做全套前置，某个功能英雄不必全部深养。

下一步先讨论这三项是否覆盖所需体验，再确定本体可培养的属性、成长由谁提供与如何分配，以及上限计量；不预定额外材料、共同点数、具体强度占比或当前可获得的成长数值。当前征程的 ProductionModes、装备、遗物和升阶收益为空，旧 4% 只是保留基线，不能当本轮已自然可得的培养方案。

### 2026-10-06：培养完成态与发展副核心（当前讨论）

用户认可核心延续、晚入队价值和培养取舍，追问单个单位的培养上限是否能鼓励培养副核心；特殊羁绊单养大核心明确排除于本轮通用方案。认可范围见 [D63](../../../04-content-validation/decisions.md#23-d63阵容配合与单位纵向投入共同构成战力)，上限的具体形式尚未决定。

Agent 判断：明确的常规永久培养上限可以产生完成感、限制资源持续集中、缩小晚入队追赶所需差距，因此值得作为通用方案优先比较。硬上限与收益递减作用不同：前者在达到额度后确定地释放后续培养，后者保留集中投入选择，但在技能／装备乘算下集中培养仍可能一直最优。当前更倾向清楚的常规培养完成态，不同时叠加复杂递减、阶段锁或恢复经验等级。

上限对象建议先讨论常规永久培养的累计额度，不把最终伤害、生命或队友帮助后的战斗表现统一钳死；单位能力、法术或其他来源提供同类永久培养时需要共用口径，不能通过换来源绕过。装备／羁绊及临时效果与常规培养分别定义，再共同检查最终战力。既有单位持续提供成长的方向仍须核对：满额后的收益不能默认浪费或自动无损转给其他人，具体目标选择与产出用途待设计，不由此新增外部训练材料。

上限不能单独保证副核心有价值。需要把首核完成时间、晚期英雄取得与启动所需机会放在同一段征程验证：封顶过早会让老伙伴失去成长感，过晚则无法影响分配；尚未满额时也应存在补弱项的合理选择，满额后仍允许培养前排／辅助，不规定必须几个输出核心。一次机制升阶并不等同全部永久数值培养已经封顶；历史方案继续保留，本轮没有规则合并、代码变更或数值决定。

2026-09-27设计执行：[候选预算与推演](../../../04-content-validation/artifacts/growth-route/README.md)把当前15层转为14次节点收益机会，比较3%／4%／6%原始基础项固定增量及多源／复利；建议先以4%单项起测，不做累计硬封顶或逐次另付材料。一次材料升阶用成本4、最早节点4/8/12作供给标尺，未定正式掉落／成本。实际候选抽样暴露生产源不稳定、高阶三选一池不足、晚来核心剩余机会短等问题，均保留限制；这不是已采纳参数或战斗平衡结论，R02-D07保持。

### 最新澄清：单位逐次提供成长，不依赖外部材料限额

用户希望成长由单位承担，只要单位满足存在／参与条件，每次备战都能继续提供成长，因此质疑仅靠有限外部资源限制的方案。此处明确的是持续单位产出方向，不推定全员必须自成长、后备也生效、每次打开整备UI都发收益或任何原作具名技能规则。升阶材料与这类逐次成长不是同一条取得途径。

Agent修正：成长范围可以通过每个有效阶段的产出速度与叠加关系控制，不必要求玩家为每次成长额外支付材料。推荐先比较固定增量／按基础值给定量，与按成长后的当前值乘算的不同曲线；在有限旅程中，前者可以保持每次正收益，同时让可达差距可预期。成长速率可随内容强弱与培养改变，但重复触发、来源数量、转化、复制及相互加速须共同进入总预算；有限旅程本身不是充分保障。

仅作算例：基础100、20次有效机会，每次+5则最终200。它没有逐角色经验等级、材料消耗或达到总硬顶后停止，但主流程内仍有可估计的增长范围。数字不是本项目参数。常规产出与当前攻击／生命等已增长值脱钩可避免自动复利；这不禁止未来明确设计的复利内容，其强度需另算。机会按实际进程计，不按往返界面次数计，仍为待设计规则建议。

若未来要求无限有效次数、每次至少固定正增量、羁绊回报有限，且任意时间差距下羁绊都不能被成长压过，则这些条件不能同时满足；届时须采用递减／有效收益边界或接受长程成长主导。本轮优先讨论有限主流程，不凭无限外推否定持续成长，也不自动采用累计硬上限、取消重复收益或新法术规则。后文早先有限材料等只是可选手段，不作为唯一限制方法。

2026-09-27用户明确当前核心冲突：需要有分量的数值养成，使后期临时买入、未经培养的一队单位不能仅凭高羁绊直接获得成熟战力；云顶常规升星有可预期的完成态，而如果本项目永久成长普遍无上限，不同队伍的积累差距可能压过羁绊。此前非战斗内容与法术的讨论不能代替这个强度问题。用户尚未选择具体上限制度。

Agent分析应进一步区分属性绝对值与可达到的培养差距：如果所有单位按同一比例成长，羁绊的相对收益并不必然消失；若不同阵容／取得时点可形成无约束的成长比值，而羁绊收益只处于有限档位，则体系组织的地位难以稳定。羁绊中的控制与特殊机制也不能被简化成固定倍率，倍率只用于解释，不作为实际战斗公式。

建议常规数值培养建立有分量且可预期的有效上限，再在该范围内标定羁绊和技能配合；不恢复等级或同名合并，不把一次机制升阶自动等同于全部数值养成。可通过单位可投入额度、成长资源／有效机会预算或递减收益构成边界，具体结构未定。有限旅程不自动保证边界：可重复产出和收益再投资仍可能拉开极大差距，需明确评估。共享物品及培养基础不要求全员具有原生成长技能。

希望检验三种关系：未经培养的完整羁绊不足以跳过成长；正常充分培养后，合理配合能取得重要优势；极端集中养成不能以过低代价普遍绕过组队要求。特殊成长可进一步讨论，但不能用“特殊”之名让常规强度边界失效。本轮仅明确问题和Agent建议，不定成长次数、属性硬上限、倍率或供给，不授权实现。

[D05](decisions.md)暂缓等级。用户提出同名合并，尤其关注酒馆战棋的高阶发现。既有UR04证据支持拆分“重复单位作为投入”“本体升级”“高阶发现机会”；本轮未核验最新补丁，经典酒馆结构按酒馆等级而非被合并随从自身等级决定高阶发现，不能迁移成低阶单位必然只能碰相邻低阶。

Agent认为高阶发现比新增一条数值成长更值得检验：对子成为可保留机会，第三份在当前战力、招募额度、备用空间和未来候选之间形成取舍，发现可引出原阵容没有的桥接或核心。但重复单位会占有限节点招募额度，实际供给若不足会成为死对子；若过于充足则变成廉价重复单位刷高阶，须共同评估。

与材料制度存在三种不同关系：一是同名合并替代材料升阶，决策清楚但撤回既有材料规划且受抽取影响大；二是同名重复作为同一次升阶的替代投入，保留材料兜底但需明确不同投入下的发现奖励；三是合并只给发现、材料另管升阶，职责分开却增加独立计数与经济回路。当前倾向第二种作为讨论候选，不新增第二条星级强度，也不要求同名与材料双重必付。若只有同名路线给发现，可能使材料升阶明显吃亏；若两条都给，则材料也变成高阶招募来源，必须纳入预算。两者未定，不因倾向记录即采用。

发现阶位建议关联旅程当前招募阶段并有最高池上限，保持不用恢复人口升级的边界。候选不保证本体系、也不完全忽略兼容性；候选规模、偏向、是否允许保存奖励和越级幅度均待定。三份仅为原作参考，不预设本项目可支持三份。常规合并不另给永久羁绊点，也不将发现描述为必定成型。

若后续授权验证，应先模拟真实招募供给与成本，统计对子完成率、未完成沉没成本、首次发现时点、阵容转向率以及低阶反复合并的收益，不能仅摆好合成阵容做战斗胜率测试。本轮只讨论，未运行模拟。

### 一次升阶与等级接口（2026-09-27续）

[D04](decisions.md)已将常规内容收敛为一次机制升阶，等级主要提供数值。下文早先多节点措辞仅保留提案背景，不再作为当前常规设计目标。等级除数值外可以作为共享规则读取的数据，不需要逐英雄逐等级制作内容。以下是项目候选，非原作事实或已采用规则：

| 接口 | 示意与选择价值 | 约束与代价 |
| --- | --- | --- |
| 读取绝对等级 | 特定装备的护盾容量等随佩戴者等级成长，改变培养投资收益 | 本质仍属数值；避免属性与等级重复放大，不全部装备照搬 |
| 读取相对等级／排名 | 特定辅助优先保护最高等级队友，玩家能通过投入改变保护对象 | 同级需稳定且可预览的选择规则；也可能强化单核，不天然增加深度 |

| 读取队伍等级分布 | 特定遗物奖励两位相近等级的核心或一定培养广度 | 提供集中／分散投资差异，不设全队最低等级硬门槛来强迫培养羁绊位 |

后续验证建议保持人口、总资源预算、敌人和种子可比，分别检查等级成长、机制升阶、队友配合的收益；同时检查单核集中、双核分配、晚入队替换以及同一核心搭配不同队友。验收关注同预算下是否存在不同有效搭配、机制何时兑现、换人损失能否在剩余旅程回本，不仅看更高等级胜率是否提高。以上仍为方案，未授权实现或开始新一轮模拟。

### 等级与升阶的职责候选

用户提出在升阶之外加入等级，到一定等级后结合材料升阶，询问是否采用；当前是讨论提议，未记为采用或实现授权。既有D01～D03、R01机制升阶和R03回退方向保持。

Agent建议可以加入，前提是职责分清：招募费用／稀有度决定取得与基础身份，等级提供适度连续属性成长及升阶资格，品阶兑现机制加强／专精。等级本身不增加人口占用或羁绊贡献，不把已有T1～T4再当作等级。升级与升阶形成“持续改善—机制节点”的节奏，不能主要依赖高等级数值压过阵容配合。

经验来源至少有三种不同选择：个人参战积累（有养成经历但新人追赶困难）、共享经验由玩家分配（方便核心投入和晚入队角色，但增加分配操作）、全队同步等级（管理轻，但等级主要成为进度门槛）。当前倾向共享经验，局内战后／事件取得、战外批量分配，不按击杀／输出分经验；个人参战方案必须另配追赶，不能默认为已确认。等级门槛之上的升阶仍用通用／匹配类别材料替代或混合支付，不把经验作为理由改成两种材料必须同时齐全。

等级只作为升阶资格，暂不推荐追加“缺升阶材料便停止升级”的等级上限锁；这种锁更强调突破，但会增加经验与材料双重卡点。如引入，应明确经验储存和后续追赶。阈值、总等级、属性曲线和供给量均未定，不把Lv4／Lv8之类说明数字当成参数。R03需要另明确经验与升阶材料各自如何随整体回退处理；不据旧材料返还规则自动推出经验可全退或自由换核。

下一步先确定经验归属与分配，再标定一局可到达的等级／机制节点、取得时点及少数核心投入与功能位最低投入。I24／I27／I35承接培养、转型、供给和成型窗口；本轮未修改运行内容。

### Q01-P01：初期采用英雄专属的预设升阶路线

## Q01-P02：复用成长内容与选择规则，控制逐英雄制作成本

日期：2026-09-08。性质：回应 R02-D01 的 Agent 方案建议，未获单独采用。用户关注系统实现与业务配置成本，不要求本轮实现；仅只读核查相关系统和类型。

### SY01：把强化内容与如何获得分开

建议每项专属加强作为有稳定身份的内容条目，说明适用英雄、前置节点、互斥／累积关系、提供的机制和说明。固定路线、主动／被动轨道、分支与随机候选引用同一类条目，不各自复制一套效果。

| 结构 | 主要变化放在哪里 |
| --- | --- |
| UP01 固定路线 | 指定下一项，满足条件后直接取得 |
| UP02 分别投入 | 条目归入主动／被动等轨道，各自记录前置和投入 |
| UP03 固定专精 | 明确候选集合，选择一项并排除互斥项 |
| UP04 混合路径 | 多次机会记录路径投入，以前置和深层节点要求控制混合 |
| UP05 随机候选 | 从合格集合生成候选，再使用共同选择与取得流程 |

这些不是五套战斗系统。共用可以涵盖资格、支付、取得、保存与展示；每种模式仍有自身资格及失败场景需要实现。轨道、互斥组与候选规则应只增加实际所需部分，不先建立任意图脚本编辑器。

### SY02：复用效果与机制表达，不为每位英雄复制处理器

同一项“治疗后向目标附加护盾”无论固定获得、专精选择还是随机候选选中，其战斗规则应相同。采用事件／条件／目标／数值或计数／结果的共享组合表达，例如来源限定、目标查询、施加状态、造成伤害、治疗、护盾和次数间隔；每项效果仍保留自己的来源与清理语义，不混并所有系统生命周期。

独特玩法来自组合和关系，不要求每名英雄专有一段运行代码。确实缺少通用能力时，新增命名清楚、边界明确、可复用的能力后供内容引用，而不是按英雄 id 分支。也不强迫所有新想法都用现有原语勉强拼出失真的效果。

注意：此前“溢出治疗转盾”依赖溢出量，现有 EventEffectiveValue 是实际生效量，不能偷换为溢出治疗。需要核实／补充对应事件数据才能支持该语义；这是新增通用能力的例子，不是当前已完成效果。

### SY03：控制配置维护成本，不能只是把代码搬进巨型配置表

基础英雄只维护一份，各阶引用独立加强，不为每阶复制完整英雄、主被动、装备与表现定义。复用的是可解释的机制模板／资源组合，英雄专属适用范围仍独立声明；不同内容的可变状态必须按实例归属。

避免让内容作者反复填写底层字段；常见机制可提供少量有意义的参数、继承默认值与引用预览，允许特殊内容组合共享组件。初期可先沿用现有 Resource／编译流程和小型模板，不默认新增完整可视化编辑器。选择互斥、前置无法到达、重复授予等问题应尽量在发布前给出具体内容位置的诊断；数值与描述同步、机制变化的前后对比可逐步辅助作者，不能承诺说明自动生成即可代替人工核对。

### SY04：机制新增与接入新增分别记成本

只读 [内容契约](../../../../system-design/content-composition-foundation.md)、[系统架构](../../../../system-design/tower-autobattler-architecture.md)、[AbilityDefinition](../../../../src/Abilities/Authoring/AbilityDefinition.cs)、[AbilityLoadoutDefinition](../../../../src/Abilities/Authoring/AbilityLoadoutDefinition.cs)、[EffectStepSpec](../../../../src/Effects/Authoring/EffectStepSpec.cs)、[RunOfferDefinition](../../../../src/Project/RunOfferDefinition.cs)、[RunOperationDefinition](../../../../src/Project/RunOperationDefinition.cs)后可区分：

- **已有可复用基础**：类型化触发、目标查询、条件／公式、状态和效果授予及撤销、编译验证、来源隔离；RunOffer 有固定／池候选、条件成本收益和保存事务的既有模式。
- **仍需设计和接入的成长公共层**：升阶条目／路径进度、选项互斥、英雄实例取得结果、升阶资源支付、持久化与战前有效能力组装。已读 RunOperationKind 没有专属升阶操作；普通 Offer 也不意味着当前已支持所有路径规则。
- **按内容需要补的能力**：技能机制差量或受约束的版本替换、特定事件读数、独特范围／计数等。已有 ReplaceGrants 不等于可随意热改任何技能字段；共享静态定义不能写入局内成长。

具体使用差量修改、受控版本还是授予组合应按代表性内容比较，不在本轮定一种万能方案。不能据资源类存在就声称机制升阶已实现，未运行或验证。

### SY05：用少量代表内容检查成本，不先要求支持全部形式

后续获授权实施前，可先用固定授予、互斥选择、混合路径和随机候选引用同一项加强，检查获得与效果是否真正分离；再用需要新读数的机制检查扩展是否能保持通用。此为成本审查方法，不是已制作样例或自动验收。

重点观察新增一个英雄为什么需要改运行代码、同一机制是否在多处重复配置、改基础技能是否要同步修改多个版本，以及作者能否看清前置和实际结果。独特机制需要新增实现本身不算失败；应区分真实的新能力与本可复用却重复编写的逻辑。无需先定“支持所有结构”或虚构配置耗时数字。组合越多仍有内容设计、表现、教学及验证成本，系统复用只能减少重复劳动，不能消除这些工作。

### 用户回应与恢复

2026-09-08 用户强调尽量复用，不能生搬硬套导致设计没有特色，已补入 R02-D01。SY01–SY05 不是压缩英雄差异的模板要求，也未整体获采用。先明确期望的玩法，再判断哪些部分有真实共性；确需新机制时可扩展，不要求它先被多个英雄使用。专用能力应有清楚职责及生命周期，但不必为了泛化增加无用配置层。

## R02-Q02：英雄升阶的支付资源与适用范围

### Q02-P01：以可自由分配的英雄培养资源为基础

## R02-Q03：通用资源与类别材料怎样共同参与升阶

日期：2026-09-08。状态：后续 [R02-D03](decisions.md)已采用 PY01 替代／混合支付。以下保留初提案及取舍，供给补偿方式和具体数值未随支付关系一并确定。D02 的 UR01＋UR03 保持；原作依据与项目推演分开。

### Q03-P01：优先考虑替代／混合支付，让类别路线提高培养效率

Agent 推荐 PY01：对匹配类别的英雄，两类材料可以支付同一升阶投入，并允许混合补足；未用通用资源仍可保留给其他英雄。同等路线投入下，倾向让类别资源以更充足的供给或更高的适用培养价值补偿用途限制，使路线选择产生“灵活性与目标培养效率”的取舍。此供给关系是推荐的成立条件，不是已定掉落量或兑换比例。

理由：保留用户期望的前期探索、逐渐定型与后期替换空间，同时让玩家为当前体系主动选择有匹配材料的路线。只走通用来源可能培养效率较低，走类别路线则承诺其适用方向；不需要把某次材料缺失直接变成所有相关英雄的升阶禁令。

如果用户希望路线决定关键专属加强能否获得，PY03 的阶段门槛比 PY01 更符合该目标；若每次培养都应受类别路线约束，则 PY02 更直接。这是不同体验，不以“有门槛就是坏设计”否定后两者，也不把原装备“未升级仍可推进”扩大成英雄材料无门槛要求。

PY04／PY05 提供不同资源用途，但会改变成长内容或选择控制结构，初期不建议仅为了安置类别材料新增这些层次。它们仍保留可用比较，不推定用户否定。D01 的各英雄特色优先保持。
