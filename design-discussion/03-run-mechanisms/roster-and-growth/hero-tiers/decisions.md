# R01 英雄分级：讨论决定

本文件仅记录讨论结果，不是现行玩法或实现权威。进程见 [总览](../../../roadmap.md)，方案与回应见 [讨论记录](proposals.md)。

## R01-D01：允许不培养的羁绊单位，品阶以机制加强为主

日期：2026-09-08。状态：**已确认但未合并**。适用范围：用户费用＋品阶想法 Q01-P03 的本轮明确边界，协作 R02。用户回应：“01不太认可，单位多的话，很难避免为了凑羁绊放几个凑数单位但不养成。02十分认可要做机制升阶而少做数值。其他的点都是一些平衡性建议，没什么好反驳的”。

### 当前结论

- **允许为了凑羁绊上场、但不投入培养的单位。** 大阵容中部分单位主要承担羁绊贡献是可接受的选择，不要求每名出场英雄都必须获得独立培养或突出的战斗表现。HF01 中将避免羁绊挂件作为普遍设计目标的建议不采用。
- **英雄品阶以机制升阶为主，少做纯数值加强。** 专属加强应主要带来玩法与联动上的变化，延续用户希望低费英雄有成为核心可能的方向；不等于禁止配套数值变化，也不要求所有低费英雄在每种阵容中都是核心。
- **HF03–HF06 作为平衡与后续设计参考。** 用户将其归为平衡建议，本次不视为逐项采用可预期固定强化、全员基础战力保障、某种回收政策或资源规则；不重复将一般平衡提醒提交为玩法表决。

### 方案背景、理由与未定事项

用户此前提出英雄的固有费用与资源升品阶两个维度，专属加强类比云顶英雄强化。本条按该方案背景记录本次明确的两项边界，不自动确认所有提案细节或研究样例。

低费英雄可以凭羁绊贡献留队，也可以成为玩家选择投入专属成长的对象；无须为证明低费有价值而强迫每个羁绊位都承担独立核心职责。机制升阶的重点是丰富玩法，不只是延长数值曲线。

费用档数、品阶数量、强化次数与内容、固定预设还是选择分支、材料来源／通用性、窗口、成长回收与招募价格细节仍未定。HF02 的溢出治疗转盾、持续伤害结算只是 Agent 示意，未选为正式技能；用户的云顶类比不自动采用原作强化随机抽取或刷新机制。

M01 固定主动＋被动、无本体配置继续作为讨论基线；预设机制加强如何作用于原能力由 R02 明确，若以后选择可配置本体分支则另明确范围。不因机制升阶这一方向自行改写 M01 或现行权威。

### 后续归属与变更记录

R01 保留费用与品阶的区分，R02 承接专属机制成长结构，R03 承接回收；I24 跟踪跨题依赖。后续无需再论证所有凑羁绊单位都应被培养，或以未培养挂件的存在判定方案失败。
