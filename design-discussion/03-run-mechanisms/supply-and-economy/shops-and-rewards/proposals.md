# R08 商店与奖励：方案讨论

本文件保存机制比较与推荐历史，不是用户决定或现行权威。来源、全库检索与限制见 [已有证据](evidence.md)，后续确认范围见 [讨论决定](decisions.md)，进程见 [总览](../../../roadmap.md)。

## R08-Q01：一场战斗结束，玩家可以拿哪些奖励，哪些必须取舍

本轮子问题：**基础资源是否独立获得；当英雄、装备、遗物等机会同场出现时，它们怎样共享或分别使用选择名额；不想要时有什么出口。** 具体价格、数量、频率、Boss 奖励档次和商店运作另论。以下数目和物品均为说明，不是选定配置。

R05 已定部分战后可以获得英雄，R07 已定普通唯一；不重新决定是否能招募。G03 的多种构筑信号、早期容错与适配推荐／其他方向保持。R08 比较的是供给机会的组织，不要求英雄／装备／遗物每场都出现。

### RW01：基础收益直接获得，构筑选择另外处理

例如打赢先获得这场规定的金币／基础材料，再处理这场提供的装备选择；拿装备不会扣掉本来的金币，跳过装备也不丢失基础收益。哪种材料属于基础收益，须与 R09 一起定，不预定所有材料每场必掉。

Loot Loop 的已有研究记录敌人／Boss 掉 Gold 和 gems、之后投入成长，提供资源掉落的相邻参照；**“资源之外再给构筑选项”的双层组织是本项目方案**，不是它的装备规则。

好处是每场有稳定进展，玩家不会为了维持最低成长一直放弃新体系组件；代价是基础收益若包办了全部成长需求，后面的选择会变轻。它能与下面多数机制组合，不是把所有奖励兑换成货币。

### RW02：按奖励类别分别给选择机会，组内取舍

例如某次结算提供一个英雄奖励组和一个装备奖励组：英雄组中选一名，装备组中选一件，两个组彼此不抢名额；若另一场只提供装备组，就只选装备。类别出现在哪些节点由节奏决定，不需要每战逐类点一遍。

Hadean Tactics 2.0 遗物二选一、Auto Brawl Chess 历史 Dungeon 战后神器三选一，是明确的**类别内选择**参照；**同一场可以有多个独立组，是本项目组织方式**，现有摘要没有闭合原作全部领取顺序。

好处是招募不会天然挤掉装备或遗物成长，便于分别控制队伍扩张与养成；代价是组太多会拉长战后操作，若每次各类都给也会让构筑趋同。与 RW01 可以构成普通奖励骨架。

### RW03：不同类别放进同一组，共享选择名额

例如同一组显示“一名新英雄／一件装备／一个遗物”，本组只能拿一个；选择补人数就放弃了本次关键装备或遗物。与 RW02 的差别在实际领取权利，不是画面是否分栏。

Milky Way TD 有奖励条满后三选一、混合新单位／单位强化／技能强化的玩家记录；**证据较弱且不是战后触发**。Magicbook 的混合面板是商店付费供给，也不能当免费互斥奖励证明。这里的战后混合组是项目迁移。

好处是玩家能直接决定“添新成员还是强化已有队伍”，每次选择的方向差异大；代价是在前期缺人数、缺装备时，某类刚需可能长期压过其他选项。若总是如此，拿潜在体系英雄的机会成本会很重；适合有明确取舍目的的奖励，不必成为每战规则。

### RW04：以整包内容为一个选项，选包时一起取得配套

例如“新英雄＋少量可用于他的培养材料”，与“装备＋另一份基础资源”作为两个完整选项。选中一个包便拿包内内容，不能从各包拆出最好的部分随意拼接；具体是否能拆包可作为另行内容例外，不是普通默认。

ShapeHero Factory 1.0 选择 Hero Upgrade 附送相应 Statue，支持“取得成长同时给配套手段”的相邻参照。**英雄材料包、多个包之间的竞争是项目方案**，不导入工厂、战斗复制或同名合成。

好处是新方向可以更快投入使用，减少选中英雄却完全养不起的落差；代价是容易把路线配得过于完整，变成挑现成答案，还要检查各包总价值与赠送投入回收。它改变单个选项的内容形态，可以放在 RW02 或 RW03 中，不要求新增一套培养系统。

### RW05：给当次领取预算，自由组合拿一件大件或几件小件

例如该次战利品给 3 点领取额度，大件花 3 点，小件花 1 点：可以拿一个大件，也可以拿三个小件。这是该奖励机会的使用预算，示例不是新增已确认的局内货币，也不是用普通金币再开一家商店。

**现有语料没有找到同构战后规则，属项目对照。** 它与 RW03 的“所有选项同等占一名额”不同，也与 RW04 的“作者打包”不同：玩家自己组配。

好处是能表达集中养一个核心和补多个短板的取舍；代价是每种奖励都需估价，比较与点击明显增加，容易把每战结算做成一次采购。初期普通奖励不优先；如后续有特殊战利品节点可再使用。剩余额度能否转资源也未定。

### RW06：先选奖励方向，再生成该方向的具体候选

例如先在“装备／遗物”中选择装备，然后才看到几件具体装备并选一件。与 RW03 先看见具体英雄／装备／遗物再比较不同，玩家先承诺缺什么类型，再承担这一类型里出现什么的随机性。

Vivid Knight 的 Maze IX Monster Spot 有选择配件部位的记录，能提供定向参照；**现有摘要不支持先选类别再揭示内容的精确时序，这个完整流程是项目方案**。若所有内容一开始都可见，只是换个分类页浏览，就不是本条新机制。

好处是玩家可以主动补缺口，避免不想增加英雄时奖励组仍被英雄占满；代价是多一层选择，选方向后仍可能没有适合的物品，也减少跨类别偶遇惊喜。不能从它推定玩家常规自选具体英雄、改变 R06 合法池或无限刷新。

### RW07：允许跳过不合适的选择，本次不额外补偿

玩家可以不拿这一组的候选并继续；若有 RW01 基础收益或其他独立组，它们不因此消失。这是放弃未取得内容，不需要先拿一个不合适遗物再付费移除。

Slay the Spire 2.x 的随机卡牌奖励可以选一张或跳过；Backpack Hero 个体报告因 Boss 遗物全部不适配而跳过。**研究支持拒领权；RW07 的“不额外补偿”是项目对照定义，不能用摘要没有写补偿证明原作所有情形都没有。**

好处是最简单，避免强迫破坏阵容或接受负面遗物；代价是连续跳过会让打赢后的构筑成长空转。Slay 的牌库稀释不直接套到本项目：英雄有有限后备，装备可入库存，遗物默认启用，拒领理由须按载体理解。

### RW08：允许放弃这一组构筑奖励，换一份通用资源

玩家看到候选后明确放弃本次构筑选择，拿一份替代资源。基础收益之外另有补偿；不能先取得内容再来领一次，也不自动把未选中的每个候选逐件折现。

Hadean Tactics 1.1 的 Hero Upgrade／Banner 可跳过换 50 Gold；Storybook Brawl 历史升级产生的 Treasure 可跳过换 Gold。前者只限已证实机会，后者触发不是胜利；本项目不照搬数值、遗物槽和合成前提。

好处是成型、满员或候选不适合时仍能积累后续购买／培养能力；代价是补偿太高会让“每次拿资源、商店再定向找”成为固定答案，吞掉随机奖励的构筑价值。究竟补金币还是培养资源、哪些组有补偿，留 R09 与供给设计；不把所有奖励无条件折成同一价格。

## 组合关系与 R08-Q01-P01：原 Agent 建议，用户采用范围见 D01

这些不是八选一。RW01 是基础收益；RW02／RW03／RW05 决定某组怎样分配领取权利；RW04 改变一个选项可以装什么；RW06 改变决定方向与看见具体物品的先后；RW07／RW08 处理放弃某组后的结果。同一个组在普通情况下不能既说“跳过没有额外收益”又默认发 RW08 补偿，但不同机会可分别采用。

**建议普通战后以 RW01＋RW02 为骨架，并为适用构筑奖励保留 RW08 的小额替代价值。** 基础收益稳定推进；该场出现什么构筑类别由进程安排，出现的独立组各自作选择。普通英雄奖励不必天然与装备／遗物争唯一名额，保持 G03 为潜在体系拿人的空间。允许拒领，不把负面内容强加给玩家；补偿不是要把每件未选物折现。

RW03 的跨类别竞争、RW04 的配套包和 RW06 的定向选择可作为不同奖励／事件设计，兼容保留，不要求初期全部制作。RW05 的逐件预算比较成本较高，暂不优先普通结算。这里的初期排序是 Agent 建议，不是用户认可所有机制或排除其后续使用。

采用上述骨架也不意味着每战同时发英雄、装备、遗物、各种材料；具体供给次数／数量与 R05／R09／R10 联动。拒领补偿与候选不足补救是两件事：正常可选但不想要，可以讨论补偿；违反唯一／合法池的候选首先不应成为可取得物，不能靠事后赔钱修补。本轮不承诺付费刷新免费奖励。

以上为提案时的推荐，确认范围以后续用户回应为准。I30 保存奖励名额、基础收益与拒领替代价值的跨题依赖，不逐项追问所有数字或把特殊奖励内容变成全局规则单选。

## 用户回应：采用 RW01＋RW02

2026-09-08 用户明确“同意 1+2”，记录 [R08-D01](decisions.md)：普通战后基础收益独立获得，该场提供的构筑类别分别选择。原推荐中的 RW08 小额拒领补偿没有一并确认，RW07／RW08 的拒领结果仍待实际供给／经济设计；不推成默认必须领取或取消已有跳过入口。RW03–RW06 保留比较与候选，不自动采用、初期制作或永久排除。Q01 普通结构收束，奖励频率／数量留节奏与经济，后续核对商店真正未决的制度。

## R08-Q02：同一家商店买完一件后，能不能继续买，怎样出现新货

本轮具体场景：店里同时有想要的装备 A、遗物 B、材料 C。买下 A 后，B 和 C 还能否继续购买；A 的空位要不要补货；继续花钱时，受金币、货物还是另外的购买次数限制。

范围是同一次访问的非英雄商品／服务。R05 英雄最多招募 x 人、R07 普通唯一与刷新分工保持；不重开战后 RW01＋RW02、不默认免费奖励也能刷、不回访旧店。下面次数与物品仅为示意，具体经济另定。完整证据与限制见 [Q02 检索](evidence.md)。

### SH01：固定一批有限商品，买完后空着，本次不刷新

进入时生成本次货单，玩家可以连续购买想要且买得起的商品；每份实际库存卖出后消耗，其他未售商品保留。此店不提供普通换货／补货，剩下没想要的便离开。每一份只出售一次不等于本局永远不能再获得同款装备。

Tales & Tactics 2.0 社区答复有“每店两件卸装消耗品”的有限库存参照；**它只证明该商品的数量，完整固定商店是项目对照，不重新引入卸装收费。**

好处是本次访问容易看清并结束，玩家只比较当前购买与留钱给后续机会；代价是货不适合时，带再多金币也无处补强。这与 SH02 主要区别是有没有主动换新货的入口，不是能否一次买多件。

### SH02：可以买多件，买后空位通过付费刷新换上新货

买下 A 后，B 和 C 仍可继续购买；A 的位置先空着。玩家可以继续买现货，也可以付费把本次随机货架换成新一批，再买新货。普通整批刷新会放弃未买旧候选；已买物品归玩家，不参与刷新。

Guildrun、Backpack Dungeon 有物品／遗物商店刷新的明确参照，Magicbook 有多类别付费换候选；**这些摘要没有闭合原作买后空位时点，本条完整过程是项目方案**。

好处是金币同时支持“买眼前东西”和“继续找更合适的东西”，允许同店连续补强；代价是可能反复搜索少数最强件，购物时间与费用都增加。具体刷新次数／价格尚未定，不能把本条理解为无穷库存或保证找到指定装备。

物品刷新可以借用 R07 已有的全刷思路，保留／定向排除／回看等不再重复作普通权限单选；软降权迁移到哪些物品与如何处理固定服务仍需明确，不由既有英雄决定自动覆盖所有货物。刷新也不会恢复已花的英雄名额或明确标注的商品限购额度。

### SH03：购买后自动补入一件新货

买下 A，其位置立即出现新的候选 D；玩家买到物品，同时获得下一件商品的信息，无须为了这个新候选单独按刷新。若作用于所有商品，便形成持续“买东西—看到下一件”的链条。 补货只是新商品上架，不是把新商品赠送给玩家，购买新商品仍须支付其费用。

Storybook Brawl 的 Crystal Ball 会让符合条件的定向法术补入新法术，并不消耗通常法术额度；**这是特定 Treasure 的条件效果，不是全店默认买一补一**。

好处是购物连贯，购买本身就能探索供给；代价是玩家可能为了看到下一件而买当前不需要的东西，便宜商品和购买触发效果会变得更有价值。适合保留为遗物／特殊商店规则；触发商品、补货类别、补货是否额外免费及限购豁免必须分别明确，不能因补货自动取消 R05 英雄名额。

### SH04：整次物品购物共用一个购买次数额度

例如这次非英雄商品一共只能买两件，装备／遗物／材料共同消耗额度；即使还有钱和未售商品，额度用完也不能再购买。刷新只改变可见货物，不恢复购买次数。数字只是示例。

**现有研究未找到完整同构的全店共用额度规则，这是项目对照。** R05 的英雄招募名额是已有特定类别规则，不能直接当全店限购的依据。

好处是能直接控制一次访问的补强量、阻止大量存款在一店全部变成战力；代价是小件会与关键件争珍贵购买次数，可能出现明明缺材料且有钱，却不愿浪费名额的情况。它能叠加 SH01 或 SH02，不是必须另开一种商店。

### SH05：只对特定类别或特定商品设限购

普通商品继续购买；某类稀缺物或某款特殊工具在本店只可买规定数量，用完不影响购买别类商品。与 SH04 的区别是，买一份受限工具不占普通装备或材料的购买机会。

Storybook Brawl 普通每轮只有一次 spell 权，仍能买角色，是明确的类别限制；Tales & Tactics 的每店两件特定消耗品是单品有限供给参照。原作有限库存如何与所有刷新交互未完整记录，**本项目限购在本次访问内不因换页／刷新恢复是方案定义**。

好处是只约束能显著改变节奏的物品，普通购物保持灵活；代价是玩家需要看懂哪些有限制，内容过多会形成零碎规则。英雄的 x 名额已经属于类似的既定分类边界，不要求重选；新限购只按具体物品／服务需要设计。

### SH06：有些常备商品或服务可在本店重复付费使用

例如店里的一项培养服务在使用后仍可用，玩家可以为另一名合法英雄再付一次费用；它不需要重新刷到同一服务。也可以对某种基础材料设计重复购买，但次数、库存、费用必须由该条目说明，不能默认无限。

Backpack Hero 的 Tote 在 patch 1161 实战里可以同店多次删牌，价格按 5／10／15……递增，每家店分别重置；**证据支持重复服务，不证明无限次数、当前定价或常用品无限库存**。本项目常备材料是进一步的内容对照。

好处是服务节点提供可靠用途，不必为每次操作重新碰运气；代价是金币可能过于直接地换成连续成长，需要由服务资格、费用或自身额度限制。可与随机装备货架共存，不要求全店都改成常备目录；培养回退仍遵守 R03 实际门槛，免费换装保持。

## R08-Q02-P01：原 Agent 建议，用户采用并补充限次要求

**普通物品商店倾向 SH02：允许在同次访问连续购买现货，买后留空，可付费刷新随机货架再继续找／买。** 普通物品不额外加 SH04 全店共用购买次数；控制一次访问的价值时先看实际货物、资源与刷新成本，具体次数和数值不在本轮锁定。英雄继续受 R05 的单次招募名额约束。

SH05 的特定商品／类别限购、SH06 的重复服务按各自内容需要兼容，不要求所有常用品都有库存上限或一律无限。SH03 的购买后补货优先作为遗物／特殊店的内容空间，不作为普通全店默认；SH01 保留固定货单型特殊商人的可能，不等于要求初期全部制作。不同物品的补货／限购机制不用重做一套全局选择题。

以上为提案时的推荐；商店是否混合英雄／物品、是否按类别分别刷新、固定服务是否出现在每家店，以及 R07 软降权细节对物品的适用范围仍需明确。后续用户确认与补充要求见下文，R08-D01 与 RW08 未确认状态保持。I31 跟踪实际库存、刷新、类别名额、持有唯一和服务门槛的衔接，当前未修改权威／实现。

## Q02 用户回应：采用 SH02，刷新必须有限，特殊资源可以进一步设门槛

2026-09-08 用户认为 SH02 合适，但明确刷新应限制次数，甚至可要求特殊资源，以免轻易刷齐构筑而降低可玩性。记录 [R08-D02](decisions.md)：普通同店连续购物、买后空位与主动刷新成立，刷新次数限制成为已定要求；特殊资源门槛保留可考虑方向，资源与金币的支付关系／来源尚未选定。原 P01 把次数整体留待后定的表述已被收窄为只留具体参数，不能继续默认有钱即可反复搜索。限制刷新不等于增加全店购买额度，耗尽次数后已有合法现货仍可买，英雄 x 名额不因刷新恢复。Q02 基础方向收束，费用／资源与实际供给留 R09，不自动批准其他特殊商店机制或 RW08 补偿。
