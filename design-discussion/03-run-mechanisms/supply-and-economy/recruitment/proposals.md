# R07 招募机制：方案讨论

## R07-Q03：没有同名升星时，招募如何持续提供成长

2026-09-16，用户指出项目没有升星，询问是否应加入并要求修改招募逻辑。以下是修订后的Agent方案，未采用／未实施。既有R07-D01普通唯一、R02材料培养及R07-D03开局6选2继续作为讨论基线；本轮主动重新评估同名升星，不能把用户询问记成已决定恢复重复合成。

### 对升星的判断

同名合成可以做，它使搜牌同时承担获得新成员与培养旧成员，并让已有英雄的重复出现具有价值。如果要把追同名牌作为主要乐趣，这是完整且有价值的方向。但它会连带改变重复持有、后备空间、金币消耗、供给次数、培养投入及回收；不能只在现有唯一英雄上加星标，再照用原招募预算。

**当前推荐保留唯一英雄，用已讨论的材料培养承担养成。** 固有招募阶级决定取得阶段和基础价值；培养品阶／专属加强由局内资源投入取得。是否用星形显示培养是表现选择，不等于三合一制度，也不需要在材料成长外再叠一套同名成长。R01的机制加强为主、低阶可作长期核心和不培养的羁绊位保持。

缺少同名升星本身不否定五阶内容分类，但不能从TFT的五档种类比例推出本项目所需的搜牌次数、掉率或低阶后期价值。Q13的66／66／66／60／42只留为待验证内容预算，不是已经匹配唯一英雄制度的定案。

### 修订后的招募机会

| 环节 | 建议行为 |
| --- | --- |
| 开局 | 保持随机6名适合起步的候选，选2名进入部署。没有同名追星或第三名随机赠送。具体低阶范围随正式分档，不重开用户已定的6／2。 |
| 普通单次招募奖励 | **展示3名未持有英雄＋1份培养资源，四选一。** 选择新成员或把这次机会用于培养原队伍；培养包是事前明确展示的正选，不是拒领奖励后的自动补偿。 |
| 英雄资格 | 本局合法池中排除当前持有英雄，包括后备；同批互异。取得失败不能扣费用或消耗机会。退出再取得沿退出／回收规则，不推成一局历史永久排除。 |
| 英雄候选质量 | 先按当前阶段抽阶，再在合法同阶内按适配和已见降权抽取；有适配对象时提高至少一个有用补件出现的机会，同时保留其他方向。适配按机制关系与功能缺口，不只数相同阵营／羁绊，不保证指定核心。 |
| 刷新 | 仅在原本允许刷新的渠道按金币和次数限制整批替换英雄候选，已见软降权；该机会的材料包在生成时固定，刷新不抬高包价值，也不重置该次领取／购买额度。免费战后选择不因此自动获得刷新权限。 |
| 满员或没有合适新英雄 | 玩家仍可选材料；若要换人，沿后备／退出规则处理，不能直接吞掉旧英雄或自动退还其培养。材料与新英雄互斥，不能先领英雄再领材料。 |

四选一先作为普通单次招募奖励的可审阅规格，不擅自将所有商店／兵营都改成同一免费奖励：原有付费招募渠道、单次最多x名、刷新上限继续独立。若付费兵营同时出售培养材料，需用其服务库存与价格表达，不因跳过购买免费给材料。领取材料消耗当前奖励机会，后续跳过不追加收益。

培养资源沿R02通用／匹配类别材料及替代／混合支付。第一版替代奖励可优先提供通用材料，类别材料仍可在明确渠道引导路线；不锁成某名英雄碎片，不以材料包偷偷恢复搜同名。培养包量来自本次奖励价值预算，不能作为额外白送成长；明确数量、英雄升级费用及来源频率要联合校准，当前没有足够依据填一套精确数值。

### 各阶段发生不同的选择

- 前期：招人通常有较高边际价值，建立人数、承压和输出基础；允许为关键能力提前选择培养，不强制每次拿人。
- 中期：核心与配套、扩军与集中投资形成竞争。比如已有连弩手时，新招募给出霜羽猎手，玩家可以转向攻击控制，也可以选材料继续培养连弩手；现有换目标保层加强是可参考内容，不表示已接入正式培养。
- 后期：以关键替补、针对敌人的补件和强化既有核心为主要价值，不再靠重复塞人维持奖励量。阶段提高中高阶供给，但仍允许有实际用途的低阶补件；已有低阶核心通过培养成长，而非要求招募再次给它一份。

不按玩家队伍强弱动态偷偷改变敌人或收回供给，阶段与机会预算应可预期。低阶培养后的战力需要与新招高阶的投入比较；并不保证任何培养选择都胜过换人，也不把高阶所有属性和功能做成低阶的严格上位替代。

### 落地缺口与验证对象

当前生产仍是选1赠1开局、候选散列截取，没有材料奖励／培养操作；Rank字段不能代表已有可用培养玩法。本修订不能通过只改候选文本或加星图标完成。需要共同接入开局选择与保存、唯一英雄资格、阶段供给、培养资源与可取得加强、奖励互斥结算，保留真实玩家存档。

后续验证分别看：重复持有是否被排除；6选2／四选一及恢复是否保留同一机会；领取与付费是否原子完成；培养资源是否实际支持低阶核心成长；玩家是否在招人／培养间形成选择，而非某一项始终胜出。当前没有实施、构建或试玩，也未采用同名升星或声称该方案已解决整局平衡。

仅为讨论提案，不是现行权威。进程见 [总览](../../../roadmap.md)，原作依据与缺口见 [已有证据](evidence.md)。最新结论见 [R07-D01／D02](decisions.md)：普通英雄唯一，默认整批刷新＋已见降权；复制与其他刷新策略按已定范围归特殊内容。

## R07-Q01：已有英雄还能否重复招募，并同时上场

本轮只处理同名英雄的持有／部署及直接关联的普通羁绊贡献。不是讨论同次刷新能否出现两个相同候选，也不决定刷新费、限次、补偿或全部退出规则。

### 已定前提

- R05-D01：普通容量默认开放，节点提供英雄，商店／兵营可付资源刷新且该次有招募名额；刷新不自动增加额度。
- R06-D01：按内容组随机开放＋公共功能英雄确定本局池，候选应契合当前阵容并保留其他体系。英雄在池里不等于必定取得。
- R02：英雄培养使用共享／类别材料，允许专属成长方向，不以凑同名副本作为通用升级条件。固定本体能力不等于各份英雄必须走相同后续升阶选择。
- M03-D01／D02：普通原生羁绊贡献 1，开战定档、后备不默认凑档；重复英雄取得／部署和同名是否去重明确留 R07，尚未决定。羁绊贡献与受益资格分开。
- 同名指相同英雄内容身份，不按中文显示名误判；同职业、同羁绊、不同英雄不是重复英雄。临时召唤与复活不是第二份永久招募。

### DR01：普通名册只允许同一英雄持有一份

已有这名英雄时，正常招募不再发放第二份。后备中的持有也算已有；只是把英雄撤到后备不会重新开放第二份普通招募。

这是项目制度对照。现有调研不足以证明某个熟悉的英雄自走棋完整采用这一契约，不配游戏名冒充已核实的唯一规则。

**收益**：每个英雄的成长和装备归属最清晰，阵容主要通过不同英雄组合，普通重复选择不会占据有限招募名额。

**代价**：无法同时养两个专精不同的同一英雄；即使同一技能在两侧都有用，也需要找另一名功能相似英雄。若局级池较小，还需避免已拥有排除后候选不足。

这里不是永久禁止本局再次取得该英雄；退出后能否再招、如何防止用退出绕过培养回收，留真实退出规则衔接。也不预定重复事件奖励自动折材料或免费补偿。

### DR02：可以重复持有，但同名最多一份上场

两份英雄都能招募、独立培养和装备，但每场只选其中一份出战。例如一份走输出升阶，另一份走辅助升阶，战前按敌情换入。

本库缺少完整同机制的普通英雄制度直接证据，明确为项目方案。多份同名占名册／后备位置，也使用实际招募和培养机会。

**收益**：保留不同培养路线，不允许同一套强技能在场上成倍铺开；同名同时凑羁绊的问题自然不出现。

**代价**：多了一条必须解释的部署限制，而且玩家可能为了适配频繁切换同名版本；投入第二份英雄，却不能增加同场角色数量。对希望简化规则的初期不一定划算。

### DR03：允许重复持有、同时上场，普通原生羁绊按不同英雄去重

普通招募可以取得第二份同名英雄，两份是独立身体与技能所有者，可以分别装备和投入培养。Just King 的双 Archer＋双 Berserker、Gladiator Guild Manager 的多 Shaman 阵容，为重复身体共同作战提供直接实践；Just King 是直接的重复英雄案例；GGM 的 Shaman 可有不同个体属性／Traits，只是同职业模板参照，不等于我们的固定英雄副本。两作都不证明本条后半段的通用羁绊去重。

**同名去重是本项目提案，未在本轮证据中核实为 TFT／Auto Chess 的完整普通规则。** 举例：战士 A＋战士 A＋战士 B，原生普通贡献按两个不同英雄计为 2；第二个 A 仍有自己的攻击、技能和承伤作用。

**收益**：同一个英雄可承担两侧任务，或分别走不同专属升阶；同时，补羁绊仍鼓励寻找不同英雄，不会仅靠重复同名把高档位堆满。

**代价**：即使不重复凑羁绊，多份控制、治疗、召唤或经济能力仍可能很强；去重并不能自动解决这些组合的平衡。玩家也需要明确看到“第二份能战斗，但不再增加同名原生羁绊贡献”。

该去重仅指同名英雄重复提供的普通原生贡献，不默默吞掉装备／遗物或其他明确额外来源。不参与凑档也不自动意味着不能受益，仍按 M03 的具体资格执行。多份英雄各自使用招募名额、培养投入和人口，不因取得新副本自动复制旧副本的升阶／装备。这些为本条项目推荐边界，未获用户确认。

### DR04：允许重复持有和上场，每份都提供普通羁绊贡献

沿上述例子，战士 A＋战士 A＋战士 B 就是 3 点普通战士贡献。更多副本既提供身体／技能，也能推进相同羁绊。

Just King 历史 Pacifist 路线有购买重复英雄以激活所需环境羁绊的记录；Auto Chess 历史 Insectoid 明确使用同名死亡者与存活同名者的关系。前者是局部历史配方，后者是特殊同名机制，都不能证明所有普通羁绊逐副本计数。**这里的全局制度仍是项目对照。**

**收益**：规则按身体数量直观计算，小规模内容池也能凑出大人数羁绊；同名群体本身可以成为有辨识度的玩法。

**代价**：重复一个兼有好标签与强技能的英雄，可能同时解决凑档和战力，削弱低费功能英雄或其他成员的存在空间。双／多标签英雄更容易把这种优势叠到多个体系。

若只希望某个羁绊鼓励成对同名，可留明确特殊内容，不必把本条设为所有普通羁绊制度。重复数量上限、特定英雄例外不是本轮另列的全局选择，不先填数字。

### DR05：普通招募限制同名，特殊内容才允许取得额外副本

常规按 DR01，某件遗物、装备或特殊招募机会明确提供永久副本并允许重复部署。特殊副本也可以按 DR03 的原生贡献去重，或者由该内容写明例外。

这是项目组合方案。研究中的复制道具、升级副本与战斗临时克隆不自动证明“唯一普通名册＋永久复制例外”的整套规则；复制原作片段和缺口见证据。

**收益**：重复同一英雄可以成为有价值的构筑奖励，常规名册仍保持不同英雄的清晰身份。

**代价**：多一层例外与资格说明。复制究竟复制基础身体，还是还包含品阶、已选加强和装备，成本差异很大；不能用“复制”两个字默认全部继承，也不能默认初期必须做一个复制系统。

本条与 DR01 可组合，属于具体内容方向；若普通已经按 DR03／DR04 开放重复，复制内容也仍可通过改变取得成本／时点提供价值，不需要用唯一权限作为唯一卖点。

### DR06：重复英雄用于合成／升级，而不是长期保留每个副本

炉石酒馆战棋、Super Auto Pets 等的同名升级会把多个副本转成更强结果；Setr's Auto Battler 1.3 将三份需求降为两份，缓解材料占战斗位置的压力。具体自动／手动合并、触发与保留规则依原作版本，不能混成一套。

**收益**：重复招募天然有纵向成长用途，重复出现不只是另一份身体。**代价**：必须考虑囤牌、自动合成是否打断重复阵容、名额和成长资源价值。

**本项目已采用材料培养，故只保留不适用的参照，不重新提交通用合成方案。** 参考云顶后备不等于必须追同名牌，也不能把研究中的三合一直接接到 R02 品阶。

## R07-Q01-P01：原 Agent 推荐，未采用

提出时倾向 **DR03：普通可以重复招募和同时上场，普通原生羁绊同名去重，各份独立投入**。理由是英雄专属升阶已经允许不同方向，同一英雄的两份培养可以形成真实不同角色；既有招募名额、后备、培养投入和人口承担成本，重复身体不必一概禁止。去重保留寻找不同羁绊成员的价值。

这不是宣称重复技能天然平衡；具体强联动仍需按内容处理，不能以羁绊去重替代效果结算，也不把所有同名技能／特效一律改为唯一。

若更重视每局英雄身份唯一与名册清晰，DR01 也完整可行，DR05 可留后续内容。DR02 有不同专精版本的价值，但额外部署限制不优先；DR04 更利于同名群体玩法，代价是不同英雄的组合空间可能被压缩。所有方案与原作区别保留，不把 Agent 推荐写成用户决定。

确认同名取得／部署后，再按实际选项衔接普通羁绊计数与必要的候选资格；每次刷新是否重复、锁定、保底等属于后续招募子问题。本轮没有实现或体验验证。

## 用户回应：普通唯一，特殊内容可复制

2026-09-08 用户明确不采用普通同名重复，理由是没有三合一培养、希望每个英雄保持独立；遗物或事件可以提供复制。记录 [R07-D01](decisions.md)：采用 DR01，DR05 保留为可用特殊内容方向，原 DR03 推荐未采用。普通同名多份已排除，不再要求选择其通用羁绊计数；复制继承、持续范围、部署及贡献留具体效果设计。Q01 收束，其余招募问题继续按已定前提推进。

## R07-Q02：同一节点刷新时，已有候选怎样保留或替换

本题限定在一个可付费刷新的商店／招募兵营节点。核心场景：本次只剩一个招募名额，当前 A 合适，但玩家还想找更合适的 B；付费继续找时，是否必须放弃 A，以及刚拒绝的英雄会不会反复回来。

### 已定前提与不展开部分

- R05 已定可消耗资源刷新、该次最多招募 x 人；刷新不新增名额。R07-D01 普通已拥有英雄不再可取得，R06 合法池和 G03 适配推荐／其他方向保持。
- G03 战前不限时，无现实倒计时；不重新采用旧商店往返采购。跨回合冻结、带往下一商店的候选预约与同节点保留不同。
- 本轮不选择刷新价格曲线、次数、保底触发、类别筛选或单次名额数字，也不默认战后免费选人奖励同样开放刷新。
- 下面的“旧候选”指尚未招募的英雄。普通持有去重与“见过一次就少出现／不再出现”是两层。

### RF01：付费后整批替换，旧候选直接放弃

玩家付费确认刷新，当前候选被新批次替代；之后不能直接回到旧批次选 A，只能在规则允许时再次遇到它。这是最简单的刷新承诺。

TFT、Vivid Knight、Auto Brawl Chess 等已有资料证明付资源换供给的通用流程；Magicbook 的共同候选面板也会付费刷新。但这些摘要不足以证明所有游戏“刚拒绝项必可立即重现”或完整回看禁令，**本条无回看与未屏蔽重现的完整契约是项目对照**。

收益是过程短、每次继续寻找都有机会成本；代价是玩家怕丢掉还不错的备选，可能过早停止探索。若不与 RF03／RF04／RF07 等组合，项目可以允许旧英雄随机重现，但不能把这一点冒充已核验的所有原作规则。放弃旧页不等于把它永久排除本局池。

### RF02：保留选中的候选，只刷新其余部分

例如当前 A／B／C，玩家保留 A，再付费换掉 B／C。A 仍是尚未招募的候选，占当前展示位置；不立即占后备，不提前增加可招募名额，也不等于把 A 送给玩家。

Super Auto Pets 的冻结是保留商店候选的直接局部参照；Magicbook 有买不起的候选可 lock later 的记录。各作冻结对象粒度／持续边界的证据需要分开，不能把所有 lock 统一写成某种单格刷新实现。**本项目“只在当前节点保留指定英雄，刷新其余”是迁移后的方案。**

收益是保留一个可接受方案，再探索另一个更合适选择；若剩多个招募名额，也可把有互补关系的英雄放在一起比较。代价是留下越多，每次可看到的新面孔越少，可能多花刷新资源；还增加少量保留／解除操作。

“冻结若干候选”与“指定只刷新某些位置”在本题若产生相同结果，不拆成两套机制让用户重复选。费用是否按整次或数量变化另归经济。本方案不允许离开节点后回来购买，也不把冻结搬到下一商店。

### RF03：新一批避开刚刚主动刷走的候选

例如 A／B／C 被刷走后，下一次尽量看到别的英雄，不立即花钱又看到 A／B／C。Underlords 的历史 Standard 资料明确区分手动刷新 blacklist 未购买候选与自动刷新不这样处理；准确连续多次的记忆边界以证据所能支持为限。

**本项目的一次刷新排除窗口是方案定义**：刚放弃的一批不能进入紧接着的新批，之后可恢复资格；不是永久屏蔽，也不删除本局池成员。

收益是每次付费更容易获得新信息，减少“刷新等于没刷新”的感受。代价是不能刚刷掉 A 就立刻反悔再找它，而且合法剩余池较小时可给出的新候选会变少。

它与 RF01／RF02 的保留规则是不同维度，可以组合；被保留候选继续留在原位，不因为排除刚放弃项就被清掉。

### RF04：本节点见过的英雄先不再出现，逐步看遍一个有限集合

每次刷新展示此前在此节点没见过的英雄，直到可用集合耗尽。这个记录窗口比 RF03 更长，看到却放弃 A 的后果也更确定。

本库未找到足够直接的同构英雄节点规则，**属于项目无放回方案**，不拿 Underlords 的短 blacklist 当作整节点无重复证据。

收益是搜索效率可预期，不会在同几人之间反复打转；代价是资源足够时可能逐渐扫完整个合法池，招募从随机机会变成付费遍历。节点之间记忆不共享是此比较的范围，不额外采用全局禁用。

耗尽后停止、循环或另换池会产生不同体验，当前未定；不默认无限生成新英雄，也不能突破 R06／D01 的资格边界。相比 RF03，它需要更强的搜索供给控制，初期不优先。

### RF05：付费先看新一批，再决定保留新批还是旧批

刷新后先比较两批，选择保留其中一批；旧批不会在新批出现前立即丢失。此方案不把两批全部永久累积，也不同时赠送两次招募名额。

本库缺少足够明确的同节点英雄新旧选择契约，**属项目对照**。收益是玩家不用为了探索先丢掉 A；代价是每次刷新多一次比较，搜索结果的下限会提高，刷新价值和操作负担都增加。

它与 RF02 的区别是：RF02 事先决定留下谁、占住位置继续搜；RF05 事后比较整批，探索过程中没有先放弃旧批的风险。费用和随机结果的下限因此不能机械按 RF01 估计。

### RF06：本节点见过的候选都可回选

刷新发现的新英雄加入该节点的可选列表，玩家可以继续探索，最后仍回头招募最初的 A。本库没有足够同构英雄案例，**属项目方案**。

收益是几乎消除“错过就后悔”，更像花资源扩充本次可浏览名单；代价是候选列表和比较工作不断增大，玩家可能倾向先刷尽预算再从所有历史结果中选最优者，减弱见到合适英雄时立即决策的意义。

它与 RF04 不同：RF04 可以不再重复展示，但看过放弃的项不能直接找回；RF06 保留取得权限。列表仍只在当前节点有效，离开后回访旧店未开放。

### RF07：降低已见候选再次出现的权重，而非完全排除

Astronarch 的物品研究记录 common／rare 物品被看见后会降低重现概率，作用范围是其局内物品池；它只提供“软降权”机制参照，**不能冒充单节点英雄刷新的直接规则**。

用于项目，可以让刚见过的英雄更少回来，但仍有机会再次出现。收益是保留偶遇旧备选的可能，比 RF04 少一层硬耗尽；代价是不能保证付费一定看到新面孔，规则与收益也比硬排除难感知。

“看过”会降低多少、持续几次、是否跨节点均未定，不在此选概率表。它与 RF03／RF04 主要是不同的重复处理方式，不要求同时叠加；也不取代 G03 以阵容适配为依据的推荐。

## R07-Q02-P01：原 Agent 推荐，默认组合未采用

提出时倾向 **RF02＋RF03**：允许在当前节点保留想要的候选，刷新其余，并让新批避开刚刚主动刷走的人。玩家可以保住一个备选继续找，也能看见付费刷新带来的新信息；名额与资源仍限制实际招募，不延长为跨节点预约。

若希望把交互压到最少，RF01＋RF03 也直接成立：每次付费就是明确放弃这一批。RF04 的长记忆和 RF05／RF06 的回看会更明显改变搜索价值与比较负担，初期不优先；RF07 是希望保留随机重现时的替代。

候选不足时不能为了凑满而违反已拥有唯一或本局合法池；完全不能产生有效变化时应明确提示，而不是收取一次没有变化的刷新费用。具体降级方式留实际候选规模和费用规则衔接，不以本建议自动锁定候选数。

本题不重开刷新付资源、每节点名额或普通英雄唯一。以上均为待讨论推荐，不更新 D01 或新增 D02；只讨论记录，未实现或验收。

## Q02 用户回应：基础全刷＋降权，RF02–RF06 归遗物

2026-09-08 用户明确采用默认整批刷新、RF07 默认降低已见重现概率，RF02–RF06 应作为遗物改变刷新策略。已记录 [R07-D02](decisions.md)。原默认 RF02＋RF03 未采用，相关机制作为不同遗物的设计空间保留，不要求再单选或初期全做；原 Agent 的初期优先级不自动限制这项内容空间。Q02 收束，降权参数与候选不足按实际供给／经济衔接，不将软降权误记成必定不重复。
