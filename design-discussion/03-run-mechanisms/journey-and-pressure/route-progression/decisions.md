# R10 路线推进：讨论决定

本文件记录讨论结论，不是现行玩法或实现权威。进程见 [总览](../../../roadmap.md)，候选与历史分析见 [开放方案](proposals.md)。

## R10-D11：细节流程认可，授权补齐实施设计与空上下文审查

日期：2026-10-02。状态：**用户认可 Q11 流程，委托 Agent 补设计并独立审查；运行尚未实施。**

- 用户明确“流程没什么问题”，要求 Agent 自行补足仍需设计的内容，并使用空上下文子 Agent review；重点是匹配当前架构与真实内容，顺滑接入系统，不能做临时逻辑。D10 的替换方向授权保持，当前交付进一步落实为可实施设计和审查闭环，不再要求用户重新逐项填写设计。
- Q11 的流程关系作为实施设计基线；新补的地图规模、地点配比、阶段行动预算、内容倍率及架构细节由 Agent 负责首轮选择。必须标明作者配置和可调参数，不能把这些参数记录成用户已逐项认可或已通过平衡验收。
- 设计入口为[实施设计](artifacts/expedition-implementation-design.md)，独立审查记录归同目录。审查须直接核对源码、作者资源、正式规则和活动任务；主 Agent 修订具体发现，再请同一 reviewer 复审。独立审查使用 `fork_turns=none`，不继承本对话。
- 本轮仅修改讨论与执行规划。正式规则、运行代码、场景、真实存档、构建和实机验收留到实施批次；静态设计审查不能写成已接入或运行通过。
- 后续用户认可五阶段实施安排，并明确不建议每阶段做特别重的验证，最后走一遍流程验收即可。执行上采用阶段内必要编译／规则／关键风险检查，最终集中做正式流程和体验验收；避免重复全量回归，存档与事务等高风险边界仍按项目要求定向验证。此调整不改变已审玩法和架构合同，也不表示所有分支／平衡已经通过。

## R10-D07：遭遇预算可继续比较，地图必须产生路线取舍

日期：2026-10-01。状态：**用户接受限定遭遇次数作为可讨论方案，指出自由跑全图的结构缺陷；具体约束尚未采用**。

- 用户认可玩家发现机会、决定打哪里和去哪里招人的方向，同时指出《杀戮尖塔》的路线会把收益与沿途代价联系起来，例如去商店可能需要经过精英，去事件意味着少打战斗。
- 若本项目全图自由访问，限定遭遇次数仍不能让地点连接产生选择，地图可能只是负担。必须回答抵达机会需要经过什么、选择后放弃什么，不能只增加地点数量或装饰性障碍。
- “限定遭遇次数是个方案”不等于最终采用Q08计费表、上限、地图外终战或三选二。此前免费的侦察／回访和散点图须结合可达条件重审；用户尚未要求每格消耗、完全禁止回头、关口守军或机会过期。
- Q08新增“路线代价与空间作用”比较PA01–PA05。Agent撤回把近乎全图自由访问与统一遭遇预算组合为足够进程结构的推荐，优先提议地区连接有前置遭遇、已通地区可回访、区域间保留多条路线。该推荐未采用、未实施；旧16×16图仅保留为内容分布示例。

## R10-D06：地图每局随机，重新设计终战资格与推进压力

日期：2026-10-01。状态：**随机地图是用户明确要求；地图规模、终战与行动限制仍在讨论，未授权实施**。

- 用户明确8×8偏小，每局地图必须随机；不能把固定全图仅换起点当作满足要求。D04的逐格迷雾探索和D05的轻提示、丰富奇幻遭遇保持。
- 用户要求共同考虑：最终Boss是否需要固定路线；是否允许出生附近就是封印终点；是否通过其他Boss取得钥匙；怎样控制区域Boss分布并保证发育空间；是否限制行动次数、到期如何处理；是否从地图外直接进入最终战。
- 上述问句是设计空间，不等于已采用钥匙、区域Boss数量、倒计时、强制终战或地图外入口。8×8固定内容稿Q07保留作地点例子，其规模和固定布局不再作为当前方案；Q07的无倒计时也未获采用。

## R10-D03：围绕世界旅行、地域招募与伙伴冒险发散

日期：2026-10-01。状态：**用户提出候选方向并要求发散，具体制度未采用，未授权实施**。

用户以“路飞当上海贼王的进程”作体验类比，提出一张地图、随机出生地、不同地域分布不同单位、在地图上往返招募伙伴组队、经历多种战斗与成长、最终战胜世界Boss结束的设想。希望战斗不必全部打到一方全灭，但明确战斗模式仍是自走棋。

- 本轮允许探索世界移动、地域供给、伙伴取得与经历、地图变化、阶段成长、特殊战斗目标及终局的连接。不是复制原作人物／岛屿剧情，也不固定当前三区、节点数、英雄池或背景。
- “有没有可能”与要求发散不等于已选完整开放世界、实时旅行、海洋地图、食物工资、无限刷取、永久队员或任何具体目标。主角是否实体上阵、是否有固定船长、单局时长与规模均未定。
- 纯自动战斗是本轮方案边界；目标改变所需的自动护卫、移动、交互、目标优先与胜负判断必须明确标成新增候选，不假定现有AI已经支持，也不增加战中手动控制。
- 用户新提“地图上来回招募”已进入讨论范围，不能拿旧G03-T05不回访旧商店采购的决定直接挡住。本轮区分有新事件／招募目标的返回，与重复刷库存／赶路；若后续选定重新采购和供给刷新制度，明确处理旧决定的替代范围。
- G01-D04的常规歼灭基线与特殊关卡归属保留历史；本轮重新展开特殊目标及其在旅程中的比重，不默认已经取消常规战斗。全局生命、Boss败战、名册容量与替换规则若需改变，作为候选冲突列明，不随题材类比自动修改。

世界与进程发散见[Q05](proposals.md#r10-q05世界旅行地域招募与伙伴冒险2026-10-01)，战斗目标候选唯一详细记录归[G01-Q04](../../../01-global-boundaries/battlefield-experience/proposals.md#g01-q04伙伴冒险中的自动战斗目标2026-10-01)。

## R10-D01：外层创新以非线性运营价值为目的

日期：2026-09-11。状态：**已确认但未合并**。本项确认目的与评价原则，具体外层主循环尚未选择，R10 未基础收口。

### 用户结论

- 用户指出：常规肉鸽用简单静态地图承载基础、清晰的决策也能成立，复杂不等于好玩。该表述记录为用户的设计判断，不作为本轮新增市场或因果研究结论。
- 外层创新不以改变这套基础选路决策的操作方式为目的；增加搭建、旋转、挖掘等操作或提高画面辨识度，本身不足以证明值得创新。
- 希望探索整局游戏中的非线性运营内容。若最终仍然是常规线性推进，就倾向采用成熟常规方式，不为形式不同增加创新负担。

### 范围与未定项

- 本次没有采用 O01–O19 或 X01／X02 中任何具体方案，也没有直接选定 O15。
- “非线性运营”的具体内容仍需结合方案说明，不能由 Agent 自动定义为投资、持续产出、多目标经营、开放世界、回头、任意顺序或无终点；这些都未因本次原则获采用。
- 没有要求把基础选路界面做复杂；简单静态地图也可作为后续方案的表达载体，但尚未确定本项目采用何种地图。
- 战斗权限、战前自由调整、既有成长供给及不回访旧商店集中采购等边界保持。仅讨论与记录，不授权合并或实施。

### 对既有分析的影响

Agent 撤回 Q02 首轮优先深入 O01 的当前建议。O01 和其他候选保留原文与编号，后续按实际非线性运营价值重新判断；不因可见操作变化就优先，也不把用户发言推成所有线性游戏都缺乏策略。
