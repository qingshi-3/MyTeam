# 合并计划

状态：未进入合并阶段，当前无合并或实现授权。

## 进入条件

- 各必要议题有明确结论；剩余问题可安全保留为待定，暂缓/不采用不强行补齐。
- 检查术语、对象归属、生命周期、资源成本、动态更新与失败语义是否一致。
- 小批样例实际覆盖和未覆盖项可追溯，不能把未验证体验写成已通过。
- 已完成 authority-diff，重要冲突和替代规则已由用户确认。

## 执行顺序

1. 形成一份用户可读的整合结论和重要冲突清单；先处理冲突，不先改权威。
2. 确认合并范围后，将规则写入唯一归属章节，更新导航和过期引用。
3. 系统文档区分目标模型与当前支持能力；记录实现差距，不能通过改写技术说明声称已经实现。
4. 验证文档一致性、引用与范围，保留讨论记录及决定来源。
5. 逐项标记已合并和目标位置；部分合并须明确未合入项。实现、配置迁移与验收另开已授权工作，不随文档合并自动执行。

当前正式代码和文档若在讨论期间发生已授权变化，合并时以新证据做差异复核，不覆盖其他工作。
