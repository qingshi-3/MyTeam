## 真实循环与基础规则

每轮准备期从三个商店位买卖单位、调整五人线性队列、选择是否刷新，然后把队伍提交到 cloud，与其他玩家最近提交的相近等级队伍异步自动战斗。战斗每次取双方第一个仍存活单位相互攻击；前排死亡后后续单位依次补位。赢一场累积一胜，1.3 目标为十胜；输一场通常扣一点生命，但前三轮免扣血。

公开 1.3 客户端显示：初始生命 5；roll 为 `$1`，第一轮两次免费；单位买价为 `tier × level + 1`，普通卖价为买价一半向下取整且最低 `$1`。每轮基础收入为 `6 + floor(round/3) + interest + win streak + lose streak`；若本轮没有购买，下一轮 interest 增一，发生购买则清零。它不是常见固定利息档，而是“整轮不买”的延迟收益。

同名升级在 1.3 需要两件，合并后等级加一、攻血相加。即使五人队已满，只要购买立即完成合法合并，仍可买入；否则必须先空槽。玩家的核心选择因此是：保留完整战斗阵容，还是留一格追升级 / 反复买卖；存一轮利息，还是用当前商店闭合成长；升级 support，还是让随机增益更集中地落在其他成员。

## 构筑一：Blacksmith + Shielder + 可选 Alchemist 的买卖成长

2023 玩家把它写成 `armorer + shield guy + optional alchemist`，并明确做法是反复买卖，至第十战几乎全队 50/50。1.3 客户端与官方补丁把对应单位命名为 Blacksmith、Shielder、Alchemist：

- Blacksmith：队友被卖时，随机一个非自身盟友获得 `+Level Attack`。
- Shielder：队友被买时，随机一个非自身盟友获得 `+Level Health`。
- Alchemist：商店结束时获得 `2 × Level` 金钱。

`armorer` 是玩家的功能性称呼，不能当作第四个单位；`shield guy → Shielder` 由名称、买入生命触发和 1.3 自增禁令共同映射，仍保留为高置信解释而非玩家原文命名。

- **engine**：每次买入触发 Shielder；再卖出同一过渡单位触发 Blacksmith；Alchemist 在商店末补回部分循环成本。
- **state/resource**：金钱、三个商店位、五个队伍槽、被买 / 被卖事件、support 等级、随机目标和 50/50 上限。
- **payoff**：买一次永久加生命，卖一次永久加攻击；不是“盾变攻击”的单公式，而是同一交易循环并行喂两种团队属性。
- **survival**：Shielder 的随机生命成长让多个单位能轮流承受前排压力。
- **spatial condition**：成长发生在商店且随机选非自身盟友；战斗时才通过队列决定谁先承受伤害。留一个可交易槽能提高循环可执行性，但会降低当轮完整战斗阵容。
- **payoff owner**：每次随机被选中的单位拥有永久攻 / 血；Blacksmith、Shielder 只拥有触发器，Alchemist 拥有经济回补。两个 support 不能各自选自己，但可以互相增益，因此不是一个固定单核。
- **economy**：最便宜的 Tier-1 Level-1 单位买价 2、卖价 1，一次买卖净耗 1 金；循环同时产生一次生命和一次攻击触发。Alchemist Level 1 商店末回 2 金，能够覆盖两次最便宜循环的净损，但占一个五人槽且自身不是指定收益者。
- **pivot**：长评说明不使用 buff 单位时，主要成长来自升级；使用 buff 单位则常要牺牲第五个常驻单位给买卖。玩家可从完整五人队转成四人核心 + 交易槽，或在找不到 support 时回到同名升级。
- **counter / failure**：没有公开实践来源给出针对这套组合的具名反制。可确认的内部护栏只有 50/50 cap、support 禁止自增、稀缺队伍槽和交易成本。官方 Warlock / Samurai 能影响攻击或前排，但资料不足以声称它们是这套 build 的已验证坏对局。
- **version**：评论发表于 1.3 之后，客户端与 1.3 补丁一致；不能把 1.2 前允许自增的 Druid / Shielder / Blacksmith 规则并入当前构筑。

## 构筑二：高攻血前排 Thorns / Thorn spam

1.2 公告原始文字是 Thorns 受击后按等级对 `enemy team` 造成 1/2/3。公开 1.3 客户端的显示与执行已不同：受击时，以自身 Attack 对 `Level` 个随机敌人各造成一次伤害。两者不能混成一个规则；这是未在 1.3 公告逐条写明的版本漂移。

2023 itch 玩家报告：自己 50/50 的 Thorns 放在最前，对方前排是 45/50 Thorns，第十战中自己一回合杀完整队伍。另一条 Steam 长评称自己的 4/5 对局都遇到 `Thorn spam build`，认为正常成功路线被迫变成同流或 anti-Thorn。它们共同闭合的是高属性前排反伤结构，不证明精确采用率。

- **engine**：让一个或多个 Thorns 频繁受击；当前客户端把每次受击转成与自身攻击绑定的随机多目标打击。
- **state/resource**：Thorns 数量 / 等级、Attack、Health、前排存活回合、敌方人数和 50/50 cap。
- **payoff**：防守承伤事件变成额外输出；Level 扩目标数，Attack 扩每个目标的伤害。
- **survival**：高 Health 让同一 Thorns 重复触发，50/50 个案同时拥有最大输出与最大承伤次数。
- **spatial condition**：至少一个 Thorns 在队首，确保被前排攻击；后续同类在前排死亡后继续补位，构成 spam。
- **payoff owner**：被击中的具体 Thorns 同时拥有触发、攻击倍率和生命续航；这是高度自闭环 owner。
- **pivot**：实践只证明玩家会选择 Thorn 或未具名 anti-Thorn，没有可复现的中途替换、经济阈值或 scout 规则。
- **counter / failure**：评论确认 anti-Thorn build 存在，却没有列出单位和站位，故本 dossier 不用 Mage、Warlock、Samurai 等零散名字拼出答案。可验证的失败是高频镜像和必须围绕单一威胁构筑的感受。
- **version**：1.2 公告、1.3 客户端和 2023 实战必须分栏。把 1.2 的固定全队伤害当作 2023 当前规则会错误解释 50 Attack 的价值。

## 线性空间、重定向与处决顺序

空间不是二维格，而是一列有序单位：前排互殴，后续补位。它仍产生精确的相对位置语言：

- Magician 在战斗开始时替前方盟友承受伤害；重定向者死亡后连接解除。
- Paladin 每回合治疗前方单位，1.3 为 2/4/6。
- Lost Soul 在盟友死亡时向队首召唤随机 Tier-1 单位；Necromancer 也改为队首召唤。召唤不是无占位特效，而是改变后续前排顺序。
- Soul Eater 监听盟友升级并给自己加攻击，展示“升级事件是资源”的独立 payoff owner；没有实践 build，故只保留为规则，不单独登记策略结论。

2021 玩家报告高血 Level-3 Druid 被 Samurai 打出等于当前生命的处决伤害，却因 Paladin 在 Samurai 死亡事件中治疗而留 1 血。开发者明确写出顺序并询问这是可用策略还是应改为无条件击杀；1.3 最终写明 Samurai `kills the front enemy everytime`。这说明“造成等于生命的伤害”和“强制死亡”是不同规则，死亡触发中的治疗能插入前者但不应偷偷改写后者。

## 经济、升级与适应窗口

- 1.3 把升级需求从三件降到两件。首发长评和 Steam 讨论都指出旧规则会迫使玩家长期占用两个 / 三个同名槽，限制完整五种单位和实验空间；1.3 反馈明确说改动后这一问题不再成立。
- roll 从 2 降到 1、首轮两次免费、前三轮免掉生命，把“找到第一对 / support”与“为成长空槽”放进保护窗口。它降低早期失败惩罚，不代表前三轮没有战斗或没有胜负记录。
- 不买任何单位会增加下一轮 interest；买一次就清零。买卖成长 build 因此主动放弃储蓄增长，Alchemist 是其内部回本件。
- Win / lose streak 都直接加收入，使失败也提供追赶资金；没有公开上限和 UI 解释材料，不能判断其平衡效果。
- cloud 对手按相近 level 获取最近提交队伍。早期玩家因样本不足匹配到自己，1.3 明确禁止 own-team matching；这修复对手池污染，不等于解决低人口或服务器长期可用性。

## 失败、反制与生命周期

本 checkpoint 计七个 materially distinct negative / reworked cases：

1. 三件升级长期占用队伍槽，1.3 降为两件；玩家明确反馈旧限制压缩队伍多样性。
2. Druid、Eggman、Shielder、Blacksmith 的自增被禁止，基础攻血又统一封顶 50/50；两条护栏分别处理自反馈与无限数值增长。
3. roll、免费刷新、前三轮免扣血和 15→10 胜共同重做早期进入成本与单局长度；属于一组 tempo rework，不拆成四个数字灌水。
4. Thorns 在 2023 被单个长评描述为环境高频、迫使同流或 anti-Thorn；没有统计，作为社区负面观察而非客观采用率。
5. Samurai 的“生命值等额伤害可被死亡中治疗救回”歧义由开发者确认，1.3 改为必杀；这是结算语义重做。
6. 2023 与 2024 两名玩家独立报告前排互疗导致无限战斗 / 最后一战循环；公开 1.3 只有手动 Stop / 加速，没有可见回合计时、治疗衰减或自动平局。
7. 低样本 cloud 曾让玩家对战自己的队伍，1.3 明确排除 own team；没有材料证明一般性的匹配质量或后来服务器停止原因。

另有 2021-12-10 官方修复 OnHit / `When hit` 指向错误阵营，以及 reroll 后仍可购买刷新前已选单位。它们是有价值的目标归属 / 商店事务缺陷，但没有第二实践来源，保留在 dossier，不增加上述计数。

## 对本项目可迁移

- **盾 / 防守与输出可以是并行轴**：买入触发生命、卖出触发攻击，说明“盾体系如何输出”不必把盾本体直接乘伤害；同一经济动作可以分别喂 survival 与 payoff，最后由明确单位拥有输出。
- **转换者必须有 owner 与成本**：Blacksmith、Shielder 是触发器，随机盟友是收益者，Alchemist 是成本回收者；五人槽和不买利息让 support 不是免费外挂。
- **反伤需要拆三个旋钮**：承伤频率、单次伤害倍率、目标数量不能同时由同一高攻血单位无条件自闭环；否则前排越耐打，触发越多，输出又随攻击继续放大。
- **线性相对位置仍能产生空间体系**：前方治疗、替前承伤、队首召唤和强杀前排形成明确选择器；迁到方格阵时应保留 owner、选择器和死亡时重验，而不是复制一维队列。
- **事件型成长必须先定递归边界**：OnTeamBuy、OnTeamSell、OnTeamLevelUp、OnHit、EveryTurn、OnDeath 是不同事件；禁止自增、统一 cap、每事件只触发一次和来源报告缺一不可。
- **开局保护是适应窗口，不是免考**：免费刷新与免扣血能让玩家等核心件；Boss / 敌人反制也应在考试前提供相似窗口。
- **失败解释要区分数值死亡和规则处决**：若治疗能插队，就必须显示是谁、何时、为何救回；若是强制死亡，也必须显式标为不可治疗。

不可直接迁移：五人一维队列、无限异步 PvP ghost、固定十胜 / 五生命、精确 1.3 数字、随机全队永久刷到 50/50、一个前排同时拥有高耐久与 Attack 倍率反伤、无自动终止的治疗循环，以及未证实的 anti-Thorn 单位组合。

## 未决问题

- 1.3 之后是否存在未公开服务器热更；2025 评测称服务器不可用的准确时期与开发者原因。
- 完整 UI 内的商店等级 / tier 概率、streak / interest 上限与玩家能否可靠预览。
- 一套具名、可复现的 anti-Thorns 队伍、经济路线和站位。
- Thorns 从 1.2 固定全队伤害到 1.3 Attack × Level 随机目标的确切补丁说明。
- 无限治疗是否有服务器侧超时、平局或隐藏回合上限；公开客户端没有可见 guard。
- 召唤是否受五人上限、临时人口或独立战斗队列约束；公告只确认向队首插入和对齐修复。
- 当前 cloud 是否仍工作。单条 2025 负评不能单独证明永久关服，更不能建立商业 / 机制失败因果。

## Disposition

`retained`

它满足规则＋独立实践门槛，并闭合两种不同结构：商店买卖驱动的团队攻血成长，以及前排承伤驱动的多目标反击。经济、空间、payoff owner、转型代价、版本护栏和已知失败均可说明；具体外部反制仍是明确缺口。资料功能类型和独立性不足以升为 anchor，但其机制密度与本项目盾体系问题高度相关。
