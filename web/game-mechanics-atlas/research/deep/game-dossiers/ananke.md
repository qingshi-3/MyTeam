以下均为 discovery leads，不是深证据：

- 小队部署在 hex board 后自动作战；短描述概括为 build squad、position、win、upgrade、go deeper。

同一段产品文本能说明开发者计划有哪些层，但不能证明这些层在同一个可玩版本中如何结算、是否已完成、是否平衡或玩家如何使用。

## 对本项目的研究价值与限制

可保留为未来设计讨论的发现线索：

- 角色职责与 Origin 羁绊应是正交轴：Mage / Barbarian 可共享 Human，Crab / Turtle 可共享 Water，但 tank / DPS / healer 仍承担各自功能。
- team-wide relic 与 unit-owned equipment 可以构成清晰的所有权分层；装备服务某个 core，遗物决定 run 方向，但两者不能免费叠满相同收益转换。
- 防守体系可有不同通路：Water 是回复状态，Shield equipment 是前线吸收 / 可能的 taunt；它们不必因都“抗伤”就成为同一个元素体系。
- quest 可以把局内行为转为 build 资源，但计数口径、时限、风险和 permanent 边界必须可见，避免“顺手完成”的免费强化。
- Elite 与路线节点应在玩家还能调整招募、装备、站位或遗物时提供信息，而不是事后展示高风险标签。

当前不能作为设计依据：任何单位、Origin、羁绊阈值、hex 空间规则、招募 / 升级经济、relic / equipment 清单、Shield / taunt / regeneration 公式、quest 数字、permanent upgrade、Elite 或战斗指令。尤其不能因官方示例用了 2 个单位就断言二人即为 breakpoint，也不能把本地化更详细的盾描述视作完成规则。
