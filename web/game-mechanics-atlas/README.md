# 塔军机制设计图谱

面向塔军自走构筑项目的中文交互式设计空间图谱。它用于探索候选机制、组合、军团流派与 Boss 能力试卷，不会自动修改 `gameplay-design/` 中的正式玩法权威。

## 本地使用

环境要求：Node.js 22.13 或更高版本。

```text
npm ci
npm run dev
```

打开开发服务器给出的本地地址。生产验证使用 `npm run build`，聚焦自动检查使用 `npm test`，代码检查使用 `npm run lint`。

## 数据保存

- 所有设计状态、备注、工作区、快照、筛选与阅读上下文自动保存在当前浏览器设备。
- 不需要账号和网络；不同浏览器、设备之间不会自动同步。
- “导出完整 JSON”是清理浏览器数据、换机或跨浏览器时的恢复路径。
- 导入前会验证结构，可安全合并为新工作区，也可经二次确认覆盖本机。
- 目录和用户状态分别带版本号。旧版无法匹配的机制稳定 ID 会作为孤儿记录保留并展示。

## 内容结构

- `app/data/atlas.ts`：只读图谱目录、稳定 ID、关系、构筑引擎和 Boss 试卷。
- `app/lib/persistence.ts`：本地工作区结构、迁移、导入校验、合并和孤儿识别。
- `app/components/AtlasApp.tsx`：交互视图与工作区操作。
- `.openai/hosting.json`：Sites 托管逻辑配置；本项目不使用 D1、R2 或后端账号。

网站根目录的上一级 `web/.gdignore` 会阻止 Godot 扫描网页源码和静态资源。不要删除它，否则引擎会为网页资源生成无关的导入副产物。

## 机制图解的视觉语法边界

- 规则图解必须直接区分前态与后态，并用箭头、路径或中文直标说明作用方向；暂停动画或开启减少动态效果后，完整结果仍然可读。
- 未确认的规则分支不得在图中静默发明。位移、目标选择、影响范围和异常结果只呈现活动任务中已确认的语义。
- 图谱中的图解用于探索与验证表达方式，不会把候选想法提升为 `gameplay-design/` 中的正式玩法权威。
- 当前只有冲阵、嘲讽目标重定向和 AOE 三类使用结构化“命中前 → 命中后”故事板；其余九类原型只继承共享的字号、对比度、形状与方向可读性，是否扩展需另行确认。
