# 内容组合基础契约

## 目标与分层

本模块区分：①通用结算与生命周期；②内容作者使用的通用模型、编译和运行接入；③具体英雄、技能、羁绊、装备、遗物与事件配置。前两层不依赖具体内容 id。新增原子机制可以扩展类型化处理器，不承诺无需扩展即可表达所有未来玩法。

沿用独立内容场景、只读 Resource、不可变编译图和显式运行作用域。BattleSimulation 仍是战斗修改权威，RunApplication 仍是征程命令边界。不得以一个万能产品类替换各系统生命周期。

## 共享战斗原语

- `EffectTargetResolver` 是效果和技能操作共同的快照目标查询。旧自身/来源/指定目标/相对队伍语义保留；`FilteredTargetQuerySpec` 组合锚点、敌我、存活、是否含锚点、标签、范围、排序、数量。`Range=-1` 为不限制，`MaxTargets=0` 为不限制。最近/生命比例排序使用 runtime id 作为稳定并列次序。空间范围使用逻辑单位中心距离，不隐含视线或普攻范围限制。
- 条件组合为 AND；支持存活、标签存在/不存在、生命比例比较。显式实体引用不存在时条件不成立，不将缺实体解释为已死亡。按所需来源/拥有者/指定目标检查，不能把一次绑定的条件误认为对查询选出的每个目标分别判定。
- `CompositeAttributeMagnitudeSpec` 支持加、乘、最小值、最大值，以及既有常量、来源/目标属性、上下文值、队伍计数、羁绊值。最多 8 层/128 节点，每个组合 2–8 项；拒绝循环、缺值和非有限结果。根节点决定整个属性修饰的 snapshot/live 时机。负系数用常量表达；效果最终值不得为负，需要截断时显式组合 Maximum。
- EffectStep 的可选 `Magnitude` 与属性系统使用同一编译器/计算器；指定公式时旧 AmountSource/Amount 保持 Fixed/1，防止两个表达式互相覆盖。效果数值在当前执行波次快照中读取，不持有可变 AttributeSet；其 snapshot/live 不意味着跨多次触发缓存数值。
- Effect 上下文只提供 `InvocationValue` 与事件触发时的 `EventEffectiveValue` 命名值。各内容载体显式校验自己供应的上下文；缺失上下文运行时抛出明确错误，不静默返回零。发布完整图验证嵌套 TraitValue 引用。
- 现有队伍计数 `Persistent` 是本战初始非临时单位，`Deployed` 是本战初始单位，`Alive` 是当前存活单位（含临时）。它们不是整个 Run 含后备的名册数，也不是人口上限；新增计数口径必须另建明确原语，不能偷换旧公式含义。
- Damage 只有 Normal（普通，序列化值0）与 True（真实，保留值2）。公式先计算原始伤害，经公共修饰后，Normal 使用目标有效防御：正伤害为 `max(1, raw × 100 / (100 + defense × 7))`，非正伤害为0；True仅跳过防御步骤。随后共同吸收护盾、扣生命、处理死亡与来源统计；有效伤害只含实际盾量与生命损失，不计过量。普攻、技能、持续伤害、反伤及法强公式不因来源或外观改变此路径。
- UnitDefinition 的 SpellPower 与 Armor（统一防御）进入 Attribute 编译快照、校验和指纹；法强只有被公式显式读取时才影响效果，不隐含给所有伤害乘倍率。MagicResistance 已移除，CombatAttribute数值5留空，后续枚举身份不移动。旧Magical数值1已从本仓库资源迁至Normal，编译器拒绝残留1或退休属性，不把旧类型猜成True。本次未迁移真实玩家存档；Run保存内容身份而非这两项战斗枚举。
- `CombatSourceRef` 从能力/状态/遗物/地板规则贯穿共同结算，拥有者与具体效果来源分开。伤害类别进入共同计算请求和事实；状态反应可筛选来源种类、事件中的来源/承受方，以及普通／真实伤害类别。
- 已阵亡/不存在的承受者返回 `Skipped(TargetUnavailable)`，与合法目标上实际结算量为零区分；不得为前者发布成功伤害/治疗事实。

## Growth Journey 征程所有权与事务

- `GrowthContentPackage` 发布独立项目、目录和不可变 `CompiledGrowthRules`；`GrowthGameRoot` 只负责选择该包与独立存档命名空间。Alpha 的 `GameRoot`、内容池及无成长的旧存档保持原语义。当前规则包含 26 名代表内容和明确发现池，不声明全 49 名内容均已完成成长改造。
- `RunApplication` 是成长命令边界。生产分配、一次升阶、发现领取、研究兑换、法术预设及真实开战都只能经门面进入；UI 不直接修改 DTO。`GrowthRunService` 计算候选状态，`RunProgressionPersistenceService` 以复制后校验、保存成功再发布的事务提交。失败返回消息并保留原活动状态、选择、库存和待领取机会。
- 非战斗节点在选择时冻结参与者与生产分配；战斗在真实开始时冻结。结算和层数推进属于同一次保存；普通败战仍按规则结算非终局成长，终局不产生下一次可用收益。生产增量记录来源、目标、模式、层数和战斗编号，攻击／生命使用受益友军内容原始值的 `4%` 固定绝对量，禁止从当前叠加后面板继续复利。
- 升阶在一个事务中验证材料、扣除材料、写入一次性升阶身份并创建固定三个候选的 `PendingDiscovery`。候选不足、重复拥有、保存失败或准备锁定时不允许部分扣款。待领取发现独立于常规 `PendingOffer`，存在时不能推进下一节点或开战；保存重载沿用原候选。
- 研究兑换只把法术身份及数量写入 Run 库存。预设只保存法术和目标；`TryBeginGrowthBattle` 先校验完整战斗配置，再于真实开战事务中冻结并消费，并清空下一场预设。准备异常后的重试复用 `PendingNode` 已消费身份，既不二次扣除也不允许替换。战斗准备把法术能力临时投影到指定英雄，不写入英雄永久 loadout。
- 永久攻击／生命和升阶 loadout 由战斗准备适配器投影到实例快照；装备、羁绊等继续按既有顺序工作。战内永久收益只接受 `BattleResult` 的明确增量载荷并校验来源／触发次数；例如 MX01 每战首次成功冻结的 `+16` 最大生命。临时状态、层数和战斗属性不能整体回写 Run。
- schema v8 为成长增加显式空状态：旧 v7 只迁移能够确定为空的成长字段，不凭历史战斗猜测产量。若v7已停在非战斗节点，迁移空参与名单／分配快照；完成原选择只授予当前节点固定材料一次，不补生产。非法或不支持的存档保留原件并拒绝载入，不静默重置。独立 Growth namespace 防止验证征程覆盖 Alpha 玩家数据。
- 全局生命仍由 Run 节点结算拥有：普通／精英败战在生命剩余时继续，Boss 败战直接终局；成长结算不得绕过或改写该失败语义。

本批数值是可调验证基线。系统权威固定的是所有权、冻结点、事务原子性、失败语义与投影边界；数值调整应留在成长规则资源，不写入 UI 或战斗特例。

## 技能入口

### 职业／体系矩阵逻辑验证包

- `scenes/app/ValidationMatrix.tscn` 经 `ValidationMatrixPackage` 发布独立 `content/validation_matrix/matrix_project.tres` 与 manifest，复用正式战斗及实验室。MX 英雄与临时单位分别有独立 `.tscn`／`.tres`，不改正式 HC、敌人定义或正式招募池；实验包使用独立存档命名空间。设计源和验收边界见 `work-items/active/trait-roster-planning.md`。
- `MatrixAbilityOperationSpec` 编译为不可变操作树，按原子类型而非具体英雄 ID 分派。嵌套效果有深度／数量／循环检查，召唤引用进入发布门禁和准备快照，所有字段及嵌套操作进入内容指纹。事件注册、延迟、计数器、条件租约和召唤寿命均归战斗实例，禁止回写资源。
- `TraitBreakpointSpec.Mechanics` 以类型化机制声明羁绊档位，旧无机制配置保持既有指纹。开战贡献者和档位固定，临时单位受益范围独立判断；生成物不能递归新增凑档，羁绊生成的死亡收益按规则排除。额外召唤消费首次成功资格，即使容量或空间不足也不延后重试；共享召唤路径保留其原有存活上限。
- `CombatDamageClass` 与 `ActionId` 区分普攻、主动技能、持续、反击及派生伤害，单次施法和单次普攻具有稳定行为身份，多段命中据此去重；投射物保存发射时身份。`HealthLost` 保存伤害前来源／伤害后目标生命比例，`HealingResolved.TargetHealthRatio` 保存治疗前目标比例；反应不得读后续变化的比例代替事件事实。
- 限时护盾按来源与到期时间记录，实际吸收和过期同步同一账本；破盾反应保留真实伤害因果。毒逐层保存来源、寿命与下一次跳伤，转移保留这些属性。寒意／余烬提供可检查的状态层数，死亡前冻结合法死亡读取值并清除活体持续结算。
- 法力增益遵守施法恢复锁，显式允许延后的返还进入战斗队列；不通过直接写蓝绕过锁。位移后效果只在真实抵达并命中合法目标时执行，取消时清理；连射递增随同一目标连续箭数计算，换目标重置，仍走原前摇与弹道。
- 新机制状态、待执行任务、行为身份与去重集合全部纳入 `BattleWorldStateCheckpoint`。旧技能、羁绊和矩阵反应在共同因果预算内依次排空；失败回滚本次事务，结束清理。没有矩阵内容／动态羁绊时不订阅无关反应或逐帧复制空状态。

### 通用技能契约

- `BattleAbilityScope.ReadStates`提供拥有者当前注册技能、成功次数、真实就绪tick及注册tick的不可变读取；包含首领当前阶段和局中召唤注册，不依赖单位原始loadout。`BattleSimulation.ReadUnitSkills`组合实际法力、怒劲账本、单元动作队列、周期节拍、条件／次数及旧行为组件状态，输出`BattleUnitSkillsSnapshot`。周期按最近成功提交和冷却向上对齐全局触发节拍，失败／受控不消耗就绪；查询不调用Prepare／Commit或修改世界。终局在清理前冻结该投影。虫母破壳／产卵的机制与显示均读取已注册阶段操作，避免首领准备移除直接loadout后失效。
- `IsDisplayedActiveSkill`只供界面分组：满蓝、条件动作及敌人显式施法动作显示为主动；周期被动维护仍为被动。它不修改`IsActiveSkill`原有战斗事件入口，也不按具体单位id分派。

- `ScaledStatusAbilityOperationSpec`在提交时读取目标当前层数，计算固定基础＋现有层数比例的施加量，以及基础概率＋另一状态层数比例的成功率。可选`ChanceTraitId`／`ChanceByTraitTier`以拥有者当前队伍的有效羁绊档位替换基础概率，只对贡献成员生效，身份同时匹配runtime id及原始实例id；未激活或非成员保持基础概率。`MaximumChance`裁剪最终概率，默认1保持旧内容；概率表须完整覆盖被引用羁绊档位，引用与参数参与出版校验及指纹。每目标只读一次、抽样一次，概率失败为成功无效果；普通`ApplyBatch`处理实际层数、来源与生命周期。确定性随机随世界事务回滚，所有状态资源及字符串引用参与出版图与指纹。此操作不作为常驻Passive授予。
- 连射操作可配置`MaxTargets`，默认为1保持旧单目标语义；多目标首箭固定本次候选组，后续每箭筛掉其中射程／通路不合法或死亡成员再轮转，不补选组外单位突破目标数。仍用原攻速前摇、投射物命中链与事务状态。`OwnerAttackOrSkillHit`读取本人普攻及技能箭命中，不把持续伤害当命中；`AllyTemporaryDefeated`仅读取己方临时单位的真实阵亡／消费，不把清理、到期或亡语代触发当死亡。

- `ApplyStatusAbilityOperationSpec.ApplicationVfx` 可为状态施加操作指定一次区域表现；仅允许有正范围的来源／拥有者中心查询。编译后随同一操作成功提交，中心与半径读取该查询，不复制视觉判定或在动画回调中施加状态。事务失败时表现事实一并回滚。
- `StatusPresentationSpec.PersistentVfx` 随状态编译快照进入表现层；持续特效以单位＋效果标识归属，同类多来源只显示一份，持续刷新不重播。嘲讽来源失效时按其索敌语义隐藏标记，其他状态遵循自己的生命周期；视觉不移除或修改 Status。
- Automatic 目标选择不依赖 ManaFull。满蓝是资源条件，周期/开战是触发时机，查询是独立目标策略。
- AttackHit/OwnerDefeated 由公共 Combat 事实桥排队，退出当前事务后再执行各自技能事务，不同步嵌套 Status/Effect 队列。反应有数量/深度约束与因果身份；失败仅回滚本次反应，不撤销已经提交的触发事件。
- OwnerDefeated 明确允许死亡拥有者作为来源，但不允许普通治疗、护盾、状态操作对尸体生效。
- Passive 是可撤销常驻状态授予。一次性伤害、治疗或召唤使用开战/事件技能，不能把它们伪装成无生命周期的被动。生产可选 `content/abilities/passive`、`triggered` 目录与已有 automatic、commands 一起接受完整图门禁。

## 蓄力直线技能与敌人阶段数值

- 敌人继续通过独立 `.tscn`／单位定义、`UnitAbilityLoadoutComponent`、技能组引用独立技能资源；不在具体敌人脚本中内嵌技能。`ChargedLineAbilityOperationSpec` 编译为不可变操作，独立声明技能距离、宽度、时序、普通／真实伤害、投射／光束、命中上限、衰减及表现引用。目前限周期自动技能的单一操作，合法性和指纹覆盖全部参数。
- 技能索敌读取自身距离及地形通路，不借用普攻射程；保持远程位置是操作显式策略。`BattleUnitState.ChargedLine` 持有不可变的起终点、开始时间和阵营，蓄力开始锁向并纳入战斗事务回滚。控制、死亡、来源位移／换队取消，目标变化不重新瞄准；结束清理，不回写共享资源。
- 飞行箭复用扫掠投射物，伤害类型、命中衰减及表现为显式参数；光束在释放步按路径碰撞顺序单次结算。两者走共同伤害／防御／技能命中事实链，表现回调不结算伤害。类型化 `BattleLineCue` 传递预警、释放、取消与命中；正式战斗和预览共用独立VFX场景、播放器与暂停／倍速时钟。
- `EncounterDefinition.EnemyHealthMultiplier`／`EnemyDamageMultiplier` 为独立正数配置，编译冻结后经 `RunBattlePreparationService` 显式传入准备请求，对敌方不可变快照缩放并进入实际战斗属性。默认1，实验室保持默认；阶段战力不由机制类别推断，也不复制或临时修改共享单位／技能资源。

本批发布内容、暂值与验收边界见 `work-items/active/enemy-piercing-skills.md`。

贯穿直线弹显式设置 `BattleProjectileState.ContinueAfterHitLimit`：名额用尽后跳过新碰撞伤害，但仍推进至锁定终点；普通弹默认命中耗尽即结束。表现消费独立终点事实，贯穿弹最后一段插值完成并呈现终点后释放；暂停不提前清除，终局立即清理。贯穿命中表现排到可见前端抵达接点时播放，队列归飞行实例并随清场清除，不延迟权威伤害结算。通用 `impact` 为独立短擦痕资源，不再承载范围圆环。

`VfxDefinition.ProjectileImpactTail` 是投射物自身命中余效的可选表现配置（默认关闭）。启用后末段显示插值抵达接触点才向同一实例发送Impact，Completed按资源ReleaseDuration释放；未命中只结束，不伪造Impact，作用域清场仍立即释放。目前酸液启用；普通箭和贯穿箭原逻辑保持。

## 首批设计英雄的组合接入

- 当前正式可用英雄之间一套角色外观只对应一个英雄身份；动画与头像同步，不以相同外形承载不同英雄来节省素材。可复用组件、技能原语和特效不受此限制。暂停候选可保留独立场景和资源，但必须同时退出正式英雄目录、招募池及可选内置预设；目录之外的草稿文件不等于已发布内容。当前名单与暂停映射维护于 `work-items/active/bc-hero-roster.md`。

- `UnitDefinition.ProjectileWindupSeconds` 与 `AttackReleaseProgress` 是静态动作配置，校验、指纹并冻结进快照；零前摇保留既有夹具语义。待释放箭保存在战斗实例的不可变 `ProjectileWindups` 中，前摇按攻速／序列倍率并向上对齐固定步，类型化 `BattleAttackTiming` 使角色动作与实际释放一致。释放前复核目标、射程与通路；控制取消，失败回滚，死亡／战斗结束清理，不能写回共享资源或让动画回调结算伤害。
- 定时技能可在 `UnitAnimationComponent.TimedActionReleaseFrames` 按表现cue绑定独立SpriteFrames片段及一基释放帧。`BattleLineCue.ReleaseVfx`选择已配置片段，未配置者保留普通攻击回退；权威 `BattleAttackTiming` 分配蓄势／恢复时长，帧duration只调阶段内节奏，释放事实才允许越过挥出帧。静态帧资源不承载播放状态；重拳、冲锋预览均走正式角色表现API。
- `AttackHitGrowthComponent` 只编写命中攻速增量、换目标策略与是否允许保层测试；冻结为单位快照。层数、目标链、普攻小数进度归单个 `BattleUnitState`，不写回共享 Resource。叠速没有内容层数上限；成长单位的普攻调度保留小数进度，可在一个固定步内发多箭，不以一个 tick 暗设攻速上限。
- `ProjectileSequenceAbilityOperationSpec` 编译箭数、相对普攻间隔与攻击倍率。序列归战斗实例，每步读取当前攻速，使用共同投射物碰撞／伤害链；普通攻击命中与 `SkillHitLanded` 明确区分，技能箭不授予普攻回蓝。施法失败时序列、法力、投射物与相关状态一起回滚，战斗结束清理序列，新战斗重建零层状态。
- `Taunt` 为带来源的定时状态，普通目标选择读取最新仍存活的来源，并沿正常移动／射程接敌，不拉位、不改已发弹道、不重定向自动技能。防御增益和按当前防御反伤复用属性及状态反应；反伤订阅 `AttackLanded`，不从普通伤害事件递归触发。
- `IsTestDummy` 标识测试单位，正式招募与运行配置校验拒绝它；实验室允许双方布置。`UnitBehaviorComponent` 的静止／禁普攻控制用于假人。实验室 `RetainAttackStacks` 是单实例准备覆盖，并进入预设序列化与摘要，只对声明支持的战内成长组件有效；它不是 Growth Journey 的 Run 升阶或永久培养入口。

### 决斗、怒劲与飞钩原语（2026-09-19）

2026-09-26局部契约更新：`GritStorage.WindowTicks=0`表示该来源怒劲战内不自然过期，正值仍表示逐笔到期；正式HC38使用0。统一样本资格读取供累计、上限、UI及触发请求使用，消费／死亡／结束及事务回滚仍归战斗实例。下文的“独立过期”仅适用于正窗口来源。

普通攻击不再读取`HealingPower`来替换为治疗；恢复只由显式能力／效果进入同一HealingResolved事实链。单位定义仍独立于阵营运行实例，敌我目录禁止重复定义引用；相同外观共用动画等静态资源，分别调参的单位属性与技能数据不合并。实验室把同一英雄放到另一测试队仍使用该英雄定义，不暗中替换成外观相同的PvE敌人。

按D50后续三名英雄局部执行授权新增`Duel / Counterattack / GritStorage / GritPunch / HookAbilityOperationSpec`。编译后均为单独不可回响操作；反击限定ReceivedAttack、怒劲存储限定HealthDamaged、重拳限定无资源成本的Automatic/ActionQueued，决斗与飞钩限定自动满蓝技能。重拳技能组必须有唯一对应CounterKey的存储操作，满怒值来自该存储上限；半血／濒死阈值与蓄力／收势时长为独立技能字段。触发资格、受击有效量、伤害／吸血／护盾和技能命中仍复用既有结算，不以英雄id分支。

`BattleCombatTechniques`中的不可变状态归战斗实例和世界检查点：决斗记录双方、队伍、期限与断开距离；怒劲记录独立过期的实际生命承伤；短盾只记录自身未消耗贡献，吸收优先扣减该贡献，到期不得删去别的护盾；重拳锁定方向、伤害快照及释放tick；飞钩保存飞行／回收／被拖单位。`BattleGritTriggers`记录半血边沿与本战已用濒死机会，伤害／治疗后及每tick观察条件。`BattleUnitActionQueue`按RuntimeId保存待执行技能、触发原因和收势结束tick；同技能合并原因，开始时重新选目标并在原能力事务内出队／消费资源，失败整体回滚。正常动作占用、位移、控制和收势时不取下一项；死亡清请求，复活不重置已用濒死机会，结束战斗全部清理。收势和表现使用同一技能时长，line_release不再假定所有技能释放帧都是80%。决斗双方不得开启主动，普通攻击及被动仍可发生，第三者不受此限制。

飞钩在普通移动之后进行相对运动圆扫掠，按最早碰撞及稳定id取首个敌人；命中后请求既有地面Pull，墙体、身体和落位保留不穿透约束。回拖取消先于位移推进，避免打断后仍多拖一tick。表现只消费`duel_* / counter_strike / hook_* / line_*`事实，金属钩头／绳索跟随插值及被拖者可见身体；没有第二套表现驱动逻辑。四项独立VFX与正式战斗／预览共用VfxPlayer。入口与验证归[三英雄任务](../work-items/active/duel-grit-hook-heroes.md)。

2026-09-12，按 `design-discussion/04-content-validation/decisions.md` 的 2.3-D06 局部实现授权扩展；本批实现与接入已完成，未构建／未运行验证，待用户体验反馈；具体完成范围与限制归 `work-items/active/bc-hero-roster.md`。具体 HC04–HC30 技能与测试数值只维护在内容资源和讨论当前稿，本节不重复英雄目录。

- `BattleValueAbilityOperationSpec` 提供有限的伤害、治疗、护盾、法力、计数写入、可撤销属性贡献、资格条件和耗盾操作。`BattleValueTermSpec` 明确读取拥有者、选中目标、事件来源或事件承受者的属性／生命／当前盾／计数／事件实量／过疗／状态层数／负面种类／本战历史等输入；不按描述字符串执行机制，也不把所有事件实量当成同一种资源。
- 个人计数按战斗 runtime id＋key 归属，共享计数按当前队伍＋key 归属。`BattleValueRuntime` 的不可变机制账本纳入世界检查点，与属性贡献、待返场、阵营租约和已消费尸体一同回滚；新战斗从空账本建立，不写回共享 Resource 或 Run 成长。界面读取真实战内资源与中文标签，不用动画猜测充能。
- 公共 Combat 事实桥区分普攻命中、技能箭命中、暴击、成功闪避、实际生命损失、新护盾、实际治疗／过疗、成功满蓝施法、控制成功、友军死亡和拥有者召唤物命中。事件所有者、来源、承受者和具体触发资格显式匹配；反应排队离开原事务后执行，带因果身份与预算。普攻回蓝、技能箭资格、反伤与附伤不得借泛化事件重入同一条收益链。
- `ShieldReceived` 读取本次正值新盾，不用状态刷新次数替代；`HealthDamaged` 读取实际生命损失，护盾吸收与减免量不计入。`HealingDone` 只读取来源真正恢复的生命，`OverhealReceived` 读取承受者收到的治疗余量，不将余量加进治疗统计。普通法力恢复窗口仍有效，显式法力技能操作可提供明确返还。
- `ConsumeStatusAbilityOperationSpec` 在同一提交中移除指定持续伤害状态，读取从当前时点起剩余的计划跳伤并转即时伤害；已消费部分不能继续结算。持续状态以应用／刷新 tick 加时长形成绝对到期 tick，周期可在到期 tick 兑现最后一次，不能因单位行动先后越界多跳；消费同时取消对应已排队但尚未执行的周期收据；`ExecuteStatusEffectNow` 通过 `TryClaimPeriodicInvocation` 领取收据后才执行周期，避免提前兑现后补跳。第一版只接受有限时、正周期、无条件单段、状态拥有者为目标、`InvocationValue×1`、正固定伤害且无额外次数／间隔限制的周期定义，不猜算任意复杂状态未来值。`ConsumeStatus.StatusId` 和状态层数读数的 key 都参与发布图状态引用检查，未知引用拒绝发布。
- `EchoAbilityOperationSpec` 只从合法友军中选择显式 `Echoable` 能力，沿供体能力和来源执行，供体仍存活。作者仅将可借用亡语标记为可复制；复制动作、返场过程与装备授予不因此复制。代触发不制造供体死亡事实，不嵌套代触发；召唤等原效果仍遵从供体数量／空间限制。
- 属性广播的贡献句柄按来源、能力操作和受益者隔离，可更新和撤销。离开范围或来源无效时撤销对应贡献；防御广播读取来源自身防御扣除收到的广播，禁止来源互相转播放大。本战成长与实时广播是不同保留策略，死亡清理不能无意删除已明确保留的战内历史。
- 普通技能召唤和敌尸转换产物均引用已发布的独立单位定义，进入共享战斗召唤快照与实验室索引。按拥有者限制存活召唤量的选项与原有队伍计数分别编译；数量、位置、成功与失败仍由战斗权威决定。战术内容指纹覆盖新增操作、可复制资格与拥有者召唤上限，不以描述文本代替结构字段。

- `LifecycleAbilityOperationSpec` 的同身份返场保留 runtime id、初始队伍、本战历史和已用能力次数；按延迟后从死位附近寻找合法身体落点。返场重授常驻被动，不重放开场技能，不重置有限返场次数。暂时无落点则继续等同一身份，仍受全战 `MaxTicks` 约束，不额外添加独立倒计时；已登记返场机会参与初始队伍终局判断。
- 消费友军只接受存活同队临时单位；以 `UnitDefeated` 的 `Consumed` 原因产生死亡事实，不伪造普通攻击、巨额伤害或敌方击杀。只转移操作声明的攻击／最大生命比例，新增生命恢复另走明确治疗，不复制装备、技能、状态或持久名册身份。
- 消费敌尸只接受敌队、非 Boss、未消费且未处于待返场队列的已死亡单位。准备时检查固定召唤产物、来源存活数量上限与合法落点；缺少产物或空间属于准备失败，不支付法力。成功后标记尸体已用并生成固定临时产物，不让原敌人能力复活。
- 限时阵营控制锁定同一活目标：引导期间持续检查来源存活、原队伍、行动控制、视线与作者指定范围；失败取消引导，成功后保留目标身份和能力并暂改当前队伍，不重播开场。到期、来源失效／改队或目标死亡时解除。切队同步羁绊成员与来源实例，撤销原队伍双向广播，并由 `CancelAllegianceProjectiles` 取消相关在途弹；目标锁定、同身份返场／切队的 presenter 重建与报告同步由同一战斗流程接入。
- 战报按单位初始队伍保留归属；有限返场只形成一个身份条目，战报界面读取的 `ActiveTicks` 实际参与时间排除死亡等待，不将返场按新单位重复计数。暂时倒戈不把敌人变成可以带走或延长我方名册资格的永久英雄。

上述是本批实现应保持的具体合同，不表示已构建、运行或完成玩家体验验收。

## 内容载体与授予

- `ContentCatalog.RetainedContent`显式引用保留英雄／技能loadout库。保留项参与同一身份、场景、头像、技能和状态依赖门禁；`AllEntries()`仍只返回活跃内容，正常单位池及实验室不因保留资源而恢复暂停单位。活跃技能不能召唤只有保留库身份、没有运行时发布入口的单位。
- `RelicPlayerSummonsTargetSpec`明确覆盖己方临时单位及后续生成者；出生发布事实前投影遗物属性并补足本次新增最大生命，后续刷新不治疗。属性保留在阵亡身份上供亡语读取，转离所属队伍时撤回，战斗作用域结束清理；不得借此改变原“初始非英雄军队”目标语义。
- 羁绊计数可选`UniqueOwner`，同一持有者的原生与装备贡献只取一份（多份取最大贡献值），不同持有者的同款徽章仍分别计数。原`CountEach`／`UniqueContent`语义不变。成员受益仍使用明确`Contributors`目标，计数／身份与对方身上的状态区别保持。

- `GrantId` 标识某载体拥有的授予，与真实 SourceId 分开；同一个来源的多个授予互不覆盖。`ReplaceGrants` 将撤销旧授予和应用新授予作为一个可回滚操作。
- Effect 次数/间隔按 binding、source、owner 及具体 Origin 实例隔离；同一英雄的独立授予不共享额度。达到普通次数或间隔限制属于正常不触发，预算耗尽/处理器故障仍是显式错误。
- 开战分为静态属性与常驻授予投影、按输入比例初始化生命/法力、重放授予玩法效果、开战事件/技能。正式征程的 Run 适配器固定传入生命比例 1，因此按有效生命上限满血入场；实验室／专项场景仍可显式传入比例，模拟内核不强制覆盖。重放前撤销的授予不再执行旧 Applied 效果；初始化伤害/治疗不能被后续生命归一覆盖。局中新增单位不重写其他单位生命；局中提高生命上限不隐式治疗。
- v1 可授予状态为永久、BySource、单层、不可驱散、拥有者死亡移除、无溢出转换。这是撤销边界而非状态系统整体限制；该状态内部仍可组合属性、周期、生命周期及战斗响应效果。普通可叠层/可驱散临时状态继续走 ApplyStatus。
- 羁绊档位可选择全队或贡献成员，并授予属性和状态。成员改变即使未跨档也更新受益者；下降、失去成员、结束时撤销对应来源。贡献计算政策保持原有部署、重复、装备、额外值与临时单位规则。
- 装备可授予常驻状态，并直接配置拥有者为事件来源或承受者，目标可以是拥有者/事件来源/事件目标。设备实例不是单位属性源；无法供应的来源属性、实体条件和空间锚点组合在编译时拒绝。
- 遗物通过 `StatusGrants` 复用状态的通用事件能力，保持自己的 Run/Battle 计数、阈值和结算职责，不再复制一套状态反应系统。遗物选取受益者仍使用既有目标模型，移动/召唤/死亡刷新可撤销授予。
- `EffectModelText` / `StatusModelText` 从编译规则生成说明，指纹覆盖条件、目标、公式、伤害类别与表现字段；描述不作为结算权威。

## 征程决策与保存

- `CampaignDefinition.RecruitmentSupply` 引用独立 `.tres`，包含按顺序编号的2–5阶英雄组、开局权重和按绝对楼层递增的阶段权重。编译时检查全部征程池英雄唯一归阶、身份资格、权重长度/非负/总和、阶段起点与范围，以及开局能提供6名且人口能容纳2人。正式当前值为14人4阶，不从全目录推断入池资格；实验室仍读取完整发布目录。
- `RecruitmentSupplySampler` 只读取编译快照：稳定身份派生随机源，先阶后英雄、不放回抽取，只在当前允许的非空阶重分。`RunDecisionService` 的 Recruit 池配方和兼容 `RecruitmentChoices` 查询共用此策略；生成后保存的 Offer 仍沿原快照恢复，不因读档重抽。旧快照中的合法历史英雄保留，不拿新池缩减去删除已取得内容。
- schema v6 增加可空 `OpeningRecruitment`（不可变候选/勾选身份数组）；缺失表示既有正常征程。只有经过严格校验的开局状态可持有空名册；必须是0层/0战斗、无节点/奖励/终局、初始资源、6个合法互异候选及0–2个候选内勾选。异常状态保留原档并拒绝载入，不猜测补人或重抽。
- `BeginOpeningRecruitment` 先保存再替换活动征程；存在开局草稿时复用。`ToggleOpeningHero` 和 `ConfirmOpeningRecruitment` 使用副本及同一保存边界；确认恰好添加所选2名、布置合法初始格并进入首战 PendingNode，保存失败不更改草稿、队伍或原征程。候选资格来自当前测试征程池，独立于旧账号解锁列表。正式 UI 仅通过这组命令开始新局；旧 `StartNewRun(heroId, seed)` 保留为测试/工具兼容入口，不是产品开局路径。

- Campaign 可配置 `RunOfferDefinition → RunChoiceDefinition → 条件/成本/成功效果/失败效果`。有限操作覆盖金币、招募、物品、生命恢复/损失、人口增长、人口上限来源；不新增升星、合并、成长曲线或独立交易经济。
- 原有默认节点参数/资源池编译为同一 Offer 模型。`ResolveOffer(offerId, choiceId)` 验证当前资格，在副本支付全部成本并执行收益，同时消费机会/推进节点，保存成功后才发布。失败保留原状态和机会。Shop 重复购买是明确策略，不等同于一次性奖励。
- schema v7 保留 v6 的 PendingOffer 及其选项快照；普通战胜的楼层推进和待领奖机会同次提交，读档先恢复待决机会。UI 只提交身份和选择，不直接写收益。
- v7 新增 CurrentRunHealth／MaximumRunHealth 及可空的不可变 LastBattleConsequence。RunRules 配置生命初值、上限、普通／精英败战损失及默认营火恢复量；共享资源不保存局内值。当前格式缺生命字段或非法范围拒绝载入，非终局不得为0。合法v6可携带冻结待决项或终局凭证迁移，初始化生命且保留其余状态；v2–5继续按原资格边界迁移，只有通过全部校验并保存后发布，原格式保留备份。
- RunNodeResolutionService 按实际结束原因验证与提交遗物transition：败战／超时不得有胜利贡献，但合法Run计数器和已消费指令金币仍写回。非Boss有余血败战同次保存扣血、战斗计数和推进，无奖励；Boss或0生命先保存终局凭证再清理。保存失败不发布副本；清理失败从已保存的凭证恢复，不能再次扣血。
- RecoverRunHealth 为通用正整数恢复收益，RunHealthBelowMaximum 为资格条件，RunDecisionChange 返回实际生命差值。营火通过既有通用offer界面显示两个互斥选项；原默认存档中的英雄伤势恢复项移除，并补充独立全局恢复选项，机会身份与金币／已冻结恢复量不变，不重抽、不读时保存。满生命显示禁用原因。UI由RunHealthDisplay显示值快照，由RunHealthText统一预告和战报；模拟器与实验室不持有Run生命。
- 普通招募资格由 `RunRecruitmentPolicy` 按名册全部内容身份（含后备）统一判定，覆盖固定／随机候选、旧快照的显示与领取和底层招募写入。去重依据可达 Recruit 操作，不依据展示用 ContentId；同一结果分支不能重复取得。候选不足不补重复，耗尽时保存可跳过空机会。旧快照读取只投影合法候选，不重抽或写回；成功的重复商店交易同时持久化过滤后的快照。已有旧名册不自动删除或清洗，特殊复制不借普通 Recruit 隐式放行。实现证据见 `../work-items/active/ordinary-recruitment-uniqueness.md`。
- 终局先保存 Run 完成凭证，再提交 Meta 已应用凭证；保存失败保留 Run，重试不会重复胜利/解锁。确认 Meta 成功后才清除活动征程。
- 旧格式遵守明确支持范围：无法区分旧非战斗节点是否已领奖的待决状态拒绝迁移并保留原件，不能猜测重建机会；支持的跨版本迁移保留唯一备份。损坏/读取失败与无活动存档区分。
- 旧体验切片使用隔离内存存档并显式跳过正式奖励机会，继续自己的奖励流程，不能创建双份收益或写正式存档。

实现状态与当前证据归 `work-items/active/content-system-foundation.md`。独立合成配置检查不依赖正式内容数量；编译只证明接口/类型一致，不能代替作用域切换、保存故障或玩家体验的实际执行验收。

### 岩垒实体表现与地面特效层（2026-09-25）

enemy_rampart_segment独立内容场景显式引用共享rock_barrier_visual。RockBarrierVisual只采样注入的投影切向/前向、墙段位置和时钟；正式BattleScreen在wall_raised中初始化，UnitContentRoot转交暂停、速度、单步。旧动画组件隐藏渲染但保留统一死亡生命周期。rock_raise在独立预览可绘制同一岩柱组件，正式事件用VfxContext.BodyProvidedByActor避免重复主体，碎石/尘仍归VFX作用域。碰撞/生成点/墙体寿命不归视觉组件。

BattleScreen单位层Z=1，地裂裂缝和酸液液斑使用绝对地面Z=0，位于棋盘背景之后、单位之前；飞行体/岩片仍保留原上层。这是绘制层级，不改变地形占位或伤害判定。

岩垒视角修订：RockBarrierVisual保持原注入/时钟接口，子场景RockBarrierPillar用 authored 足印和纹理面投影柱体，俯侧视顶面/厚度随前向与弧切线共同变化；视角与受光不再依赖逐柱Sprite翻转。所有Polygon2D节点由场景编排，脚本只投影几何和采样起升。其石材底色来自项目内barrier-stone-matte.png；旧单柱图保留供历史对照。

岩壁近景的角色缩放与地面投影须使用同一比例（BaseCellPitch×UnitScale），不能只放大角色而保留固定格距。共享场景通过ArcDepth与ForwardOffset调节视觉浅弧，墙段的实际生成点和碰撞仍归战斗；保留施法者与墙体的可见间隙。
