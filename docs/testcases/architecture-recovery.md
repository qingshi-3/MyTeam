## 运行

先按项目要求构建：`dotnet build my-team.csproj -maxcpucount:2 -v:minimal`。

设置 `DOTNET_ROOT` 为本机 .NET 安装目录，`GODOT` 为本机 Godot .NET 可执行文件，然后从仓库根运行：

```sh
python3 tools/run_architecture_checks.py
python3 tools/run_architecture_checks.py --case recovery-input --case recovery-exit
```

第一条串行运行当前清单中的无渲染专项；第二条运行两项 960×540 隔离恢复输入。可用 `--include-input` 加入全部隔离输入，或用 `--case battle-architecture --case ranged --case piercing` 单独检查战斗治理边界。具体清单以 `tools/architecture_checks.json` 为准。`--godot` 可覆盖环境变量，`--output` 指定证据目录；默认保存到 `.godot/architecture-checks/`。未改变代码且已具备可信证据时无需重复跑全部专项。

`results.json` 中 `assertions_passed` 要求进程退出码 0 和全部完成标记，`clean_run` 还要求无未预期错误与退出资源错误。存储故障注入只在明确的 BEGIN／END 标记之间匹配本测试 namespace 的 `Save failed`；其他错误不会被豁免。资源退出错误单独列出并使整体返回非零，不能把断言通过表述成清洁运行通过。

## 读取、机制与作者配置治理专项

- `read-boundary`：公共 API 不返回可变 Run／Battle 对象，嵌套集合不可写，保存失败不泄露暂存状态，新局身份独立，战斗实时读取可刷新；表现层不得绕回内部 DTO。
- `battle-architecture` 同时覆盖机制检查点归属、重入保护、清理后恢复以及既有属性／投射物契约；`matrix-lifetime` 和 `enemy-actions` 补充实际矩阵失败回滚与五类敌人动作。
- `matrix-status-rules`：当前作者默认值与旧战斗数值相同，非法项目发布失败，已发布内容包存活期间强制 GC 后可再次发布并在修正配置后恢复成功，规则冻结并传入准备；真实技能验证毒周期／伤害、寒意线性减速与余烬上限。
- `matrix-authoring-layout`：四个参数资源构成编辑器 schema，所有现有矩阵技能可以保存、重载且编译结果一致。一次性迁移前后比较使用场景参数 `--compare-baseline`，基线在本次输出目录；普通专项不冻结未来合法的玩法调参。`python3 tools/migrate_matrix_authoring.py --check` 检查是否重新出现旧格式。
- `preparation-projection`：49 名实际矩阵英雄的冻结准备快照与正式初始化一致，正式战斗推进／销毁不能改变快照。记录小样本分配用于诊断，不以 Debug 时间作发布性能承诺。
- `preparation-input`：默认正式入口，新征程六选二、当前路线／对手确认、整备、真实英雄详情切换、关闭及重开；仅使用 960×540 隔离舞台与测试 namespace，检查只读浏览不写存档，不移动桌面指针。

这些专项验证代码正确性与实际输入，玩家最终观感、手感和平衡仍单独验收。当前批次的完整来源与失败记录保留在 `outputs/architecture-boundaries-20261001/`。
