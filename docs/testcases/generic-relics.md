# 通用遗物验证

历史入口：[已归档任务](../../work-items/archive/generic-relic-integration.md)。下文是旧遗物成品批次的验证记录；D74已清空该库存，不能按旧清单恢复当前遗物。通用事件／装备池能力保留，现行内容边界见[内容清理](content-reset.md)和[征程规则](../../gameplay-design/expedition-progression.md)。原检查使用隔离存档，不读写玩家真实征程。

## 自动正确性

- `dotnet build my-team.csproj -maxcpucount:2 -v:minimal`
- Godot headless 启动 `res://tests/GenericRelicContractSmoke.tscn`：发布 25 个独立物品、图标留空；折扣原价冻结、保存失败和重载不二次打折；钱匣停止、商店与获金回血、跳过换最大生命／回收收益、利息时点与过期供给；精英池奖励。
- 战斗检查使用正式资源与真实伤害／治疗／普攻事件：高血量和近距离／首领增伤，三种不同减益与同种叠层的区别，精英敌人保留上限但残血入场，金币生命与闪避攻速实时转换，击杀引燃／护盾，五次普攻破甲，暴击攻速上限，暴击回血接溢出护盾，闪避反击，以及公共入场／死亡能力的额外执行。
- 装备契约检查在真实成长战斗中从剩余 4 次击杀开始，以实际攻击获得击杀和合法遗物 trace，验证保存失败不发奖／不改计数，重试从单件池发奖，重复凭证被拒，剩余计数读档保留。为缩短检查，队伍伤害和护盾在测试中提高；这不是平衡实测或完整游戏推进。
- `GrowthRewardGroupsContractSmoke.tscn`：既有分类奖励、领取资格、唯一遗物和商店现货回归。
- `ContentCarrierGrantContractSmoke.tscn`：状态授予隔离、撤销和载体上下文回归。

## 隔离真实输入

以图形模式启动 `res://tests/GenericRelicInputSmoke.tscn`。内部 SubViewport 固定 960×540，真实 GUI 鼠标输入只注入该视口，不移动桌面鼠标。检查商店实际点击按 8 金币购买原价 16 的遗物，以及装备奖励页明确显示“最大征程生命 +2，回收 +5 金币”，点击后不领装备，只消费本组资格并发对应收益。

本轮真实输入通过，不表示现有整套页面布局已经验收。商店卡区高度不足，需要滚动查看／确认；截图记录现状。整套交互布局仍归 D66 后续任务，本轮没有用扩分辨率或另做专用 UI 掩盖它，也没有制作图标。

## 用户体验检查

1. 查看 `gameplay-design/generic-relics.md` 的完整效果清单，先确认经济取舍、触发奖励、跨遗物组合这三类的占比与强度方向。
2. 战利品契约先用 5 击杀／精工瞄具单项池；观察进度是否形成期待，再决定 N 与装备池构成。
3. 重点试“收割镰＋盈愈护符＋猎性之眼”“封存钱匣＋赤金神像＋复利钱罐”“碎甲重锤＋其他减益＋厄兆印记”。留意是改变阵容与投入，还是单纯让数值滚大。
4. 返响骨灰不进当前供给；以后加入明确入场能力再评估，不用普通召唤翻倍顶替。

数值平衡、组合乐趣、供给频率、遗物效果风格以及后续图标均待用户确认。
