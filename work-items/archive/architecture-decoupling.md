## 检查结论与实施范围

- 已检查目录依赖、主要组合根、独立内容场景、最长的控制器与结算类、父级／全局节点查找、运行时 UI 构造及现有测试入口。当前内容发布、Battle／Run 作用域、单位组件组合和 authored UI 的基础合理，没有发现战斗核心反向依赖界面。
- `BattleScreenController` 同时持有战斗流程、角色展示、飘字聚合／节点／Tween 生命周期、详情快照拼装。抽取 authored `BattleFloatingCueLayer`：输入已发生事实和显式位置投影，独立拥有显示及清理；控制器保留事实游标、音频与流程协调。抽取 `BattleRuntimeUnitProjection` 及其视图快照，使装备／羁绊／属性的展示拼装脱离场景控制器。
- `BattleLabScreenController` 直接绑定预设弹窗所有控件，并处理筛选、预览、焦点及保存／载入。抽取 authored `BattleLabPresetPanel`；面板只读预设目录并发出具名意图，控制器继续负责 session 变更、撤销记录、保存事务与反馈。
- 结算核心、状态／效果作用域仍大，但包含有顺序要求的提交与回滚，不按行数拆成共享私有状态的 partial 文件，也不引入全局事件总线／DI 框架。后续候选与本轮实际完成项在下方分别记录。

- 同步 `system-design` 的职责与 `work-items` 路由，不为纯重构新增玩法权威。
