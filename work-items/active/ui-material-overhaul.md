# 物件化 UI 正式替换

## 目标、授权与边界

2026-09-25，用户反馈静态修订与前稿的主要可见差异仍像收掉亮光，方向大体可用但质量未足；要求调研倾斜 UI 是否应画正后由代码变形，并明确开启 goal 模式，持续做到炉石／大巴扎线上 UI 的同等品质，直接替换真实界面，不停留在草稿。

主责在现有 main 实施；保留既有未提交讨论记录、试稿及独立 web/house-spatial-viewer。未授权提交、推送或发布。授权包括真实 UI 的资源、组件、布局、动效和必要验证；不把草稿中的英雄、价格、币种、槽数改成玩法。除下方用户明确授权的“每战满血／休息与事件”规则变化外，现有招募、装备、奖励、保存和模拟语义保持。

用户随后明确：UI质感更重要，倾斜视角可以不做。当前采用正面布局与画入素材的截面／凹槽／投影，不引入全屏透视变换；优先材质、体积、主次与真实反馈。透视调研保留结论，不作为交付门槛或继续消耗的主线。

早期整体材质目标经历过用户暂停与恢复，历史暂停状态不代表本轮状态。2026-09-27 用户再次明确要求 goal 模式逐页视觉检查和优化；当时 get_goal 返回空，已成功建立无预算限制的当前活动 goal。此轮交付范围是全页面信息层级、冗余标记与文字、布局和可操作性检查，不将完成此轮记为用户已认可整体美术品质。

## 实施路线与验收

1. 取得透视／材质／交互制作的实际来源，区分原作观察、公开生产说明与项目实现选择。研究记录归讨论区 Q25。
2. 建立可复用生产美术与共享 Theme／组件，保留 authored 场景和显式绑定。文字、数值、技能与按钮必须实时可用，禁止用整张截图假冒运行 UI。
3. 优先贯通招募／战利品／商店的共享选择组件与英雄／装备整备，再覆盖游戏通用外壳、弹窗和必要主流程页面。保持语义图标一致性、独立人物展示与真实内容关系。
4. 检查正常、悬停、选中、按下、禁用、焦点、拖放、取消、长文、缩放与动画打断。动效支持减弱；实输入验证在隔离存档中进行。
5. 同尺寸对照线上参考的结构厚度、材质反光、主次、字与图标可读性、过渡阶段和响应。只按实际证据记录通过项，尚有明显差距则继续迭代。

## 最新视觉约束（2026-09-25）

用户连续纠偏：原效果像廉价亮光砖；但 Agent 后续生成的粗木纹、绒面磨砂同样不符。用户提供炉石主菜单截图并明确“先照着炉石的做，不要自由发挥”。以 `design-discussion/04-content-validation/artifacts/ui-study-20260925/user-hearthstone-reference.png` 为当前直接视觉基准：概括而平滑的手绘木面、宽厚灰棕倒角、深凹槽、浅灰按钮面与宽金色边框；保留结构性高光，不把磨砂等同于铺噪声或换绒面。自主发挥的四张 matte 素材只留在生成缓存，未接入游戏。

用户指出不能所有大小面板共用同一大框；现仅 ModalPanel 保留大型框，卡片使用专用灰石基底，内部说明／属性／装备槽／提示各有轻量角色。用户认可 `user-approved-card.png` 的材质与画法，只要求上沿弧度减小；已作局部生图编辑接回 `reference-card.png`。其余石块、侧边、底边、配色按认可版保留，不自行重画。这次是素材认可，整套成品品质仍未达验收。

最新用户再次拿出这张 Agent 生成的灰石框，明确“这个就叫有质感”。它是直接认可的本项目材质标杆：大块石面、宽倒角、深内缘、柔和底面。不能再以原图缺质感为理由另起风格。实机需保留原图大形；前一轮九宫格切线穿过角石、低分辨率导入及内部黑框削弱了形体，这属于接入问题。

已读取用户提供的少数派文章《炉石传说 UI 浅析》：实体物件隐喻、操作反馈、统一风格和语义特效是可采用的设计观察；作者的全 3D 说法不是官方实现证据。本轮只采用正面可切片素材和原生 Control，不引入透视。

## 当前进度

### 2026-09-27：单位与技能说明清理

已核对现行玩法规则、能力资源与单位场景，清理英雄、敌人、士兵及技能的玩家可见 `Description`／`RuleDescription`。文案现在直接说明触发、对象与效果，保留影响选择的条件、代价和失败限制；删除测试编号、暂定数值、报告／战斗步／合法位置等开发口吻，并将“行动禁用”“消费”“当前盾”“攻速 +0.35”等改为“无法行动”“消耗”“护盾”“攻速提高 35%”。单位简介只概括战斗定位，不再重复整套技能。典型改法是将换位妖使的“标记最远可换位敌人后互换位置；没有换位伤害，自身也进入敌阵”收束为“短暂标记后，与最远的敌人交换位置”；践踏精英则只保留蓄力冲锋、推挤伤害及受控／受阻停止等玩家需要判断的规则。

核对中同步纠正两处过期文案：HC08 实际范围技能只为范围敌人施加三层蚀毒，没有额外增加主目标毒层；HC23 的寒羽实际为 25% 冰冻概率，霜羽同盟达到 2／4 名成员时提高至 35%／50%，不再沿用旧的寒意层数概率说明。范围也覆盖 Matrix／Growth 的能力、单位简介、场景规则、升阶与运营说明，以及详情面板和实验室中动态生成的连续命中说明；人工文案由生成器写入时保留，不回写历史讨论方案。

文案修改不调整单位数值。核查另发现护阵附近目标漏排除施法者，导致自身重复获盾并少覆盖一名友军；已补 `ExcludeSelf` 恢复既定“指定英雄与至多两名附近友军各一层”规则，`GrowthBattleGainSmoke` 的近远目标分配检查通过。低并发构建 0 警告／0 错误；`UnitInformationInputSmoke` 真实鼠标／键盘检查通过，主责查看 `.godot/unit-information/swap-description.png`，换位妖使的短句在技能正文和展开说明中正确显示，日志 `copy-input.log` 位于同目录。自动渲染检查不代表用户对整套文案和界面体验的最终认可。同期冲撞修复另见 `enemy-trample-charge.md`。

### 2026-09-27：战前拖动预览避让目标格

用户反馈拿起动效已有，但大卡片遮住落点。英雄拖动预览现为 96×96、紧凑肖像及单行省略名称，使用独立 `HeroDragPreviewPanel` 六像素边距，避免通用侧栏的十六像素边距和长名字反向撑大卡片。正式棋盘、后备与实验室英雄拖动显式启用目标避让：预览在当前目标格外选择可见位置，并计入放大、倾摆、滞后和阴影；鼠标仍是实际落点，原合法／交换／非法边框与身体轮廓保持。装备预览定位保持原样，拿起、落下、返回和减弱动效沿用。

正式 `FormationDragOnlyInputSmoke` 增加拖动中检查：卡面与外扩阴影不得遮挡整个目标格，鼠标命中和实际 hover 格一致；覆盖后备部署、移动、交换、1280×720 顶边及 Escape 后恢复。渲染证据为 `.godot/ui-review/deployment-target-{deploy,move,swap,top-edge-1280,cancel-restored-1280}.png`，已查看目标格与提示可见。最终低并发构建 0 警告／0 错误，正式拖放、长中文名保持 96×96、`UiDragMotionInputSmoke` 共享生命周期与 `LabDragMotionInputSmoke` 均通过；三份日志为 `.godot/ui-review/deployment-target-{formation,ui-motion,lab-motion}.log`。不将自动检查记为用户手感认可。

### 最新交互：装备与英雄的拿起、跟手和落下

用户要求游戏内容拖动参考炉石拿牌／大巴扎物件操作，不停留于静态预览。正式装备槽／库存、备战棋子／后备、实验室单位库与棋子共用 authored `UiDragVisual`：拿起时原位留淡影，180ms 轻回弹抬起，柔和投影，跟随速度产生最多约 4.3° 倾摆和 12px 视觉滞后；鼠标停下后归正。落点保留原规则反馈，预览补充 ＋／⇄／×。成功提交后约 160ms 收入目标，非法位置／Esc／提交失败约 220ms 返回来源。仅视觉滞后，命中和提交不等待动画；减弱动效立即取消倾摆／缩放／飞行。装备沿用物品图，英雄保持当前像素肖像与名字，未替换既有布局或角色身份。

原生拖放使用空的引擎预览锚点管理生命周期，独立显示组件留在同一视口以完成短暂落下／返回；拖放数据只附临时视图引用，实例 id、scope/context、持久化与领域判断保持原有路径。成功落点由提交后的绑定或明确成功回执提供，不以 Godot 的“接收拖放”为保存成功。实验室沿用已有指针拖动控制器，显式注入相同表现，不叠加第二套输入。

实输入查出单位库打开时 Esc 先触发窗口关闭动画，随后松鼠标仍能落子的冲突。ContextPopup 现通过显式取消回调先取消实验室拖动；再次 Esc 才关窗，其他关闭方式也立即取消拖动而不等待退出动画。

验证：低并发构建 0 警告／0 错误；`.godot/ui-formation-motion.log` 检查正式备战部署、移动、交换、撤回、替换、敌区／Esc／满后备取消和恰提交一次；`.godot/ui-equipment-motion.log` 检查正式整备穿戴、替换、转交、卸下、焦点、滚动和说明；`.godot/ui-drag-motion.log` 聚焦接收拖放但提交拒绝、非法目标、连续重拖、减弱动效中途开启、所属界面隐藏、原位色值恢复；`.godot/ui-lab-drag-motion.log` 检查当前正式实验室单位库放置、交换、Esc、撤回、装备模板取用与移除。实验室首次 Esc 检查失败已修复并复跑通过，非放宽断言。最终共享表现小修由聚焦输入和实验室检查覆盖，未无理由重复全部整备。

实机动图 `runtime/hero-drag-motion.gif` 与 `runtime/equipment-drag-motion.gif` 来自真实输入逐帧采样，保存时再编码，未用渲染图假冒交互。采样内部 1600×900、动图预览缩至 800×450 并约 15 帧／秒抽帧，段间加审阅停顿。已查看拿起和装备拖动渲染；未宣称原作参数复刻或用户手感验收。检查发现项目最大化配置可覆盖命令行：`UiInputStage` 的隔离分支现在直接设置桌面窗口 960×540，聚焦检查已断言实际模式和尺寸；生产默认窗口设置未更改。

### 最新局部修正：弹窗回弹、按压反馈与悬停闪烁
