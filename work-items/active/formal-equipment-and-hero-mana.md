# 正式流程：装备体验与英雄独立法力

Status: Implemented — Compilation Passed; Player Experience Pending

## 用户目标与边界

- 2026-09-06：用户认为体验切片已证明链路可通，但表单式交互、装备和状态可视化弱，不再投入独立体验界面；转向正式游戏的装备、操作和战斗反馈。
- 本轮新增确认：多英雄分别拥有技能和法力，自动回蓝、攻击回蓝、受击回蓝，满足施法条件后自动释放，不再以全局手动英雄技能作为核心。
- 独立战术命令是否保留已向用户提问；该选择不阻塞英雄法力及装备工作。未明确前不删除其数据与规则。
- 保留现有研究语料、Web 基础模型、试验场景和未提交工作。只在 main 开发；不提交、发布、改真实存档或启动用户试玩。
- 用户此前要求不自动推进战斗或替其试玩；仅编译、静态检查和数据安全检查。新增行为检查可编写但不擅自运行战斗。明确报告未体验验收。

## 实现契约

- BattleSimulation 保持唯一战斗权威；能力仍使用既有 authored loadout、编译图、操作和事务，不写具体英雄 id 分支。
- 英雄当前法力是独立 Battle 状态，不写共享 Resource，也不跨战保存；上限、起始值、三种回复可配置。法力达到施法门槛但没有合法目标或受到行动控制时不消费；成功施法才消费，失败回滚。
- 攻击回蓝以一次普通攻击为基准，不因溅射/穿透重复；受击回蓝只计算有效承伤，不从无效伤害或尸体产生；被动回蓝按逻辑 tick，不受渲染帧率影响。
- 法力条、技能及状态表现读取真实 runtime 快照与事件，不伪造触发；角色有清晰装备槽与效果详情，技术 id 退出常规展示。
- 正式装备获得、归属和更换复用 Run 的原子命令及持久化；替换不得默默销毁旧装备。资源变更限于明确接入的装备/英雄技能内容。

## 工作分工

- 主责：法力与能力内核、内容校验及指纹、系统/玩法权威、共享接口协调、串行编译和交付。
- 装备：Run/Equipment 正式装备库存、获得和转移接口；正式奖励、备战与队伍 UI；对应装备资源/池及数据安全检查。不改 Battle、Abilities、表现组件。
- 表现：BattleScreenController 的快照/UI绑定、角色选中面板、角色头顶法力/状态与技能触发反馈；不改 BattleSimulation、BattleModels 或内容能力定义。
- 内容：各英雄独立 authored 法力技能/loadout、英雄内容场景；不改编译器、运行时、装备、共享 UI。

## 验收与恢复

- 普通角色和首发英雄均走同一自动施法机制，队友之间法力不混用；击杀、无效目标、控制及提交失败保持正确边界。
- 正式流程能获得装备并看见归属、槽位和作用；更换/卸下不丢物品，失败不保存半状态。
- 用户可以通过真实游玩观察法力增长、施法消耗、装备归属和状态变化。自动检查不能替代该验收。
- 当前：实现已接入，低并发编译通过；见下方记录。恢复入口为本文件和各模块当前 diff；不要按陈旧历史任务的“尚未实现”重做既有多英雄迁移。

## 本轮实现与实际证据

- 独立法力：`BattleHeroMana` + `BattleUnitState`，六个 authored 法力参数进入 Attribute 管线，可被既有装备／状态属性机制修改。32 个玩家模板（8 首发、24 招募）均配置独立自动技能和 loadout，不按 `IsHero` 旧首发标志限制普通招募英雄。
- 技能：Automatic/ManaFull；攻击类选择范围内可达敌人，治疗类选择受伤友方（含自身），自护明确自身。初始法力 0–25、上限 60–90、施法恢复 10 tick 为首版可调配置，不是平衡验收。临时模板不继承该法力循环。
- 已修边界：技能伤害后的状态不能重挂尸体；死亡导致的后续无效操作正常跳过；真正失败回滚法力、行动锁、伤害／死亡链和反馈。显示目标同步实际受术者。
- 正式装备：schema v5 背包实例、获得／购买、无损更换／卸下／转交；v4 空背包明确迁移，跨版本保存留唯一 `.vN.<guid>.bak`。装备锁覆盖战斗及尚未提交的结算；既有正式资源池接入三装备。
- 表现：头顶蓝条、满蓝提示、护盾与控制轮廓、技能成功事件名称/光环；角色详情中的中文技能、装备三槽图标、状态层数和时间。奖励获得后可分配，备战和军团抽屉共享点击／拖放换装组件。
- 旧切片自身库存不迁移；禁用其共享部署页面上的正式库存编辑，以免双库存污染。调研资产和 Web 模型未修改。
- 静态检查：参与者核对新增资源引用与 `git diff --check`；主责读审查并修复死亡及目标反馈边界。`dotnet build my-team.csproj -maxcpucount:2 -v:minimal` 通过，0 警告／0 错误。
- 新增 `HeroManaContractSmoke`（含致死回滚和临时模板）及 `FormalEquipmentInventoryContractSmoke`，已编译但未执行。没有启动 Godot、自动战斗／试玩、截图验收，也没有读写真实玩家存档；不得将上述静态／编译证据写成实际效果已通过。
- 用户手动入口及观察点：`docs/testcases/formal-equipment-and-hero-mana.md`。下一轮按实际体验修正；独立战术命令是否取消仍待用户异步答复，暂保留原已确认契约，不把英雄技能改造等同于擅自删除另一系统。
