## 目标与授权

用户在了解此前已有控制、尚无专门位移后，要求把冲锋、跳跃、闪现切后排、击退、拉拽、聚怪做出来，希望战斗更生动。授权见 [2.3-D07](../../design-discussion/04-content-validation/decisions.md)，具体可修改草稿见 [HC31–HC36 当前稿](../../design-discussion/04-content-validation/content-drafts.md#位移与空间控制英雄批次hc31hc36)。本任务负责六种真实位置变化及可见过程，各由一名新英雄承载，保留固定主动／固定被动，不以文字或特效替代战斗位置。

只在 main；不建分支、worktree，不提交／推送，保留已有未提交改动和无关 Web 工程。保留 HC01／HC03、HC04–HC30、假人、原 31 个预设及最新实验室 UI。HC02、R10、旧 V01-H01／U01 继续暂停。沿用户此前“不用验证”要求，不构建、不运行测试、不启动 Godot／试玩／本项目录制；实现必要阅读照常进行。参考动作的官方媒体观察属于制作依据，不能写成本项目验收。

六名开场法力暂为上限（80／90／80／80／80／100），用首轮观察接敌前的空间变化；后续正常回蓝，主动恢复间隔暂为 1.2 秒。名字、数值、子分支、开场满蓝与被动配套均是 Agent 初稿，不是用户逐项最终采用。完整基础配置、配合与取舍只在当前稿维护，不补齐未定羁绊、正式费用层级或完整升阶。

集成时按运行合同修正停距：`StopDistance` 是在双方身体半径与必要间隙之外额外保留的边缘距离。HC35 从 0.8 改为 0.12，使合法拉近可接普攻；HC36 从 0.9 改为 0.2，使聚拢更紧密但仍保留各自身体。原值分别会把普通体型留在约 1.455／1.555 格中心距离，偏离拉近／聚集的内容目的。详细修改理由见当前稿，未重跑一次性资源生成器。

界面入口为主菜单 → 战斗实验室 → 预设库，新增 `MV01 · 破阵骑兵 · 冲锋` 至 `MV06 · 风眼术士 · 聚怪`，原 31 个预设保留，合计 37 个；累计设计英雄 35 名。预设以新英雄、少量实际配套和假人展示动作，后续可以自由调整站位；不是固定最优阵容或完整供给证明。

## 运行与表现职责

- 扩展现有 Ability 操作，使用 `DisplacementAbilityOperationSpec`，不另造平行战斗框架。配置以 `DurationSeconds` 写入资源，编译为固定战斗 tick；查询用当前 Owner、敌方、最近／最远与目标上限。
- 自移与敌方强制位移分别处理，身体位置、边界、路径阻挡、合法落点和终止归战斗权威；跳跃／闪现的穿行表现不能允许非法落地。目标选择由技能明示，后续普通索敌遵已有机制。
- 多个聚怪目标朝施法者施放位置附近分别移动，保留身体间隔；聚怪中心不从旋风特效反推，不把多个单位设为同一点。
- 真实位移期间的动作占用、受控／死亡／阵营变化中断与在途攻击衔接、事件及回滚清理由共享运行实现负责。源代码已由主责整合，必要 gameplay／system 权威同步完成，不扩成其他讨论的统一合并。
- 表现只读取位移开始、逐步位置、完成／取消事实；地面运动、跳跃弧、闪现瞬间换位、受击者推拉姿态有明确区别。选择点、血条及身体仍在地面，不因美术弧高改变命中位置。
- 复用已有角色帧与语义相符的传送／冲击／旋风层。未制作六套专属角色、坐骑、独立起跳／落地骨骼动作或实体钩索；不将现有角色换名当成专属美术完成。
- 表现 Agent 已完成实际绑定：闪现两端的传送起手／完成／取消，冲锋／跳跃／击退成功抵达后的冲击，聚怪共用旋风维持至整组位移结束。身体盾壳及贴附状态跟随跳跃高度，地面状态保留脚点；冲击等待末段位置插值完成才播放。此为代码与资源接入状态，没有运行或动态观感验收。

玩法依据复用 [BC28／BC29 映射](../../design-discussion/04-content-validation/evidence.md#bc-条目与来源对应)与原库只读的 Gladiator Guild Manager／Auto Chess 记录。Rhino 聚集供 AOE、Hookbot 拉近供爆炸及刺客落点风险提供关系依据；原作优先级输入、精确数值与版本强度不迁移。

具体动作的实际观察、来源链接、未知项与项目适配由表现 Agent 写入 [P01-S34](../../design-discussion/02-foundation-models/combat-presentation/evidence.md#p01-s34英雄位移的身体动作与空间参考2026-09-12)。已观察 Riot 官方 Gragas E、Tristana W／R、Katarina E、Blitzcrank Q、Orianna R。媒体没有进入运行资源，参考原作的动作观察不等于当前实现运行通过。

资源分组：

- 六名独立 `.tscn`：`content/heroes/hero_hc31_breach_lancer.tscn` 至相应 HC36 文件；配套 definitions、portraits、catalog entries 和 loadouts 同 id。
- 主动：`content/abilities/automatic/ability_hc31_a.tres` 至 `ability_hc36_a.tres`。HC31–HC35 被动在 `triggered/`，HC36 周期被动在 `automatic/`。

- 正式入口：`content/catalogs/alpha_catalog.tres`、`content/project/pools/pool_designed_heroes.tres`；实验室入口：`content/battle-lab/battle_lab_presets.tres`。

## 验收边界与后续反馈

本轮按要求**未构建、未运行自动测试、未启动 Godot／试玩／本项目动态录制**；实现、源代码阅读、参考观察、实际运行和用户体验必须分别报告。已有英雄和 UI 的旧证据不套用。主责整合后的完成状态只指实现接入，玩家体验、节奏、碰撞观感与最终数值仍待后续反馈。

用户体验时优先观察首轮动作能否看清、落点是否合理、突入者能否获得后续输出机会、击退是否让己方频繁追赶、拉拽与聚怪有没有把危险带回己方，以及连续控制／回蓝节奏。无需逐字段定稿后再修下一名；全批规模、供给与所有其他讨论的统一合并不在本任务范围。
