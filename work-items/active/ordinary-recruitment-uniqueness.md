# 普通招募唯一英雄

日期：2026-09-16。状态：已实现；正式内容专项检查通过；历史测试加载受阻；玩家操作体验待验收。

后续：[开局与分阶招募](recruitment-opening-and-tiers.md)已在用户追加执行授权下接入14人池、保存式6选2和阶段概率；本文“未实现6选2/阶段”仅描述本次去重任务当时范围。通用去重专项在后续改版后继续通过。

## 目标与授权范围

承接用户“改一下我们的招募逻辑”，本轮明确先不做升星、继续材料升级，并要求没有遗物等特殊效果影响时普通发牌严格不出现相同英雄。本次只落实普通取得资格与候选去重。相关决定见 [R07-D05](../../design-discussion/03-run-mechanisms/supply-and-economy/recruitment/decisions.md)。

- 同一内容身份当前已在名册中（包括后备），不能再通过普通招募出现或取得。同一批候选不重复该身份；不同英雄可以同职业、同羁绊。
- 曾展示但未选的英雄仍合法；不加入历史永久排除。本次没有推荐权重、已见降权、阶段分阶、开局6选2或材料培养实现，3英雄＋材料包仍是建议。
- 特殊复制须另有明确内容和操作契约；现有战斗召唤独立，本次不新增复制绕过开关。旧存档中已有的单位不被擅自移除。
- 只在 main 修改，保留其他未提交内容，不提交、不推送、不接触真实玩家存档。

## 实现与恢复入口

- `src/Run/RunRecruitmentPolicy.cs`：全名册身份检查、组合选择的可达分支检查、批内去重及待决快照可见投影。按实际 Recruit 操作身份判定，不信任卡片外观身份。互斥成功／失败分支可分别取得同一个合法英雄，但单个分支不能发两份。
- `RunRewardEconomyService`：初始同伴排除起始英雄及重复池项；普通候选在取数量前过滤已持有者／重复池项；取得时再次校验，不成功不消耗序号、不保存。物品供给不套英雄去重规则。
- `RunDecisionService` / `RunApplication`：固定／随机候选共享去重；旧待决快照显示与领取采用相同过滤。重复购买英雄后移除英雄候选，物品保留原购买策略。合法池不足不补重复，空机会允许跳过。价格、收益、快照和推进仍原子保存。
- `RunDecisionValidation`：允许有明确跳过权限的空机会，支持耗尽后保存／恢复；default 数组及不可跳过空机会仍拒绝。
- 修正部分测试通过重复普通招募填充后备／人口的设置，改取未拥有身份；不豁免历史 IsHero=false 的常驻友方单位。
